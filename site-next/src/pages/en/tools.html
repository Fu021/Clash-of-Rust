When something will not connect, the toolbox follows one request through DNS, the proxy, TLS and the exit, and tells you which step failed. It is in the window, in cor network and in the terminal interface.

Start from what you see

You do not need to know the tools by name. Find the symptom, then run the check beside it.

{{tools:symptoms}}

What every check has in common

  • It runs only when you ask. Nothing scans in the background.
  • Website and HTTP checks go through the core's local proxy as it is now. A check never starts the core, switches node or falls back to a direct connection.
  • Only the current result is kept. Switching page or tool cancels the check and clears the result, and a late answer is not filled in afterwards. Export first if you need it.
  • Reports leave out the URL path and query, any user name or password, and the downloaded body.
{{tools:articles}}

Options and limits

Defaults are 5 attempts, 1,000 ms apart, 10 seconds each, an 8 MiB download cap and 8 hops. The window shows the options that apply to the selected tool and returns to the defaults when you switch tools. The terminal interface always uses the defaults; set anything else with cor network.

{{tools:options}}

Every run also has an overall budget, so nothing waits forever: a stability run stops at 120 seconds. System output is kept up to 8 KiB per stream, and a report holds at most 48 entries of 2,048 characters each.

While Claude protection is on

With protection on, or when its state cannot be read, the toolbox sends no system DNS lookups, no UDP, no ICMP and no hop-by-hop probes. Checks that need them say why they are unavailable instead of running. The other checks still go through the local proxy and your current rules, so a diagnosis can never be used to step around protection.

If you have switched UDP off in settings, the UDP probe is not sent either.

Reading and saving a report

Each report ends in one of four states. They are not interchangeable, and the command line returns a non-zero exit code for the last two while still printing the report.

complete

Every step ran and gave an answer.

partial

Some steps answered and some did not. Reaching a time or size cap on purpose does not count against a check.

failed / unavailable

The check ran and failed, or could not run here at all: a missing system tool, no permission, or protection being on.

From the window

Use the export button under the result. The export carries the tool, its result and any error code.

From the command line

Add --json to print the report, or --output FILE to save it.

$ cor network phase example.com --seconds 5
$ cor network stability example.com --count 10 --interval-ms 500
$ cor network explain example.com --json
$ cor network tls example.com --output tls-report.json

The JSON holds schema, tool, a target reduced to its origin, elapsed_ms, status and a list of entries. Each entry has a label, a detail, a code and success, where null means a note or something that could not be confirmed. cor network check keeps its earlier JSON shape.

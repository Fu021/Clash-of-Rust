Send every connection down the right line.

Clash of Rust is a native mihomo client for Windows, Linux, macOS and Android. It keeps your subscriptions, nodes and rules in one place, and shows where each connection actually went.

A real window, not a web page wearing one.

The interface is drawn with Rust and Slint. There is no WebView inside, so the window gives its memory back when you close it, and the tray and the core carry on without it.

Four platforms
Windows on x64 and ARM64, Debian and Ubuntu on amd64 and arm64, macOS 14 on Intel and Apple silicon, Android 8.0 and later.
One backend
The window, the tray and the cor command line all talk to the same background service and the same mihomo core.
Nothing to fetch
Installers already contain mihomo and the Geo data. Add a subscription and you can connect.

What you do with it, day to day

  • Subscriptions and nodes

    Remote subscriptions and local YAML sit side by side and refresh on a schedule. Test, filter and switch nodes from the window or the tray.

    Subscriptions in the guide

  • Rules

    Rule, global and direct modes. Five quick rules cover ads, private addresses and mainland China traffic; your own rules can be added, reordered and switched off.

    Rules in the guide

  • Per-app routing on Android

    Choose which apps enter the VPN. On Android 10 and later, an app can be sent to a node, a policy group or straight out.

    Android in the guide

  • Access checks

    See your exit IP and whether GitHub, AI services and streaming sites answer through the current node. Results are grouped and can be re-run or exported.

    Checks in the guide

  • Claude protection

    Pins one node, turns on TUN and encrypted DNS, blocks stray connections, and locks network settings until you switch it off. Your own settings come back afterwards.

    Protection in the guide

  • Updates

    Stable and preview channels inside the app. Each download is checked against its SHA256 before it installs, and the desktop app can step back from preview to stable.

    Updates in the guide

Eleven checks for when something will not connect0.7.2 preview

Run one when you need it. HTTP checks use your running proxy; ping and route trace use system tools. None of them starts the core, changes node or quietly falls back to a direct connection.

The window, the command line and the terminal interface share the same checks. Results are not kept: leave the page and they are gone, so export first if you need them.

{{tools:home}}

The same client, without the window

cor ships inside the desktop installers and drives the same backend as the window. Use it on a server or over SSH, and add --json when a script is reading.

$ cor profile add home 'https://example.com/subscription'
$ cor profile use home
$ cor start            # run in the background
$ cor node select      # pick a group and a node
$ cor proxy tun        # capture traffic with TUN
$ cor status

cor ui opens a terminal interface prototype with home, nodes, connections and the network checks. Command line in the guide

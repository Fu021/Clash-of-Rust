Home and connection

Home shows core status, the selected profile, a reference node, traffic and network details. The connection button starts or stops the core; the proxy method determines which applications enter it.

  • System proxy: handles applications that honor system proxy settings. Terminals and some apps may ignore them.
  • TUN: captures at the network layer. Desktop requires system authorization on first use; Android asks for VPN permission.
  • Off: releases this instance's system proxy or TUN. Other VPNs may still be active.
{{shot:home}}

Home service latency and node-test latency measure different targets. A reference node is not every connection's actual exit; inspect individual paths in Connections.

Subscriptions

In Subscriptions, choose Import and enter a name and subscription URL. For local YAML, use Local file on desktop or Choose local file in the Android import form. Save, then choose Use to activate the subscription. Remote profiles can update from their source. You can rename or remove local profiles while keeping the original file.

Download or validation failures preserve the existing profile and running state. Removing the active profile returns to Default direct, which cannot be edited or removed.

{{shot:subscriptions}}

Search by name or source, choose a grid or list, and switch between showing all profiles and pagination. On phones, editing, updating and removing profiles are in the details. See schedules for automatic updates. Claude protection pauses subscription changes and updates.

Nodes and modes

Search and test nodes in Proxies, using a grid or compact list. On desktop, show all proxy groups or page through them. You choose members of manual groups while the core handles automatic groups such as AUTO. Details show node information and available actions.

Latency tests measure reachability and response time, not bandwidth. A timeout does not mean a node was removed. If every node fails, the mode is preserved and recovery options appear; update downloads have a separate fallback.

Rules

Quick rules offer ad blocking, private-network and China-direct options. They start disabled and only add missing rules. Custom rules can be added, edited, disabled, removed and reordered.

The first matching rule wins. Subscription rules remain read-only but can be reordered. Changes are validated before saving and do not rewrite the original YAML. Duplicate enabled rules are rejected.

{{shot:rules}}

In Rule mode, Android app-specific exits take priority over ordinary rules. Global, Direct and Claude protection suspend them. Use rules and exit to inspect a URL.

Android app routing

Open Settings → App routing to decide which apps enter the VPN. Search names or package IDs, filter selected or system apps, and review your selection. All apps mode hides the selection list.

Choose an app's exit

On Android 10 or later, choose Manage app rules to create named groups, filter apps and choose a node, policy group, DIRECT or REJECT. Rules belong to their profile and follow the selected profile. On Android 8 and 9, you can still set VPN scope.

Block connections when the target is missing is enabled by default. A recoverable warning appears when a real connection is blocked by a missing or changed target; latency timeouts alone do not make it missing. Disable this option to fall back to the ordinary configuration. Apps outside VPN scope cannot use these exits.

Save and recover

While connected, choose Save and reconnect. The new VPN applies the change once connected. If reconnecting fails, the app reports the cause and restores the old connection. If disconnected, saved changes apply on the next connection. Normal mode respects the UDP switch. An exit without UDP support blocks that traffic.

Claude protection covers all apps, suspends app exits and locks edits; disabling it restores your settings. Android's Block connections without VPN setting may block excluded apps too. Full routing boundaries ↗

Connections and logs

Connections lists active requests with filtering and details for domains, targets, protocols, matched rules, policy chains and traffic. Copy details or close a connection; an application may reconnect afterwards.

View or clear messages and export diagnostics in Logs. Logs, domains and IPs may contain personal information; review before sharing.

Checks and tools

IP check shows exit addresses, service reachability and confirmed per-service exits. A÷ check groups Claude region, DNS and configuration clues by topic. Network diagnostics checks websites, DNS, TLS and actual exits. On Android phones, these pages are usually under Tools.

{{shot:network}}

Tools run on demand and keep only the current result; leaving cancels and clears it. An HTTP response does not prove login works. Inputs, options, report states and protection limits are in the network tools manual.

Claude protection

Enable it in A÷ check to pin a concrete node, apply strict TUN and encrypted DNS, and monitor bypasses. Existing core connections close before activation. A network without IPv6 is not treated as a bypass.

{{shot:protection}}

Network changes—including nodes, rules, profiles, updates, Geo, autostart and schedules—are locked. Theme, accent, font size and read-only browsing remain available. Protection suspends Android app exits and temporarily captures UDP; disabling it restores your preferences.

Protection persists across restarts and can be disabled from the same entry. It constrains connections, not third-party service acceptance. Scope and allowed actions ↗

Settings and schedules

In Settings, choose System, Simplified Chinese or English. The interface switches as soon as you save. Appearance offers theme, accent and font size, with window and tray options on desktop. Network includes ports, IPv6, UDP, DNS and Fake-IP. Check the result shown by the app after making a change.

Subscription updates and software checks have separate schedules in minutes. Both default to 360, accept up to 10080 and use 0 to turn off automatic checks. A manual software check resets its timer. Protection pauses the relevant schedules.

Fake-IP exclusions have a dedicated editor and do not require changing the original profile. Phones, tablets and desktops share fields where possible; compact screens move actions into details.

Updates and autostart

Settings → Update checks stable releases by default. Include prereleases adds newer previews. Installers are verified with SHA256. Android also requires system confirmation and cannot install a lower version as a normal update.

The official Arch package can download and install updates from the app. Fedora and openSUSE use their package managers for RPM updates.

Geo updates replace data only after validating the full set; failure keeps the old data. Follow recoverable prompts for download, permission or installation errors, or download manually. Keep your configuration.

Desktop Background autostart logs in with the window closed. If the tray remains unavailable after waiting, a window opens to explain. CLI user services are an alternative; choose one autostart method. Android's foreground VPN service is separate from desktop login autostart.

Errors and recovery

Ordinary notices dismiss automatically. Recoverable warnings offer retry or export; serious errors explain blockers. Claude protection alerts are separate. Dismissing a message does not fix its cause.

Export diagnostics from Logs or an error prompt and record the time and steps. Nothing uploads automatically. Review domains and IPs before sharing, and preserve evidence if the core fails to start.

For websites, use the website check; for installation, read common questions. Without a window, use CLI diagnostics.

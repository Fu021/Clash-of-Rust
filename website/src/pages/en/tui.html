Open and exit

cor ui
cor ui --demo

Windows, Linux and macOS installers include cor. Use a real interactive terminal. Demo mode uses fictional data, without network access or saving.

From fix.5, the layout follows terminal size, compresses narrow screens and prioritizes the focused item or confirmation in tiny windows. Long connection details scroll. Version fix.4 and earlier still require 60 columns × 18 rows.

Opening, browsing and exiting do not start the backend or core. Use Actions to start one if needed. q / Ctrl+C exits while the existing backend and proxy remain running. Emoji rendering depends on your terminal font.

Page shortcuts become ordinary text inside input fields. Use --no-color or NO_COLOR to disable colors.

Six pages

1 · Home
Core and backend state, profile, reference chain, protection, rates and connection count.
2 · Nodes
Find groups and nodes, read latency and confirm a manual selection.
3 · Connections
Filter active connections, inspect details and request closure.
4 · Network
Choose an on-demand tool, enter its target and read the result.
5 · Settings
Inspect values, edit supported fields, review and submit.
6 · Actions
Forms generated from the command catalog cover profiles, rules, updates, services and more.

Only the current page's data is read, sampled once a second. Drawing updates changed lines, without accumulating connection or command-output history.

Node selection

Press 2, find and open a manual policy group, choose a member and confirm again. Spaces, emoji and punctuation are preserved. Automatic groups show the core's choice and cannot be manually assigned a member.

Profiles, membership and protection are rechecked before submission. Choosing AUTO in a parent manual group does not become invalid just because AUTO changes its internal node.

From fix.5, one s control cycles through name, ascending latency and descending latency. The page shows the mode actually saved by the backend and keeps the selected node during refresh and filtering.

Connection details

Press 3 and Enter on a connection for domains, destination IP/port, protocol, time, rule, actual path and traffic. d adds resolution details; x opens a close-connection confirmation.

If the connection disappears, the original ID is reported as unavailable; another connection is never substituted. The source application may reconnect after closure.

From fix.5, details include original and sniffed domains plus process information; no sniffed result is guessed. Lists prefer sniffed domains, and search covers both domains, IPs, rules and proxy chains. Use ↑ / ↓ to scroll wrapped details. Missing fields currently show “unavailable”; empty-field presentation still needs refinement.

Network tools

Press 4, choose a tool with [ / ], then / to enter a target. Enter ends input; another Enter runs the check. Scroll with ↑ / ↓ and cancel with Esc.

{{terminal:network}}

Version fix.5 has twelve checks, all requiring a target. Rule and exit is part of Website check. Traffic summaries belong to Connections and node information to Proxy details; see the tool guide. Direct checks use defaults; Actions accepts count and time limits. Changing pages cancels and clears results.

Settings forms

Press 5 to inspect settings. Drafts are submitted only after confirmation. Cancelling a field restores its previous value; leaving the form discards drafts. The backend still validates ranges, permission and current state.

From fix.5, ports, DNS/Fake-IP, IPv6, UDP, update channels and intervals, run mode, profile selection and shortcut rules have switches, choices or editors. Use Enter, Space or arrow keys to choose, then move down to Save settings and confirm. Ordinary settings save inside TUI and read back the result; failures keep drafts. Proxy and protection authorization still uses the normal terminal. Settings categories, some empty values, shortcut-rule deduplication and profile selection interaction still need refinement. GUI accent, font and tray preferences stay outside common terminal settings; advanced commands remain available.

Actions and authorization

Press 6 and search for an action such as profile add, rule add, update install or service status. Fill positional arguments and options separately, without shell quotes. Arrays use JSON; boolean options accept true or an empty field.

Confirmation temporarily restores the normal terminal for output, download progress and authorization. It skips neither confirmation nor system permission. Press Enter to return; software installation exits TUI after completion or handoff to release files that need replacement.

Ctrl+C during authorization or a continuous command exits the whole CLI; already submitted work may continue. Foreground run and another ui session remain direct CLI entries.

Protection and read-only access

Claude protection allows navigation, status, reports and appearance edits. Network mutations—including profiles, nodes, rules, updates, Geo and autostart—remain locked. Forms do not bypass backend permission checks.

After a read failure, old snapshots are marked as reference data and cannot be submitted. Browsing or testing cannot implicitly start a stopped core during protection.

Recovery

Press r to retry. A larger window can show more content. If recovery fails, exit and export diagnostics using the original account and data directory.

TUI does not require fixed colors or screen coordinates. Automation should prefer CLI JSON and exit codes. See the full terminal reference ↗.

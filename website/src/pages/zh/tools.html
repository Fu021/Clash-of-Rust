从你看到的现象找起

不用先记住工具的名字。找到对应的现象，运行旁边的检查。

{{tools:symptoms}}

检查范围

  • 按需运行，不在后台扫描。
  • 网站和 HTTP 类检查经过内核现有的本机代理。检查不会启动内核、切换节点，也不会回退到直连。
  • 切换页面或工具会取消检查并清空结果，需要保留时先导出。
  • 报告里不包含网址的路径和查询参数、账号密码，以及下载到的正文。
{{tools:articles}}

规则、配置与运行状态

网站检查显示真实请求命中的规则及策略链。

用 cor config get 或 cor config effective 查询配置，cor config check 校验配置。

流量汇总看连接页，节点详情看代理页，内核状态看首页或诊断报告。

参数与上限

默认 5 次、间隔 1000 毫秒、单次 10 秒、下载上限 8 MiB、最多 8 跳。GUI 按工具显示参数；TUI 按 o 在当前工具中编辑适用参数，应用后运行；CLI 使用以下选项。

{{tools:options}}

稳定性检查最长 120 秒。

Claude 保护开启时

保护开启，或者读不到保护状态时，工具箱不查询系统 DNS，不发送 UDP、ICMP 和逐跳探针。依赖这些的检查不会运行，而是说明不可用的原因。其余检查仍然经过本机代理和现有规则，所以不能借诊断绕过保护。

如果你在设置里关闭了 UDP，UDP 探针同样不会发送。

看懂报告，保存报告

每份报告以四种状态之一结束，它们不能互相替代。后两种状态下，命令行返回非零退出码，但仍然会先输出报告。

complete

每一步都运行了，并且得到了结果。

partial

有的步骤有结果，有的没有。正常达到时间或流量上限，不会因此被降为部分完成。

failed / unavailable

检查运行了但失败，或者在这里根本无法运行：缺少系统组件、权限不足，或者保护处于开启状态。

在窗口里

点结果下方的“导出诊断”。导出内容包含当前工具、结果和错误码。

在终端界面里

真实检查结束后按 e，填写路径并确认导出 JSON。写入失败可修改路径重试；演示模式不写文件。

在命令行里

加 --json 直接输出报告，或者用 --output FILE 保存到文件。

$ cor network phase example.com --seconds 5
$ cor network stability example.com --count 10 --interval-ms 500
$ cor network check example.com --json
$ cor network tls example.com --output tls-report.json

JSON 里有 schema、tool、只保留源站的 target、elapsed_ms、status 和一组 entries。每一项包含 label、detail、code 和 success；success 为 null 表示这是一条说明，或者结果未能确认。cor network check 沿用原来的 JSON 结构。

在哪里找到它

窗口侧栏“工具”下的“网络诊断”。输入、操作和结果在同一张卡片里。
Android同一套工具，从“工具”入口进入。路由追踪取决于系统里有没有 traceroute。
命令行cor network 后面跟工具名和目标，Windows、Linux、macOS 通用。
终端界面运行 cor ui，按 4 进入。[ 和 ] 切换工具，/ 输入目标，Enter 运行，Esc 取消。

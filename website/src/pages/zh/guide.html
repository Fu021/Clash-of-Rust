从安装包到第一次连上

这里讲的是你最常用到的部分。照着做一遍，大约几分钟就能连上；后面的章节可以用到时再查。

首次连接

先在下载页安装对应系统的安装包。安装包已经带有 mihomo 内核和 Geo 数据，你只需要准备一个订阅链接，或者一份本地配置文件。

  1. 打开订阅页，添加机场提供的订阅链接，或者导入一份 YAML 文件。
  2. 在这条订阅上点使用。在此之前，客户端用的是内置的“默认直连”，所有流量都直连。
  3. 打开代理页，给节点测速，选一个。
  4. 回到首页，选择模式（规则、全局或直连），再选择接管方式（系统代理或 TUN）。
  5. 连接。第一次使用 TUN 时，系统可能会要求授权；在 Android 上，允许 VPN 请求。

关掉窗口不会断开任何东西：界面进程退出，托盘和内核继续运行，随时可以从托盘重新打开窗口。

订阅

Clash of Rust 读取的是 mihomo / Clash Meta 格式的 YAML，不做格式转换。如果链接返回的是节点分享链接、Base64 列表，或者 sing-box、Xray 的配置，客户端会提示“订阅格式不兼容”，并保留你现有的订阅不动。这时请向机场要 Mihomo 或 Clash Meta 的订阅链接。

  • 远程订阅默认每 360 分钟自动更新一次。间隔可以在设置里改，范围 0～10080 分钟，填 0 关闭。
  • 本地文件可以改名、删除，但不会自动更新。
  • 下载或校验失败时，已保存的订阅和当前运行状态都保持原样。
  • Claude 保护开启期间，定时更新和手动更新都会暂停。
$ cor profile add home 'https://example.com/subscription'
$ cor profile list
$ cor profile update --all
$ cor config set subscription_update_interval_minutes 720

节点与模式

节点可以用宫格看，也可以用紧凑列表看。可以测速、按名称筛选，并在允许手动选择的策略组里切换。不打开窗口，也能在托盘菜单里切换节点、查看当前速度。

模式效果
规则每条连接按规则逐条匹配，由规则决定走节点、直连，还是拦截。
全局所有流量都从 GLOBAL 组里选中的节点出去。
直连所有流量直接出去，不经过代理。
接管方式效果
系统代理设置操作系统的代理。遵守这项设置的程序会经过客户端。
TUN创建一块虚拟网卡，在网络层接管流量，连不理会系统代理的程序也能接管。服务器上建议用它。

规则模式下，首页显示的节点是默认规则当前选中的那个。某条连接可能命中别的规则、走别的线路；连接页会显示每条连接实际命中的规则和线路。

规则

订阅自带的规则是只读的，但可以调整顺序。你自己的规则可以添加、编辑、停用、移动和删除。修改要先通过 mihomo 的校验才会保存，订阅原始的 YAML 不会被改写。

快捷规则

五个开关，对应最常见的几种情况。默认全部关闭，开启后只补上订阅里缺少的规则，不会重复添加。

ads拦截广告域名
private-domain私有域名和本地域名直连
private-ip私有 IP 段直连
cn-domain国内域名直连
cn-ip国内 IP 段直连
 
$ cor rule add 'DOMAIN-SUFFIX,example.com,DIRECT' --position 1
$ cor rule shortcut ads on
$ cor rule list --filter example
$ cor network explain example.com   # 它命中了哪条规则？

Android 应用分流

在设置里打开应用分流，决定哪些应用进入 VPN。

模式选中的应用其余应用
全部应用进入 VPN进入 VPN
仅选中进入 VPN使用系统原有网络
排除选中使用系统原有网络进入 VPN
  • 进入 VPN 不等于强制走代理节点。流量具体去哪，仍然由当前模式和规则决定。
  • Android 10 及以上，还可以给单个应用指定出口：直连、某个策略组或某个节点。Android 8 和 9 只有上面三种模式。
  • 已连接时保存，客户端会请求重建 VPN，让改动生效。
  • 如果系统设置里开了“阻止不使用 VPN 的连接”，被你留在 VPN 之外的应用仍然可能被系统拦住。

完整行为见 android-application-routing.md。

访问检测

侧栏“工具”下有三个页面，各回答一个问题。

网络诊断这个网站为什么连不上？十一项按需运行的检查，详见网络工具页。
IP 检测外面看到的是什么？出口 IP，以及 GitHub、AI 服务、流媒体经当前节点能否访问。结果按分类列出，可以筛选、重测和导出。
A÷检测在 Claude 看来有没有异常？把地区、DNS、WebRTC 和项目配置方面的线索汇总成一份报告。

检测跑完，只说明观察已经完成，不说明服务一定可用。请看报告本身：失败的项目就记为失败，不会算成“可访问”。

$ cor ip-check list
$ cor ip-check --category AI -o ai-report.json
$ cor claude check

Claude 保护

有些时候你需要一个固定不变的出口，不希望手滑点错，也不希望有连接悄悄绕出去。Claude 保护就是为这种时候准备的。它默认关闭，开关在 A÷检测页面。

开启之后

  • 固定当前节点，并用优先规则把 Claude 相关的流量都导向它。
  • 启用 TUN、严格路由、IPv6 与 UDP 接管和 DNS 接管，DNS 经同一个节点走加密的 DoH。
  • 实时拦截会绕开固定节点的连接。开启时会先关闭内核里已有的连接。
  • 锁定节点、模式和网络设置的修改。主题、强调色和只读页面照常可用。
  • 订阅更新暂停。在 Android 上，应用指定出口暂停，VPN 临时覆盖全部应用。

关闭之后

恢复你原来的模式、接管方式和节点选择。订阅、规则，以及 DNS、IPv6、UDP 的偏好从头到尾没有被改写，只是被临时覆盖。

开启时的确认按钮要等 3 秒才能点。全局模式下，如果所选线路的最终出口是直连，保护会拒绝开启。

$ cor claude protect on --yes
$ cor claude watch          # 观察真实线路和被拦截的请求
$ cor claude protect off --yes

检测只提供线索，不能保证第三方服务一定接受你。保护的范围和边界见 claude-protection.md。

命令行

Windows、Linux、macOS 的桌面安装包都自带 cor。它不需要显示器，和窗口共用后台与内核：窗口开着时，cor 操作的就是它；窗口没开时，需要后台的命令会自动启动一个不带窗口的后台。

系统cor 在哪里
Debian / Ubuntu/usr/bin/cor，装完 DEB 就在 PATH 里
Windows安装目录里的 cor.exe，例如 C:\Program Files\Clash of Rust\cor.exe。常用的话，把这个目录加进 PATH。
macOS/Applications/Clash of Rust.app/Contents/MacOS/cor。可以自己建一个符号链接到 PATH 里的目录。

第一次使用

$ cor profile add home 'https://example.com/subscription'
$ cor profile use home
$ cor start              # 后台运行，关掉终端也不会停
$ cor node select        # 输入文字筛选，按编号选择，q 取消
$ cor proxy tun
$ cor status
$ cor stop               # 停止内核，恢复网络

日常请用 cor start。cor run 在前台运行，终端一关就停，只适合调试。

按用途找命令

运行start stop restart status version启动、停止和查看后台。status --watch 持续刷新。
线路mode proxy envmode rule|global|direct，proxy system|tun|off，以及给当前 shell 用的代理环境变量。
订阅profileadd、import、list、use、update、edit、remove、export
节点nodelist、select、test（单个节点、单个策略组或全部）
规则rulelist、add、edit、move、enable、remove、shortcut
连接connectionlist 和 show：每条活动连接命中的规则和线路
诊断network dns ip-check diagnose十一项检查、访问检测，以及反馈问题用的完整报告
设置configget、set、check、effective
维护update geo autostart service completion更新、Geo 数据、开机自启和 shell 补全

cor help 列出日常命令，cor help all 列出全部命令，每条命令都支持 --help。

写脚本时

  • --json 输出一份机器可读的结果；--jsonl 逐行输出，适合状态、日志和连接。每一行的外层都是 {"schema":1,"command":"…","data":…}。
  • 结果写到 stdout，进度、授权提示和错误写到 stderr。
  • 凭据默认隐藏，加 --show-secrets 才会输出。有破坏性的命令需要 --yes。
  • --timeout N 设置单次后台请求的等待秒数，默认 300，最大 3600。
退出码含义
0成功，或者下游管道已关闭
1操作、校验或权限失败
2命令或参数格式错误
3后台启动失败或无法连接
124请求超时
130查询被中断

全部命令和选项见 cli.md。

终端界面

cor ui 打开一个用键盘操作的界面，有首页、节点、连接、网络检查四页。它目前是原型：编辑订阅、规则、更新和大部分设置，还得用上面的命令。cor ui --demo 用虚构数据演示，不连接后台，也不保存任何设置。

按键作用
1 2 3 4 Tab在首页、节点、连接、网络之间切换
↑ ↓在列表里移动
Enter打开策略组；选中成员后，再确认一次才切换
/搜索；在网络页用来输入目标
Esc返回、清除搜索或取消
r立即重新读取
q Ctrl+C退出。后台和代理保持原样。

需要真实的交互终端，至少 60 列 × 18 行。打开、浏览和退出都不会启动后台，也不会改动代理；后台没在运行时，它会提示你先执行 cor start。

更新与开机自启

应用按你选的通道检查更新，默认只看正式版；下载时显示进度，可以取消。安装包先校验 SHA256 再运行，升级保留订阅和个人设置。在 Android 上，安装由系统确认。

$ cor update check
$ cor update download -o update.deb   # 下载并校验，不安装
$ cor update install --yes
$ cor geo update                      # 更新 Geo 数据

开机自启

下面两种选一种，不要同时用。

  • 桌面程序：在设置里打开“后台自启动”，或者运行 cor autostart on。登录后恢复后台和已保存的网络模式，窗口保持关闭，等你自己打开。
  • 只用命令行：cor service install --yes 为当前用户注册后台。它是登录后启动的用户级自启项，不是登录前就运行的系统服务。

遇到问题时

提示“订阅格式不兼容”链接返回的不是 mihomo YAML。向机场要 Mihomo 或 Clash Meta 的订阅链接。
某个网站打不开先运行网站检查，再看规则与出口。
Windows Defender 告警先核对文件的 SHA256，再看告警处理说明。来源不明的告警，不要直接放行。
macOS 打不开应用DMG 没有经过 Apple 公证。按 Apple 的说明，在“隐私与安全性”里放行。
cor 提示后台未运行执行 cor start。status、node list 这类只读命令不会替你启动后台。

提交一份有用的报告

窗口里，出错提示和检查结果旁边有“导出诊断”。在终端里：

$ cor diagnose --output cor-diagnose.json
$ cor diagnose --offline -o cor-offline.json   # 只采集现场，不访问网络

报告不会自动上传。订阅凭据和控制密钥不会写进报告，但日志里可能有域名和 IP 地址，附到 Issue 之前请自己先看一遍。

卸载之前

如果你用自定义数据目录配置过命令行自启，先执行 cor stop 和 cor service remove --yes。Windows 的卸载程序可以选择删除全部配置和数据，这一项默认不勾选。

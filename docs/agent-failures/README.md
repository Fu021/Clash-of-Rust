## 排查顺序

1. 找最早失败的 job；输入解析、已验证 CI 或缓存恢复失败可能使整组平台被跳过或连带失败。
2. 区分源码/生成代码、测试假设或竞态、外部服务/runner、产物/发布前置条件，再查相关主题的错误签名。
3. 对照失败步骤、实际 diff 和公开修复证据定位根因，补充必要的最小回归验证；不要对固定端口、runner 或临时路径加特判。
4. 收尾按 [AGENTS](../../AGENTS.md#任务收尾与失败复盘)更新相关文档及[最近复盘](reviews.md)。已有模式链接引用；新模式写入对应主题，保持症状、根因、修复、预防与证据完整。

新增主题仅在现有分类不再适用时拆出；不要为每次任务创建一套重复文档，也不把这里的内容复制进根 `AGENTS.md`。

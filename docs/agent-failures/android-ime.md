## 2026-11-05 多版本对照

[issue #31](https://github.com/Fu021/Clash-of-Rust/issues/31) 的 Redmi K30 / MIUI 14.0.5 在两种输入法下均有光标却无键盘。准确 Android API 级别及 MIUI 实机仍未验证；下列模拟器现象不能直接证明与该设备同根因。

`1851b2f` 的专项 `41999178442` 与采集修正 `f4defcf` 的补测 `42003318092` 合并覆盖 API 26、28、29、30、31、32、33、34、35、36。每个系统三轮正式路径；API 30+ 再三轮移除输入视图动画回调的对照。前两轮动画倍率为 1，第三轮为 0。最终取得 51 轮、346 张截图及配套状态；JUnit 成功只表示导航与采集完成。

| 系统 | 正式路径的截图结果 | 移除动画回调的对照 |
| --- | --- | --- |
| Android 8 / 9 / 10，API 26 / 28 / 29 | 三轮名称、地址及 Back 后重开均可见键盘 | 不支持该动画接口，不运行此对照 |
| Android 11，API 30 | 三轮名称可见，切换地址后三轮均无键盘 | 前两轮切换地址仍无键盘，第三轮可见 |
| Android 12 / 12L，API 31 / 32 | 名称三轮均未绘出键盘，部分状态却报告 IME 可见 | 名称三轮均可见；关闭动画的第三轮切换地址仍会消失 |
| Android 13 / 15，API 33 / 35 | 正常动画两轮名称、地址可见；关闭动画时切换地址异常 | 本轮名称、地址及重开截图可见 |
| Android 14，API 34 | 名称可见；首轮切换地址无键盘，其他时点存在状态变化 | 本轮名称、地址及重开截图可见 |
| Android 16，API 36 | 三轮名称、地址及重开截图可见 | 本轮截图可见 |

截图、输入法 dumpsys 和应用 JSON 按顺序采集，并非同一原子时点；动画或异步隐藏期间可能彼此不同。API 34/35 的六个 Back 后时点没有处于前台且有焦点的 Activity，JSON 的 Android 部分为空，截图仍保留；不能把这些未知值算作隐藏或显示成功。不能只凭 `ime_visible` 或单次几何值判定实际显示。

## 已收窄的实现风险

- `v0.6.6` 与本轮修复前的 Java helper 已含将动画回调移至输入视图的 OEM 修正；[上游 #11344](https://github.com/slint-ui/slint/issues/11344) 不能当作本次遗漏补丁。重复点击已聚焦输入框也会再次请求键盘。
- API 31/32 的保留与移除回调对照明显不同，优先调查 `WindowInsetsAnimation.Callback` 所选择的窗口合成和动画路径。API 31 的正式路径曾同时有有效输入连接、`mInputShown=true`、可见 IME surface 与空白截图；这不能归为简单没有调用 `showSoftInput()`。
- API 30 等版本在字段切换后仍会隐藏，移除动画回调并未解决全部现象。继续核对 helper 的 `requestFocus()`、`restartInput()`、显示与隐藏请求时序及系统回调；不使用无限重试或强制弹出来掩盖失败。
- 所测版本的 `MobileView.keyboard-inset` 始终为 0，即使截图有键盘。这是 Android 窗口属性未同步到移动布局的独立缺口；下述本地补丁未进入这些 APK，不能视为已验证修复。
- API 26/28 日志中有 ART 尝试解析较新动画及 Back 接口的类加载提示，但相应测试仍启动并绘出键盘。不能把这些提示直接当作输入失败或应用崩溃的根因。

## 当前修复与待验收

- CI `42247872414` 的 API 31 恢复前台时，Android 已重新显示键盘而 Slint 高度尚为零；恢复测试反复点击旧坐标，随后两个字段均失焦。恢复流程改为先核验系统恢复的键盘、字段避让与 Back 清零，再等待几何稳定、单次点击目标字段，只读等待焦点。保留恢复前后截图及全部键盘断言，不能用重复触摸掩盖生命周期或布局问题；本修正待同提交 Actions 验证。
- CI `42253136066` 的 API 36 在“已隐藏”截图中实际出现键盘，随后地址字段失焦；API 31 的错误栏关闭点击也失败。`nativeDiagnostics` 原先只返回后台周期更新的 `PRESENTATION`，等待 250 毫秒的几何稳定并不能排除约一秒的旧快照。采样改为在 Slint 所属线程读取，等待最长一秒；超时仍保留旧现场并标记 `live=false`，触摸和成功断言不得接受旧快照。所有按钮都等待实际几何稳定，恢复键盘还核对隐藏截图后的系统与 Slint 状态；不把截图文件名当作键盘已隐藏的证据。待新提交 Actions 验证。
- 不发布打包 `42225435685` 的 Android x64 首轮输入失败时，后台“检查更新失败”通知遮住订阅名称框。按[通知等级](../../crates/client-ui/README.md)将可恢复失败保留在顶部详细栏，严重故障才居中并阻断背景；两者均保留诊断与关闭入口。后续 CI `42231435994` 暴露 Slint 将 Android 返回映射为 `Key.Back`，仅处理 Escape 与 Java 回调会漏掉原生键；关闭按钮几何通过实时属性读取，避免异步全局投影漏掉重建后的坐标。输入回归先真实触摸关闭普通错误，再注入严重错误并验证 Back 关闭和草稿保留，然后继续字段切换、前后台及旋转；尚待同提交 Actions 验证。
- CI `42243011533` 的 API 31 已通过错误栏关闭、严重弹窗 Back 和前四次字段输入；第五次等待键盘时两个字段均失焦。采集同时显示：键盘收起后字段坐标仍短暂保留旧布局，测试在焦点快照更新前会重复点击；第四次地址提交也在短暂满足长度断言后变为 53 字符。回归改为等待字段与视口几何稳定后单次触摸，只读等待焦点；输入前等待 Java editable 与 Slint 字数同步，结束组合再替换整段，并在稳定期后再次核对文字长度。保留真实键盘、遮挡、崩溃及前后台断言，不以重放触摸或重启输入法改判；这些时序修正尚待同提交 Actions，不能据此认定输入后端没有缺陷。
- [Java helper](../../vendor/slint-android-activity/java/SlintAndroidJavaHelper.java) 移除应用动画回调；显示请求合并至下一帧，隐藏延后 150 毫秒并可被新的显示请求取消，只执行最新状态。`42031422051` 的 API 34 首轮切换字段时，隐藏请求已先发出，约 30 毫秒后才显示，系统随后继续旧的隐藏动画；仅按一帧合并仍不足。取消中间隐藏时也保留输入视图焦点，实际离开编辑器仍有界隐藏；窗口尚无焦点时等待焦点到达，已经发出的显示请求不因窗口再次获得焦点而重放。
- 每次显示请求只走一套系统接口：API 26–32 在输入视图有焦点后调用 posted `showSoftInput()`；API 33+ 优先 `WindowInsetsController`，控制器不可用时才回退输入法管理器。旧补丁参照 [AndroidX 实现](https://github.com/androidx/androidx/blob/androidx-main/core/core/src/main/java/androidx/core/view/SoftwareKeyboardControllerCompat.java) 同时调用两个入口；`788e8ed` 的 API 31 首轮采集时 Gboard 在 `onStartInputView` 中空指针崩溃，三轮严格回归仍通过，尚不能认定重复请求就是该输入法崩溃的唯一根因。保留输入法崩溃门禁，不通过重启或忽略崩溃冒充成功；未加入持续重试、强制键盘或测试进程专属修复。
- [Android 窗口](../../crates/client-ui/ui/mobile/android/window.slint) 将系统键盘高度同步给共享布局，扣除已由布局处理的底部安全区，收起恢复为零。旧 API 的可见区域推断先排除稳定系统栏；横屏侧导航栏不能被当作一个占满屏高的键盘。订阅编辑器在键盘或视口变化、焦点切换时滚动显示当前字段，避免小屏或横屏仍被遮挡；普通手动滚动不触发反复拉回。
- 横屏键盘可能只给表单留下约 64 逻辑像素；固定保存按钮会把滚动视口进一步挤到不足一个输入框，即使字段坐标高于键盘仍会被裁掉。低矮编辑器将同一组保存/取消操作放入滚动内容，保留字段空间；回归读取真实滚动视口，要求聚焦字段完整落在其上下边界内，不再只检查键盘顶边。
- 字段避让直接读取当前组件几何，不用 `changed` 异步投影到全局的旧坐标计算滚动增量；键盘、视口和焦点连续变化时，重复计算也不应把字段滚出顶部。对外诊断仍保留全局快照，普通手动滚动不触发自动拉回。
- [正式界面回归](../../apps/android/app/src/androidTest/java/org/clashofrust/android/ProxyTunTest.java) 连续切换五次字段，检验文字进入真实输入连接、稳定显示、系统高度与 Slint 布局数值一致及输入框未被键盘覆盖；再检验 Back 清零、重开、前后台与横竖屏恢复。每个系统三轮，前两轮动画倍率为 1，第三轮为 0，保留正式路径截图探测。专项仍只构建一次 APK。
- 每轮必须导出截图、状态、输入法与窗口 dumpsys；日志按本次 marker 隔离，并记录当前输入法崩溃，避免旧日志污染或把输入法进程崩溃误判成应用成功。logcat 先保存原始字节，供查看的文本以 UTF-8 替换无效字节，保留 marker 和崩溃检查；`42037263494` 的 API 34 已完成 instrumentation，却因系统日志中的无效 UTF-8 中断后续导出，不能将这类缺证据当作成功。截图、API 状态与布局断言共同验收，不能仅以 JUnit 成功认定键盘已绘出。
- `0100f5b` 的常规 CI `42050212504` 中，API 31 instrumentation 返回 `OK`，随后一次性 `logcat -d` 超时，导致截图导出也未执行；不能将其视为最终验证通过。采集改为测试前启动日志流并直接保存原始字节，确认开始 marker 已落盘后才运行测试，收尾要求结束 marker 齐全，再核验本轮崩溃；不按启动瞬间的最后一条日志截取，避免日志流稍晚连接时跳过开始 marker。流提前退出或 marker 缺失仍失败，但保留已有日志并继续导出截图。
- `f1983e2` 的常规 CI `42056849111` 已完整导出日志，API 31 的 JUnit 返回 `OK`，但第一次显示时捕获到 Gboard `InputView.a(boolean)` 空指针，严格崩溃门禁正确失败；500 毫秒内有两次显示请求，不能仅凭相邻事件认定重复请求就是根因。发生该崩溃时，仅在可调试 API 31 模拟器中追加原生 `Activity` / `EditText` 对照，分别清空该模拟器输入法的测试数据后发送一次或两次请求，保存版本、日志、截图和状态。对照界面仅存在于测试 APK，不加载 Slint；原始失败与证据保留，对照不替代订阅回归，也不重启输入法后将原回归冒充成功。
- 测试高度采样在 API 30+ 使用 `WindowInsets.Type.ime()`；API 26–29 仍需旧版稳定导航栏 API，以区分系统栏和真正键盘。弃用标注仅限这一兼容方法，保留全局 `-Xlint:deprecation`，不影响现代接口检查。
- `42026115423` 的 API 28/32 暴露无障碍根节点不能可靠代表 Slint 原生窗口是否可交互；就绪改查真实 Activity 焦点、可见 decor 和布局，随后仍用触摸与页面变化证明交互。API 29 恢复前台后系统曾明确报告没有可触摸窗口；恢复字段焦点沿用 30 秒预算有限重取实际坐标，必须确认指定字段获得焦点，不能仅以事件投递成功或另一字段的键盘已显示通过。
- API 33/34 横屏及 `42031422051` 的 API 35 恢复竖屏失败，截图和系统状态均显示真实键盘重新打开，不是系统栏被误算为键盘。横竖屏共用验收：先核验重开的实际焦点、高度与字段避让，再发送 Back 并核验系统键盘隐藏、Slint 高度清零及侧导航栏不算键盘；保留重开、隐藏和后续输入截图，不删除原有高度/遮挡断言。每轮必须导出新增的 `portrait-hidden` 四份证据。
- `42031422051` 的 API 28 三轮恢复前台均出现旧 `BufferQueue` 被丢弃、`EGL_BAD_SURFACE [300d]`，随后 Slint 事件循环退出、Activity 销毁；不是输入字段等待时间不足。窗口仅在表面已初始化且获得焦点时绘制，失焦、暂停或停止后暂停动画驱动；终止表面时失效渲染资格，获得新表面/焦点后请求重绘。固定版本 Skia 的交换缓冲 `[300d]` 错误仅释放失效表面并等待下一次 `InitWindow`，其他渲染错误仍传播；真实前台触摸、输入、旋转和截图断言必须全部通过，不能以进程未退出代替恢复成功。

## 采集失败与验收边界

- 首轮 `41993603936` 被首帧诊断尚未就绪及镜像元数据差异阻断，不算复现。API 31 官方 `x86_64-31_r14.zip` 的下载 revision 为 14，包内 `source.properties` 为 12；分别固定下载身份与包内版本，不放宽为任意值。
- `41995793003` 首次得到 API 31 空白键盘与 API 36 可见键盘的截图；该轮关闭系统动画。后续矩阵补上正常动画、不同系统及回调开关，未将旧运行的成功代替新证据。
- 十版本首轮中 API 30 因存储权限无法导出截图，API 32 被无障碍根节点检查阻断，API 34 模拟器中途断连。前三者的缺失证据由补测补齐；模拟器断连原因尚未确定。
- `f4defcf` 只在确认是可调试模拟器后，才为权限失败重启 root adbd 并重新导出；缺必需截图或状态时失败。探测以 Activity 焦点和真实触摸导航判断就绪，常规严格输入法回归不变。Actions 的 174 项脚本回归（1 跳过）与 11 项产物回归通过；本机仅静态检查。
- 所有截图使用虚构名称与地址，仅测试 x86_64 通用模拟器。API 27、MIUI、ARM 实机、第三方输入法、完整订阅保存、真实 VPN、休眠及重启未由此专项验收；成功采集不等于 Android 8 起全面兼容。
- 故障设备采集跨进程 `adb logcat -b main -b system -v threadtime`、点击前后 `dumpsys input_method`、`dumpsys window windows` 和准确 API 信息，分享前脱敏。`cor logs` 是内核日志，不能替代输入法与系统窗口日志。

# 桌面与命令行下载

[返回索引](README.md)。

手动订阅、Geo 和 `cor update install` 曾在共享后台锁内等待网络；慢网时其他窗口和命令也无法读取状态。下载改在锁外，最终验证与提交由所有者串行处理。手动订阅提交前核对原订阅、文件摘要和保护状态；定时更新还须核对定时开关。失败或过期结果保留现有数据。Geo 和客户端更新也限制同类任务并发，停止内核会取消尚未安装的下载。

GUI/CLI 的订阅更新在开始下载前也核对当前名称和来源；旧版控制请求和显式导入允许指定新来源，两者下载后均检查原配置未被并发修改。新增的控制字段缺省保留旧请求语义，避免把正常换源误判成过期更新。

本机控制连接中断或超时时，订阅、Geo 和客户端更新取消尚未提交的下载并清理暂存；进入安装事务后继续完成或恢复，不能中途丢弃事务。客户端安装交接一旦开始，系统安装程序可能已启动，断开请求不等于撤销安装。慢速下载、取消、重复请求及订阅被编辑后的回归见 [下载任务](../../crates/client-runtime/src/engine/downloads.rs)和[控制连接](../../crates/client-runtime/src/control/transport.rs)；实际网络、安装授权和设备行为须以同提交 CI、安装验证及用户设备结果为准。

macOS 的 `cor update install` 还会等待 DMG 校验和系统授权；此阶段不能持有共享后台锁。助手暂存后须等待所有者复核更新通道、取消状态与 GUI 身份，并收到提交许可且旧进程退出后才替换应用。取消、交接目录消失或未获许可均保留旧应用；普通权限与管理员授权路径遵守相同条件，放弃交接后清理独立暂存目录。

Windows 安装器在交接时可能立即执行；目前等待 UAC 的 `cor update install` 仍持有后台锁，状态请求可能等待授权。不能直接套用 macOS 的等待闸门：需先设计兼容旧安装包、授权取消与事务恢复的安全交接，再以真实 UAC 场景验证。

## 订阅客户端识别

[Issue #30](https://github.com/Fu021/Clash-of-Rust/issues/30) 的截图显示推荐客户端和“不支持本机场协议”的 SS 提示节点，不能据此认定内核将 VLESS 转成 SS，也不能直接认定机场故意封禁。订阅请求应声明内核兼容能力；混合客户端标识可能触发 V2rayN/NG 的非 YAML 分支，须有受限的 Meta 格式回退。仅含重复占位节点的配置不能替换用户订阅，但真实节点和 provider 必须保留。格式协商、错误分类和上限统一见[订阅说明](../subscriptions.md#客户端兼容与格式)；回归以本机 HTTP 夹具模拟服务端分流，不使用真实订阅令牌。

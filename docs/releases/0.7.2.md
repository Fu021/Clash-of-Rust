# 0.7.2

## 更新

- TUI 按手机 SSH 与桌面终端的宽高自动重排，完整导航按实际文字宽度保留，不再低于 80 列就紧缩；紧缩时各页及连接详情标题居中，帮助、表单和长结果按宽度换行。节点排序用一个入口循环切换并保存当前模式。
- TUI 设置按类别组织，补齐 Fake-IP 实际状态、订阅选择与独立快捷规则；订阅已包含的规则禁止重复添加，保存失败保留草稿。连接详情分别展示真实原始域名与嗅探信息，隐藏缺失字段。
- 网络工具箱收敛为十二项专项检查，明确代理路径、证据与测量边界；路由追踪解释无响应的跳数，不将星号当作断网。TUI 可直接编辑当前工具参数，并导出本次 JSON 报告，无需重新运行检查。
- 更新安装失败后保留可恢复警告与诊断入口；Android 待呈现警告在前台实际展示后才确认，避免重开界面或其他提示遮挡时丢失。

## 验证与已知问题

- 发行门槛包括同提交 CI、Android 8.0～16 十一个系统版本、Ubuntu 20.04 双架构、内存基准及发行签名验证；实际运行结果与包身份以该版本的 Actions 和最终发布回执为准。桌面终端验收包含八个主页面、可操作选项及子页面，演示数据与隔离后台的实际操作分别标注。
- TUI 退出会释放前端；既有短时测量中后台与内核合计未完全回到初始值，不能据此承诺长期或所有平台零增长。手机 SSH 真机与长期负载不属于终端仿真验收。
- Windows 用户现场代码 68 的原始原因尚未复现；独立 Mihomo 共存更新的自动化通过不等于定位了该现场。厂商 ROM、真实设备首次授权及长期网络仍需实际使用验证。

## Updates

- The TUI rearranges itself for the width and height of phone SSH and desktop terminals. Full navigation remains visible whenever its labels fit, including below 80 columns. In compact mode, page and connection-detail titles are centered; help, forms and long results wrap to the available width. A single control cycles through and saves node sort modes.
- TUI settings are organized by category, with effective Fake-IP status, profile selection and separate shortcut rules. Rules already included in a profile cannot be added again, and failed saves preserve drafts. Connection details show actual original and sniffed domains separately and hide missing fields.
- The network toolbox now offers twelve focused checks that identify proxy paths, evidence and measurement limits. Traceroute explains unanswered hops without treating asterisks as disconnections. TUI can edit options for the current tool and export its report as JSON without rerunning the check.
- Recoverable warnings and diagnostic access remain available after an update installation fails. Android warnings are acknowledged only after they are actually presented in the foreground, so reopening the interface or another notification cannot hide them.

## Verification and known issues

- Release gates cover CI, eleven Android versions from 8.0 to 16, both Ubuntu 20.04 architectures, memory benchmarks and release-signing verification for the same commit. Refer to that release's Actions runs and final receipt for actual results and package identities. Desktop terminal acceptance covers all eight main pages, available actions and subpages; demo data and actual operations against an isolated backend are identified separately.
- Exiting TUI releases the frontend. In existing short-term measurements, combined backend and core memory did not return fully to its initial level; this does not establish zero growth over the long term or on every platform. Phone SSH devices and long-running workloads were not covered by terminal emulation acceptance.
- The original cause of the reported Windows code 68 incident has not been reproduced. An automated update test with a separate Mihomo process passing does not identify the cause of that incident. Vendor ROMs, first-time authorization on real devices and long-term networking still require real-world validation.

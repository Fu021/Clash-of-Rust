# 0.6.7-fix.5.cli-tun-coverage

基于 `0.6.7-fix.4.direct-downloads`，本轮补齐 CLI 上下文补全、更新重启的数据目录继承和 Linux TUN 覆盖核验。

- `cor completion` 生成的 Bash、Zsh、Fish 与 PowerShell 脚本改为调用隐藏的本地补全入口。命令树、当前命令选项、`config get` 可读键、`config set` 可修改键，以及布尔、主题、强调色、节点排序、shell 和日志等级等已知值按上下文提供；补全不读取设置、不启动后台，也不创建数据目录。
- 桌面自动更新把当前数据目录写入安装交接；替换后的 GUI 通过 `CLASH_OF_RUST_DATA_DIR` 恢复同一 `settings.json`。旧版 `plan.json` 缺少该字段时仍兼容，不把 CLI、root 与普通用户各自的数据目录误当成同一实例。
- Linux 开启 TUN 后对示例 IPv4 路由做短重试核验；内核启用 IPv6 时同时核验 IPv6。若样本仍经过物理接口，切换失败并回退原代理模式，不把控制接口的 `tun=true` 当成全机接管成功。未知、权限不足或非 Linux 样本不会被伪装成已覆盖。
- `cor diagnose` 与 `cor diagnose --offline` 增加 `tun_configuration`，只提取实际运行配置的 `auto-route`、`strict-route`、`route-address`、`dns-hijack`、DNS 模式与 Fake-IP 段；不包含 DNS 服务器正文、订阅凭据或控制密钥。`host_routes` 的警告可区分外部 TUN 与本程序 TUN 的部分 IPv4/IPv6 绕过。
- Android 安装包的 `.sha256` 与桌面、服务端打包器统一为单摘要文件，避免同一发布流程出现两种校验文件格式。

当前为待验证版本；需要同提交 CI 和不发布打包验证。路由样本只覆盖两个示例目标，不能代替真实应用错误、全部路由表、长期 TUN 或真实设备验收。

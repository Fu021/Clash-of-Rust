# 0.6.7-fix.7.settings-storage

相对上一次公开的 `0.6.7-fix.4.direct-downloads`，本轮改善 Windows 安装后的用户文件写入、CLI 配置、Linux TUN 观察、控制连接恢复和桌面布局，并精简通知。

- Bash、Zsh、Fish 和 PowerShell 增加上下文补全，覆盖命令、选项、`config get/set` 配置键及枚举值；补全本身不创建后台或用户数据目录。
- 更新安装交接保留实际用户数据目录，重新打开同一份设置，避免预发布通道等选项因重启进入另一目录而看似丢失；仍兼容旧版更新计划。
- 设置或订阅索引只有确实不存在时才使用初始值；读取失败或格式损坏时保留原文件并报告具体路径，避免将权限异常误认为空配置。
- Windows 安装完成页和更新后的重新启动改用普通桌面用户身份及对应环境，避免沿用安装器的管理员身份和临时目录；无法取得普通身份时保留安装结果并提示手动打开。更新失败区分主程序、界面、卸载程序、网络助手和安装登记阶段，不再统一归为磁盘写入失败。
- `cor status`、`cor proxy`、`cor stop` 与 `cor diagnose` 在 Linux root 下接受 `--all-users`。该标志只扩大只读 `/proc` 观察范围，显示其他用户持有的 TUN 进程 PID/UID；文本输出即使在本实例自身也使用 TUN 时仍单独显示持有进程摘要。它不会停止、切换或修改其他用户的内核。
- 默认扫描仍只核对当前有效用户，普通用户不再因无权读取其他用户的 `/proc/<pid>/fd` 而得到误导性的“持有进程无法读取”。观察到 TUN 但没有当前用户持有者时，文本提示给出 `sudo cor status --all-users`。
- JSON 的 `host_routes.holder_scope` 与 `tun_holders.scope` 标明 `current_user` 或 `all_users`；`tun_holders.skipped_other_users` 记录默认范围内被跳过的其他用户进程数。
- `proxy --all-users` 仅允许只读观察，不能与 `system`、`tun` 或 `off` 切换同时使用。
- Linux 启用 TUN 后核对示例 IPv4/IPv6 路由，确认仍绕过 TUN 时报告覆盖异常并回退；诊断报告增加路由与 DNS 劫持配置摘要，保留未知或无权限状态，不伪装成完整覆盖。
- root 已具有必要有效网络 capabilities 时允许在 `NoNewPrivs` 环境使用 TUN；不为普通用户放宽提权和 capability 检查。
- 控制接口只读查询遇到连接错误或超时后，最多使用新连接重试一次；写操作不重放，HTTP 拒绝不重试，也不会因超时擅自切换已有内核的控制端口。
- 启动健康检查同时等待代理端口和初始 TUN 配置，避免端口刚绑定便恢复代理模式，与内核尚未完成的初始化相互覆盖；失败仍保留原有回退和诊断。
- 桌面修正滚动内容高度与偏移约束，短内容保持顶部对齐，内容缩短及窗口变高后不留在无效滚动位置；连接列表采用统一自然布局。
- 设置页分组高亮跟随实际滚动位置，点击分组仍可定位；滚到底部显示“计划任务”，窗口放大至内容无需滚动时回到“常规”。
- 桌面设置分组导航移到页头，与标题和内核状态同行；窗口宽度或字号使空间不足时隐藏导航，所有设置仍可纵向滚动访问，不换行或遮挡内容。
- Windows、macOS 和 Linux 去掉系统标题栏，窗口内提供最小化、最大化/还原和关闭；空白标题区可拖动、双击最大化，边缘可缩放。窗口按钮不被错误弹窗禁用，关闭仍遵循托盘与退出策略；左上角图标及几何字标跟随强调色。
- 节点全不可达提示缩短为结果、接管状态与操作建议；后台复测直接更新原警告，不再堆叠“测速失败”和“双目标复测”两段说明。技术细节保留在日志，诊断入口保留；桌面、移动端及 CLI 将“停止接管”明确为“关闭代理”，仍须主动点击或执行，不自动关闭代理或 TUN。Claude 保护期间不提供该操作。
- 桌面和移动端普通通知改为 5 秒自动消失，下沿进度条显示剩余时间，再次通知重新计时；可恢复错误和严重错误继续保留到主动关闭，不显示自动关闭进度，具体错误原因不截断。
- Android 网络集成在重载后再次核对真实 TUN 连接，并在有限预算内验证域名请求；在首次启动前登记完整的测试订阅，使 Activity 冷启动和磁贴恢复使用相同配置，额外核对运行内核已载入出站及持久化 runtime。该调整修正测试前置，不代表已定位用户持续断网的根因。
- 订阅、Geo 和应用更新的内核直连回退改用独立 mixed 端口的 SOCKS5 域名请求，减少内核 HTTP 转发层，域名仍由内核 DIRECT 解析；代理优先顺序、保护门禁与失败保留配置不变。回归核对远端域名、端口、路径及完整响应，隔离环境仍须在节点不可用时实际完成订阅导入和更新。
- Ubuntu 20.04 ARM64 和 x64 的客户端安装验证接入[私网预装模板](../workflows/prepared-vm-images.md)，分别冻结环境和精确恢复；按服务端 `vm_limits` 声明的架构与限制启用，未就绪或恢复失败时保留冷准备。模板独立清理、关机、校验及二次启动后上传，只存私网，不占 GitHub Cache。SSH 就绪检查允许单次探测超时后在总预算内继续等待，不提前中断慢速启动。双架构真实上传、暖恢复及安装后 GUI/代理/TUN 已通过；首组暖环境就绪分别约 5 分 43 秒、1 分 34 秒，仍单列候选包等待及应用验证，不将单次准备节约等同于整个 CI 提速。
- 镜像客户端对齐 `2026-11-08-x64` 协议及完整 46 条共用向量，核对 health 兼容字段的一致性、完整环境和回执身份，接受小数时间戳；上传应答丢失先查询原回执，回执过期则按精确环境键确认，不把发送完成或 pending 当作保存成功。
- CI 各平台和 Memory Benchmark 成功后均尝试保存新编译缓存，同仓库开发分支不再反复只读旧 main 缓存；macOS 复用 Tailscale 引导二进制。保留 9 GiB 总预算、macOS ARM64 优先及 fork 权限边界；发布继续复用 CI 候选包，不另建编译缓存。此规则变更待下一轮 Actions 验证。
- Ubuntu guest 验证按当前架构读取 `prepared_vms` 中的冻结环境，继续复核索引摘要与实际包版本；不因模板上传成功便跳过应用安装和代理/TUN 验证。
- 字标右侧新增收起/展开侧栏按钮，保留页面及窗口重建后的手动选择；窄窗口继续自动使用图标栏。窗口拉伸直接重排，不再反复触发节点淡入、位移和侧栏宽度过渡；手动折叠保留轻量动效，尊重桌面系统减少动态效果设置。
- 代理和订阅页增加宫格/列表图标切换，桌面与移动端均放在顶部输入框左侧，图标随包离线提供；列表专为高密度浏览压缩，桌面代理列表只保留名称、延迟与详情，协议等元数据进入详情，桌面关闭并重开窗口后恢复各页的视图选择。
- 修复本地文件导入订阅没有编辑和删除入口的问题，文件路径或空来源均识别为本地，改名保留已保存的 YAML；桌面与移动端统一显示“本地／订阅”标签。各类订阅保持相同操作按钮，不可用项置灰，默认直连禁止更新、编辑和删除；“使用中”保留强调色且不能重复点击。
- 移动订阅页和节点页缩小操作按钮，常规字号下表面高度 40px，触控区域仍至少 48px，大字号随内容增高。
- 移动订阅卡片常显“使用／使用中”和“详情”，将更新、编辑与删除统一收进详情；列表压缩为单排操作，长名称优先省略，保留完整详情和不可用按钮的灰置状态。
- 修复移动订阅卡片首次显示及条数变化时的布局崩溃，宫格沿用桌面端的逐行排列，保留自适应列数、列表切换和详情操作。
- 几何测量仅在测试主动启用时执行；正式界面不注册无用的几何观察，避免 Android 首屏模式按钮构造时重入重复网格布局。补充 Android/iOS 原型全部页面的冷启动、字号与窗口尺寸回归；实际 Android 启动与代理/TUN 仍由同提交 CI 验收。
- 移动通知操作区按可用宽度排列按钮，保留诊断、Issue、恢复和关闭入口及窄屏、宽屏切换；这一预防性调整与订阅页已定位的崩溃分开验收。
- Android [应用分流](../android-application-routing.md)增加全部、仅代理选中与排除选中三种模式，以及带搜索、系统应用、图标和批量选择的独立页面；旧排除列表兼容迁移，保存后重连生效。通过系统包管理器核对并清理已卸载包名，避免部分系统的 VPN Builder 接受不存在的包名；空允许列表不会意外接管全部应用。Claude 保护期间覆盖为全部应用且锁定编辑，保留原选择。VPN 就绪检查不再要求本应用自身经过 VPN。按应用指定节点仍为后续能力，本轮不宣称支持。
- Android 构建按固定官方 SHA256 校验 Gradle 分发包，官方源暂时失败时可恢复私网已有原包；不再由 setup action 绕过该回退路径。原包清单在工具准备后提交，发布只重签已验证 APK，内存基准不安装 Gradle。
- 节点、IP 检测和首页网络/服务的响应时间统一用绿、黄、红强调，阈值分别为低于 300 ms、300–799 ms、800 ms 起；延迟与可用性分别表达，不把响应快误报为服务正常。
- 连接详情内“复制详情”“关闭连接”和“关闭”按钮统一宽高。
- 修复桌面订阅添加、编辑表单中的名称和链接输入框过窄，使用弹窗的可用正文宽度，长文本保留完整值。
- macOS 窗口状态上报与恢复复用 Slint 的最大化状态，避开无边框窗口的原生最大化查询触发样式切换；窗口仍须通过同提交的首次显示和重建可见性检查。
- README 标题使用与应用相同的几何路径字标，分别适配浅色和深色。
- 清理已完成重构的旧 HTML 设计稿，文档以正式 Slint 组件与预览为准。
- 正式版和预发布版的发布说明自动附上九种安装包下载徽章及各附件下载量；链接固定到本次版本。版本文案使用统一模板，历史文案归 Git 历史和 GitHub Releases 查阅。
- 候选包生成及基本代理/TUN 验收集中在同轮 CI，保留 Ubuntu latest 与 20.04 双架构兼容检查；完整源码、窗口、安装更新和生命周期专项改为按需运行，相关 Android 分流和 Linux 多用户改动自动追加专项。Publish Release 复用九组候选包，仅公开发布时重新签名并验证 Android 包；本轮测试范围调整尚待同提交 Actions 验证。

发布前以同提交 CI、九组安装包和实际运行的安装后验证结果验收；完整窗口、Windows 普通身份写入及更新回滚不再是常规 CI 项目，既有文件被外部权限锁定时仍须报告失败，不能全局放宽目录 ACL。跨用户结果依赖 root 能读取目标进程的 `/proc`；扫描预算、进程退出和隐藏进程仍可能产生 `partial`。路由采样不等于已经验证所有连接或所有 DNS 组合；长时间运行后的间歇 TLS 握手失败仍未定位首次触发原因。真实设备、长期 TUN、重启/休眠及人工授权交互不以静态预览代替。

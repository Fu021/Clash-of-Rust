# Clash of Rust 0.4.11

修复 Ubuntu 22.04 / 24.04 无法开启 TUN 的权限流程，并修正 Ubuntu 任务栏的应用图标识别。

## 更新内容

- Linux 开启 TUN 使用独立的原生授权助手，为安装目录内经过校验的 mihomo 配置 `CAP_NET_ADMIN` 与 `CAP_NET_RAW`，不再进入 Windows UAC 流程。
- 首次授权成功后自动重启内核并恢复运行模式与节点选择；取消授权保留原代理，重启失败尝试恢复原状态。桌面界面继续以普通用户运行。
- 启动恢复 TUN 检查内核的实际权限；后台自启缺少权限时提示打开客户端授权。更新替换内核后会重新检查权限。
- 明确提示 TUN 设备缺失、启动环境限制、授权取消和桌面授权服务不可用等问题。
- 窗口的 X11 / Wayland 应用标识与桌面启动文件统一为 `clash-of-rust`，Ubuntu 任务栏能匹配默认蓝色应用图标。
- 安装包表格改为直接下载链接。
- README 内存数据更新为 Ubuntu 24.04.5 LTS x86_64 上的 0.4.11 Release 实测，并附六次独立进程的原始记录。
- CI 在 Ubuntu 22.04 / 24.04 的 amd64、ARM64 环境增加普通用户 TUN 开启、无显式代理的流量接管、配置与内核重启恢复、代理互切和退出清理验证；在隔离网络环境执行。

Windows 运行对应架构的安装程序；Debian/Ubuntu 使用 `sudo apt install ./安装包文件名.deb`。每个安装包附带同名 `.sha256` 文件，升级保留订阅和个人设置。下载链接在对应 Release 发布附件后生效。

Linux TUN 需要 `/dev/net/tun`、`pkexec` 与可用的桌面授权服务。首次点击 TUN 完成管理员授权；升级替换内核后可能需要再次授权。容器或沙箱需允许 TUN 设备及网络能力。

支持自动更新的已安装客户端也可直接更新。Windows 自动安装需要 UAC 授权；Linux 需要桌面授权。

安装包由 GitHub CI 构建与测试，正式发布使用对应提交通过检查的 CI 产物。

可能造成 Windows Defender 误判查杀，需自行规避。

# Clash of Rust 0.4.13

本次更新增加节点排序和 IP 检测总结，优化内存占用，并修复配置保存与检测结果的一致性问题。

## 新增

- 代理组内支持延迟从低到高、从高到低和名称自然排序，自动保存排序偏好；未测速和失败节点排在有效延迟之后。
- IP 检测完成后，在原始结果上方显示总体与分类总结，包括出口 IP、地区和各类结果数量；支持分类、状态、地区与搜索组合筛选，点击统计数量可查看对应明细。
- 检测结果区分确认可用、部分可用、仅网页可达、信息识别、受限、未确认和请求失败；明细支持展开原因，取消检测后保留已完成结果和部分总结。

## 优化与修复

- API 快照共享重复文本、精简字段和延迟历史；代理页先搜索、排序再分页，每页最多四组、每组六十个节点，控制大订阅的界面内存。
- 平台检测减少响应正文和字符串的临时分配，并发检测复用 HTTP 客户端，Cookie 保持隔离，检测结束后释放共享客户端。
- 本地订阅读取前检查大小，并在读取过程中执行 10 MiB 上限，避免超大文件占用过多内存。
- 保存端口时合并最新设置，避免排队操作覆盖模式、测速间隔或当前订阅；配置与节点变化时取消旧检测，忽略过期结果。
- 订阅和模式变更使用配置事务，提交失败恢复原有文件与运行状态，进程中断后启动时恢复未完成事务。

## 开发与发布

- CI 负责四平台编译、测试和导出程序；手动发布工作流复用成功 CI 产物，完成打包及安装测试，支持只验证不发布。
- 统一内存基准支持 API 堆内存与 GUI/内核进程采样；手动工作流可测试指定提交，并生成实际界面预览。

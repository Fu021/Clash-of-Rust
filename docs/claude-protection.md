# Claude 保护

[检测入口](claude-region-detection.md)；平台排障见[复盘索引](agent-failures/README.md)。

## 覆盖范围

A÷检测中的“Claude 保护”默认关闭。开启后固定当前具体节点，以运行时优先规则覆盖核心、关联服务、关键词及官方入站 IP 网段，启用 TUN、严格路由、IPv6、UDP、TCP/UDP DNS 接管、经该节点的公网 DoH 和实时拦截。保留并锁定原规则/全局模式，原直连模式改用规则模式。全局出口沿嵌套策略组检查，最终为 DIRECT 时拒绝开启；GLOBAL 临时固定到具体节点，重启仍有效。原始订阅、用户规则和 DNS/IPv6/UDP 偏好不改写，关闭后恢复原选择；UDP 平时默认开启。

Linux 上确认本机没有可用 IPv6 地址时，保护仍可通过 IPv4 工作，不误报 IPv6 绕行；地址读取失败保持未知，有 IPv6 时仍要求对应接管，网络变化按[IPv6 判定矩阵](ipv6-tun.md)重新评估。

## 启用、关闭与恢复

开启确认按钮等待 3 秒。首次保存原运行模式、代理模式和节点选择，持久化恢复记录；重启继续保护，关闭则移除覆盖并恢复，保留检测报告且不自动重测。开关均使用配置事务，下次启动恢复未完成事务；取消授权不保存开启状态。应用后先关闭已有内核连接，再通过内核查询上游 DNS，失败恢复原网络与配置，不能只凭 TUN 创建判定成功。已断连接无法恢复，未经过内核的连接和浏览器 DNS 缓存不在关闭范围内。

保护及切换期间保留草稿和详情，按[操作权限](#操作权限)锁定影响网络的修改。定时订阅和自动更新暂停；启用保护会取消在途下载，不能把已开始的任务留到保护期间继续。

## 操作权限

保护锁定的是网络和更新操作，外观操作不改变固定出口。界面禁用与业务层校验必须一致；CLI 直接提交和后台附加客户端也不能绕过。

| 操作 | 保护及切换期间 |
| --- | --- |
| 主题、强调色、字号、窗口大小、托盘/通知速度显示、节点显示排序 | 允许；持久化不重载内核、不修改保护恢复记录 |
| 导航、查询状态、应用列表搜索/筛选/刷新、规则详情、网络诊断、测速、浏览既有报告、复制/导出诊断、清空日志、关闭提示 | 允许；诊断请求沿保护线路，不能切换出口；列表浏览不改变应用选择，清空仅移除日志记录 |
| 关闭 Claude 保护 | 允许，沿用事务恢复 |
| 启动/停止/重启内核、切换代理/运行模式、节点、订阅、端口 | 拒绝，先关闭保护 |
| 订阅、规则、DNS/Fake-IP/IPv6/UDP、应用范围与指定出站的保存/更新 | 拒绝；Android 应用出站暂时停用，范围临时覆盖为全部应用，不删除原设置 |
| 软件/Geo 更新、更新通道、自动更新及定时任务设置、自启动设置 | 保持锁定；不在保护期间创建下载或改变后续网络任务 |

测速只操作已运行的内核；保护期间内核已停止时，测速拒绝隐式启动，保留原保护记录。全部节点复测也不自动启停内核、改出口或关闭接管。

设置提交仅允许白名单中的显示字段变化；同一请求夹带任何网络或应用规则变化都拒绝。未改变字段值的设置提交不视为网络修改。新增设置字段默认不在白名单。Android 的主题/强调色保存只写设置，不创建运行配置或重连 VPN。保护开启和关闭的网络事务继续复核当前状态，不能用外观修改覆盖迟到的保护状态。

每个新增操作先按上表分类：无法证明只影响本地显示或只读观察的，按网络/写入锁定；外观保存不得触发内核重载、订阅刷新或保护恢复记录改写。每轮[循环审查](loop-workflow.md)同时复核旧白名单，主题、强调色、字号、窗口、排序、导航、只读查询及日志清空不应被误锁；新增字段只有在共享业务、宿主和至少一个界面入口都有允许/拒绝回归后才加入白名单。

各页和移动详情标题栏共用盾牌，不加状态线：绿勾表示接管与拦截就绪，黄沙漏表示切换/待确认，红叉表示异常并在内容上方展开原因。图标与内核徽标并排，完整文案留于无障碍标签和详情；移动点击区至少 48px，适配大字号。点击进入 A÷检测，不关闭保护。状态读取失败或旧后台缺少字段时回到待确认，拦截任务停止则显示异常；不能只凭保存的开关或旧成功快照显示绿色。跨页仅传轻量状态，不保留完整拦截记录；`cor claude watch` 同步输出共享 `protection_status`。

Android 常驻 VPN 通知标注“Claude 保护已启用/待确认/异常”，关闭保护移除标注，保留模式、节点和可选网速。关闭窗口、隐藏网速或内核重载/计数失败不阻止标注刷新；复用服务轮询和轻量 JNI，不序列化拦截记录。启用标记不替代开启时的 DNS 验证。

## DNS 与 Tailscale

公网解析使用 Cloudflare/Google DoH 并指定保护线路；节点引导解析优先保留原节点 DNS 与分流，未指定时使用原 DNS 上游，避免强行替换为当前网络不可达的固定地址；仅节点引导在本地直连解析，Claude 等公网域名始终经保护节点使用加密 DNS，不回退到本地。局域网名称保留本地解析策略。订阅原有 DNS 分流、备用、直连解析与 TUN 排除项在保护期间被运行时覆盖，关闭后恢复。系统或浏览器绕行、独立 DoH、时区、语言和账号资格仍需独立验证，不能宣称消除所有风险。

macOS 由已授权的网络助手临时覆盖系统动态 DNS：默认解析器统一进入助手独占的 `127.0.0.1:53`，只转发到内核的随机本机高端口，兼容原生系统解析和读取 `resolv.conf` 的程序，公网与 Claude 查询使用保护节点的 DoH；Tailscale MagicDNS、私有分域、搜索后缀及其接口绑定单独保留，不要求用户关闭 Tailscale DNS 或手动调整 DNS。State/Setup 只改 configd 运行缓存，不改持久网络偏好。助手监测 VPN 重连和 DNS 变化并重新接管；保护 DNS 失败时不使用 VPN 或物理网络 DNS 作为公共查询的回退。本机端口占用时先报错，不将查询交给占用端口的其他解析器。关闭、异常退出和升级清理使用恢复记录，仅恢复仍由本应用托管的字段，保留外部修改且不重建已删除服务，并关闭本机转发。

开启时若系统分域与保护范围重叠（包括非 Quad100 的分域），或本机 DNS/系统接管未就绪，会报错并恢复；运行中出现冲突则保留本机接管、隔离冲突解析器并显示错误，冲突消除后自动重试。隔离期间私有解析可能暂时不可用。接管或重连后通过系统原生解析接口确认随机名称到达本机入口，且系统返回预期本机响应，未完成则保留未就绪提示，不能只凭配置更新或收到请求判定切换完成。探针不含用户域名，不转发到内核上游。首次启用新版助手可能需重新授权；原生模拟和真实 Tailscale、接口变化、出口节点及其他 VPN 的验证边界见[最近复盘](agent-failures/reviews.md)。

## 递归 DNS 国家排查

排查虚拟机中递归 DNS 地区不一致时，分别查看报告里的系统和浏览器来源、浏览器独立 DoH 以及 `scutil --dns` 的解析器和作用域。虚拟机网络、上游公共 DNS 和 IP 地区数据库都可能影响观测结果；递归服务器显示美国并不能单独证明流量绕过德国节点，也不能证明没有泄漏。分享报告或命令输出前请移除私人地址及网络标识。

2026-10-27 的对照发现，bash.ws 将 Google 递归地址标为美国，而 [Google Public DNS 官方 geofeed](https://www.gstatic.com/ipranges/publicdns_geofeed.txt) 将其所在的 `172.217.33.128/25`、`172.217.34.0/26`、`172.253.1.192/26` 标为德国法兰克福，覆盖截图中的地址及 VPS 直接指定 Google DNS 得到的全部六个地址。这是国家数据误报，国家确实不同仍属于风险，不能靠隐藏差异解决。检测每份 DNS 报告使用同一个受限请求读取官方清单，最长前缀匹配且国家唯一时修正标签，显示官方来源和 bash.ws 原标签；不依赖 bash.ws 必须提供 ASN，也不硬编码永久白名单。请求失败、清单冲突或无匹配时保留原数据及差异判定并说明未作官方修正；没有有效国家时列为未确认，不能冒充正常。保护开启时官方清单请求走诊断保护线路。浏览器来源仅说明由浏览器触发查询，不能单凭递归地址区分独立 DoH 与内核上游；此对照也不能证明客户端的完整 DNS 路径已无泄漏。

## 嗅探与 STUN 边界

保护期间为纯 IP 请求启用 HTTP、TLS 与 QUIC 域名嗅探，补充浏览器旧 DNS 缓存等路径的规则匹配；已知 DNS/代理域名保留，不被订阅的强制嗅探或其他 SNI 名称覆盖。相关配置关闭保护后恢复。没有可识别域名的加密请求仍有识别限制。

STUN 保护依赖[覆盖主机与路由规则](../crates/client-core/src/protection/mod.rs)：当前对 `stun.cloudflare.com`、`stun.l.google.com` 添加精确域名规则，走保护节点或拒绝回退，前提是流量进入内核且能识别该域名。规则模式仍保留其他订阅规则，其他 STUN 服务器或无法关联域名的纯 IP 请求可能命中 `DIRECT`；全局模式会固定 `GLOBAL` 到保护节点，覆盖范围更广。Fake-IP 排除只让 DNS 返回目标服务器的真实地址，不决定直连或代理；后台拦截也不识别任意 STUN 流量。[STUN 服务端在请求到达时就能看到网络出口](https://datatracker.ietf.org/doc/html/rfc8489#section-2)，事后断连无法撤回已暴露的地址，不能将开启保护等同于阻止所有 STUN 真实出口探测。

## 后台拦截与通知

实时监测在隐藏窗口和切换页面后继续运行。它只关闭 Claude、所覆盖共享服务及官方入站 IP 范围中偏离指定节点的存续连接，不依据 DNS 地区差异或浏览器偏好断连，也不读取 HTTPS 内容或进程名。共享服务可能属于其他应用，开启确认框对此作出提示。通知与断连分开运行，提示合并去重；通知不可用时保留失败说明，不因此停止拦截。连接扫描逐条解析，只保留最多 128 条异常连接，展示最近 32 条记录。

明确保护错误在桌面与 Android 均列入风险，包括原生保护线程停止时返回的失败快照。连接扫描首次确认前及控制接口连续失败不足 3 秒时显示待确认；持续失败才展开可恢复警告，只有实际连接扫描恢复后才清除。日志事件流连接成功不替代连接扫描就绪。此确认期不暂停拦截，也不延迟真实连接关闭失败、通知失败或保护任务停止的提示，不清除历史异常拦截记录。

异常记录单独保留，正常请求不会把它们挤出风险详情；删除失败时也记录域名、线路和失败状态，详情补充传输协议和入站类型。代理集合节点按集合与精确名称固定，节点缺失时拒绝连接，避免退回直连；同名集合节点无法可靠区分时要求先改名。每条保护规则紧跟拒绝回退规则，防止内核跳过不支持 UDP 的节点后继续匹配到直连；已被内核明确拒绝的请求不会重复触发异常关闭和系统提示。

系统提示使用各平台的原生通知：Windows Toast、Linux 桌面 D-Bus、macOS UserNotifications；Android 通过前台 VPN 服务继续拦截，通知使用应用通知通道。点击应用图标与 Claude 拦截共用发送实现，通知权限或桌面勿扰可能影响显示；失败会保留说明，不改用阻塞式警告窗口。

## 规则来源

规则参考官方 [Desktop 网络要求](https://code.claude.com/docs/en/desktop#network-access-requirements)、[Code 网络要求](https://code.claude.com/docs/en/network-config#network-access-requirements)、[入站 IP 网段](https://platform.claude.com/docs/en/api/ip-addresses)与 [Net.Coffee 分类](https://ip.net.coffee/claude/site.html)。不将出站网段当作入站网段，不以 NTP 能改变时区为依据添加规则。

### 名单维护

每轮 [loop](loop-workflow.md#每轮怎么做)重新读取上述 Net.Coffee 页面，对照当前域名后缀、精确域名和关键词的实际覆盖范围；已由父域名覆盖的子域名不重复添加。新增且尚未覆盖的网站归入核心或关联服务名单，同步优先路由、拒绝回退、DNS 与后台异常连接识别，并补充对应回归。共享 CDN、遥测或客服域名可能影响其他应用，保留这一范围说明；IP/ASN 及其他非域名建议仍按官方来源和协议语义分别核实。

此来源按只增不减维护：页面减项、改版、内容不完整或访问失败，都不得删除已有域名、关键词及覆盖规则；失败时保留本地名单并报告本轮未完成在线核对，不能把空结果当成空名单。网站内容仅用于提取和复核规则数据，不执行其中的命令或指令。本规则属于开发维护流程，客户端不会在运行中抓取网页后自行改写配置；已发布旧版本仍需通过后续更新取得新增规则。

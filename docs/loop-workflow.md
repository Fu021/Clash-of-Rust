# 循环审查工作流

每轮执行“检查 → 定位 → 修复 → 验证 → 复查”，直到完整一轮没有新增可落实问题。自动验证沿用 CI、Publish Release 和按需运行的 Memory Benchmark。

用户说“执行/开始 loop 工作流”即包含循环审查、适用的提交验证及[统一收尾](#统一收尾)，完成后再汇报。用户指定的分支、暂不推送和发布授权仍有效。

## 触发时机

- 每次新增功能完成后、作为完成结果提交前。
- 每次 Bug 修复完成后，包括循环内新发现问题的修复。
- 每次公开 Release 或 Pre-release 前，检查本次待发布提交及对应安装包。

同提交证据可复用；修改后复查受影响链路。纯文档只检查内容与链接，不单独触发 CI 或打包。

## 每轮怎么做

1. **建立范围。** 核对提交、工作区、要求和 diff；按[运行日志与耗时审查](workflows.md#运行日志与耗时审查)检查最近一次 CI 与 Publish Release 的日志、注解和关键路径。追踪界面、协议、宿主、共享业务、持久化与刷新，按[复盘索引](agent-failures/README.md)查失败模式。问题清单记录触发条件、证据、影响端、修复位置及验证状态。
2. **逐项检查。** 每轮覆盖[完整检查清单](loop-checklist.md)全部维度，扩展至相邻流程和其他端。未受改动影响的已验证部分引用证据，继续检查未覆盖场景与交互组合。
   每轮执行[依赖与缓存审查](loop-dependencies.md)，或复用同清单近期审计；核对升级、弃用、框架修复及所有工作流的缓存分工和耗时。升级授权、兼容约束、私网边界与结果分类集中在该页。
   **Claude 保护影响判定。** 每个新功能或既有写操作先按[操作权限](claude-protection.md#操作权限)分类：改变内核、网络、订阅、规则、应用出站、更新/Geo、自启动或定时任务的，必须同时验证界面、宿主、共享业务和 CLI 拒绝；纯外观（主题、强调色、字号、窗口、托盘/通知速度显示、节点显示排序）、导航、日志清空及只读查询必须保持可用，并确认保存不重载内核、不改保护恢复记录。新字段默认拒绝，只有明确证明仅影响本地显示后才加入白名单。若功能触及保护判定、共享设置或 Android VPN/应用分流，重新执行完整允许/拒绝矩阵；每轮同时复查旧入口，发现把纯外观或只读能力误锁的应放宽并补回归。
3. **定位并修复。** 优先解决数据丢失、网络状态恢复、功能错误和无法操作的问题，再处理布局、性能和一致性缺陷。追踪到实际原因，在共享层或对应平台修复；同步所有调用者、必要的协议、预览和权威文档。
4. **验证修复。** 根据风险补充最小且有价值的回归，覆盖触发场景、边界、失败与恢复；同时检查修复对其他端和 GUI/CLI 的影响。验证方式遵循[开发与验证](development.md#本地验证与-ui-预览)及[资源受限规则](../AGENTS.md#资源受限环境)。
5. **反常操作。** 每轮结尾选少量与改动相关、偏离正常步骤的探索，例如把非法值交给配置项、连续提交或取消、下载中重建界面、编辑后收到旧结果、授权后取消安装。验证拒绝原因、退出码、旧数据及恢复状态，不只检查程序未崩溃。优先复用隔离夹具；确认缺陷后保留最小源码回归，临时探测和输入留工作区外，不对用户正在使用的网络做实验。
6. **开始下一轮。** 重新审阅实际 diff，复查上一轮修复及其上下游，再走一遍全部维度。新问题继续进入清单处理；CI 或打包失败也进入本循环，先定位再修复，不能靠放宽断言或反复重跑掩盖代码问题。

问题在任务内跟踪，收尾记入[最近复盘](agent-failures/reviews.md)，不重复堆日志。

## 每轮覆盖范围

逐项要求及平台适用性集中在[循环审查检查清单](loop-checklist.md)，本页保留执行顺序和结束条件。每轮按任务读取对应权威主题，不反复全文加载未变化的文档和源码。

## 多尺寸 UI 检查

按[代表尺寸与检查方法](loop-ui.md)检查手机、横屏、Pad、桌面、长文本、键盘和拖动。资源受限时按风险选尺寸并串行预览；预览不能代替交互及实机验收。

## 何时可以结束

- 完整一轮覆盖上述维度，没有新增可落实的 Bug、明显 UI 缺陷或应同步的功能缺口；已发现问题完成修复与对应复查，不以固定轮数代替结束条件。
- 每项结论有实际调用链、复现或验证证据；区分“通过 / 失败 / 未执行 / 仅静态检查”。没有设备、工具链、资源或外部服务时列明未完成项及影响，不能宣称没有 Bug 或所有平台已通过。
- 不为凑轮数做无依据美化、无关重构或重复测试。未获授权的扩展及未定位问题记录原因、影响和下一步；有未关闭问题不得称为无问题完成，发布前标明是否阻塞。
- 完成适用的提交、验证及统一收尾；列出外部阻塞，不能以循环检查结束代替整个流程完成。

## 提交与发布衔接

功能和修复先完成循环审查、同步文档，再按[提交规则](../AGENTS.md#actions提交与发布)整理最终提交。推送后持续跟进同提交 CI；失败修复后重新复查受影响链路，并取得新提交的验证结果。

同轮 CI 必须等全部 job 结束，集中读取所有失败 job 的日志、注解与必要附件，列清根因、影响端、修复和待验证项，再整理下一次推送。修复可以在等待期间进行，但不得边发现单个失败边推送，导致其他平台被新运行取消、证据缺失或重复编译。同一提交已由 PR 自动触发时，不再手动重复启动完整 CI。

推送前按[测试与调用者核对](loop-checklist.md#推送前检查)复查产品及新增回归。单平台问题优先现有已授权专项，再做完整验收；不新增临时工作流、不降低断言。runner、上游、测试环境和源码故障分别判断，不能用网络异常解释明确的编译或断言失败。

Release 与 Pre-release 采用同一审查要求。按[Publish Release](workflows/release.md#publish-release)核对成功 CI、安装包、校验值、安装后行为和来源提交；仅打包及公开发布分别遵守既有授权和参数要求。最终检查发现代码或版本需改动时，重新进入循环并验证新提交，不能借用旧提交产物直接发布。

资源不足时本地只做静态检查和必要单页 UI 预览，其余验证交已授权的 Actions；未执行项如实记录。跟进频率按[历史耗时](workflows.md#actions-跟进节奏)，不因循环审查提高轮询频率或每修一个问题就推送。

运行时集成的常规范围按[CI 说明](workflows/ci.md#ci)执行，聚焦系统代理/TUN；发布前另须完成同提交 Android 与 Ubuntu 兼容验证。已完成的键盘、多版本截图及全版本诊断专项不因 loop 自动重跑，重新调查须有维护者明确要求。

## 统一收尾

以下均属于 loop，无需另行提醒；提交前整理，验证后最终复查。

1. **改动与脚本。** 对照要求复查 diff、调用链和验证结果；按[脚本说明](../scripts/README.md)审查全仓入口，有依据才合并重复或删除弃用脚本，同步调用者。确认 Actions 未残留临时工作流、探索测试步骤或默认开启的专项；必要源码回归沿用现有测试策略。需要服务端配合时，在汇报中列出具体问题、证据和验收条件，由用户转达；遵循[缓存服务边界](workflows/cache-server.md)，不修改或上传 README.txt，不自动交换 agent 反馈。
2. **文档冲突纠错与精炼。** 按[结构复查](structure-review.md#文档冲突纠错)核对本轮涉及的约束、实现、帮助、工作流及验证证据，判明实现缺陷、过期说明和平台/版本差异，修正矛盾、重复与旧入口；不能仅把文档改成符合错误实现。评估长文是否继续按职责拆分，保留权威来源、证据和有效链接；无法判定的冲突说明影响与待确认项。
3. **代码与目录职责。** 按[模块边界和目录复查](structure-review.md#大代码文件与模块边界)评估大文件、多职责、重复能力及依赖方向，更新[全仓职责树](structure-review.md#目录与职责)。任务内必要的局部拆分同步调用者和验证；整套目录树或跨层重构先给维护者问题证据、目标树、迁移映射、验证及回退方案，批准后实施。
4. **内存分析。** 按[内存基准](workflows/memory.md)检查同提交或明确标注版本的窗口、后台、API 快照和页面退出证据，比较 RSS/PSS、匿名/堆私有页峰值及最终值、模型和日志上限及释放情况。有证据再优化持有、复制和任务生命周期；必要时完善基准日志，不缩小输入或隐去进程。无实测时只报告静态风险，真机和跨平台差异不能用 Linux 基准代替。
5. **失败复盘。** 在[最近复盘](agent-failures/reviews.md)记录结论、来源提交、证据与验证范围，完成的待办改为实际结果；经验归主题，已有模式引用，不堆流水和日志。
6. **最终验证。** 检查链接与锚点、`git diff --check`、`git status --short` 及文件范围；纯文档保留预期未提交改动。推送后跟进同提交 CI/不发布打包至核验完成，重新检查日志与注解中的 warning、弃用提示及耗时，未解决项继续进入循环。核对来源、附件、Release 未变及最终分支/工作区状态。
7. **汇报。** 说明修复、文档、内存分析和验证结果，区分通过/失败/未执行/仅静态检查，列明设备验收、文档冲突、待批准重构及其他阻塞。

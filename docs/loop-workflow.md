# 循环审查工作流

每轮执行“检查 → 定位 → 修复 → 验证 → 复查”，持续覆盖软件各方面，直到完整一轮没有发现新的、可落实的问题。流程按本文执行，自动验证沿用现有 CI、Publish Release 和按需运行的 Memory Benchmark。

## 触发时机

- 每次新增功能完成后、作为完成结果提交前。
- 每次 Bug 修复完成后，包括循环内新发现问题的修复。
- 每次公开 Release 或 Pre-release 前，检查本次待发布提交及对应安装包。

同一提交的审查证据可复用；后续修改必须复查受影响链路及跨端一致性。发布前再核对完整覆盖范围、遗留项和产物身份，不能仅以之前某轮通过代替本次检查。纯文档任务只检查内容、链接和流程一致性，不为执行循环单独触发编译、CI 或打包。

## 每轮怎么做

1. **建立范围。** 核对当前提交、工作区、用户要求和实际 diff；沿调用者追踪界面、协议、宿主、共享业务、持久化与刷新，按[复盘索引](agent-failures/README.md)查相关失败模式。维护简短问题清单，记录触发条件、证据、影响端、修复位置及验证状态。
2. **逐项检查。** 每轮覆盖下表全部维度，从本次改动向相邻流程和其他端扩展。已经验证且未受新改动影响的部分引用已有证据，把精力用于尚未覆盖的场景和交互组合。
3. **定位并修复。** 优先解决数据丢失、网络状态恢复、功能错误和无法操作的问题，再处理布局、性能和一致性缺陷。追踪到实际原因，在共享层或对应平台修复；同步所有调用者、必要的协议、预览和权威文档。
4. **验证修复。** 根据风险补充最小且有价值的回归，覆盖触发场景、边界、失败与恢复；同时检查修复对其他端和 GUI/CLI 的影响。验证方式遵循[开发与验证](development.md#本地验证与-ui-预览)及[资源受限规则](../AGENTS.md#资源受限环境)。
5. **开始下一轮。** 重新审阅实际 diff，复查上一轮修复及其上下游，再走一遍全部维度。新问题继续进入清单处理；CI 或打包失败也进入本循环，先定位再修复，不能靠放宽断言或反复重跑掩盖代码问题。

每轮发现与修复在任务内简要跟踪，收尾再汇总到[最近复盘](agent-failures/reviews.md)，不为每一轮堆积永久文档或重复日志。

## 每轮覆盖范围

| 维度 | 必查内容 |
| --- | --- |
| 功能与数据 | 订阅添加、导入、编辑、更新、切换及删除当前订阅；规则表单、启停、排序、筛选、分页与应用草稿；Fake-IP 来源、排除及还原；节点选择、测速、连接、日志、诊断、IP 与 A÷检测。检查输入校验、重复操作、空数据、大列表、取消、重试、退出及重启恢复。 |
| 下载与网络 | 订阅、Geo、客户端更新分别追踪真实下载入口，检查代理/直连、实际出站、DNS/IPv6、重定向、超时、慢速和断流处理、校验及临时文件清理。速度结论来自对应下载证据；下载或重载失败保留旧数据和可用网络状态，避免边下载边破坏活动文件。 |
| UI 与交互 | 按下文代表性尺寸检查桌面、手机横竖屏和 Pad，兼顾字号及主题；以内容可见、控件可达为准，检查顶部与底部裁切、遮挡、列表重叠、宽度、滚动、长文本、来源与原文、键盘和安全区。分页、应用/放弃、拖动和边缘滚动应可用，操作区紧凑且容易辨认；检查加载、禁用、进度、错误及成功反馈。 |
| `cor` 命令行 | 逐项核对[命令文档](cli.md)、参数、帮助、默认值、退出码、标准输出/错误输出及结构化结果；检查无显示环境、后台启动/重新附加、取消、失败提示、配置和规则操作，避免命令假成功、遗漏入口或意外启动额外 GUI/内核。 |
| 桌面与移动同步 | 对照用户可见入口、实际业务调用、校验、持久化、反馈和失败恢复，防止共享代码已有而某端无法使用。检查 Windows、Linux、macOS 与 Android 的适用能力，手机与 Pad 同时核对；平台差异写明原因和替代入口。 |
| GUI 与 CLI 同步 | 适用于两种入口的功能应采用相同业务语义、默认值、校验和结果。检查 GUI 修改后 `cor` 查询及操作是否一致、CLI 修改后已打开窗口是否刷新；保留未保存草稿，共享数据目录、后台所有者和内核，避免重复任务与旧状态覆盖。 |
| 平台与生命周期 | Android VPN、套接字保护、通知、磁贴、Activity 重建及后台运行；桌面托盘、窗口关闭/重建、服务、授权、自启动、代理/TUN/DNS 切换和恢复。检查授权拒绝、迟到回调、连续点击、进程退出及重启。 |
| 性能与资源 | 检查 UI 线程、运行时 worker 和引擎锁是否被网络或同步磁盘操作阻塞；下载缓冲、轮询、模型复用、后台任务取消、内存/日志/缓存上限及关闭窗口后的资源释放。性能结论注明环境、版本、输入与方法。 |
| 可靠性与发布 | 检查本机控制器认证、敏感信息脱敏、文件及配置事务、协议兼容、版本迁移、依赖与资源身份、脚本调用关系；核对安装、升级、卸载、签名、架构、更新通道、说明文档及安装后行为。 |

功能同步按平台适用性落实：Android 使用系统 VPN 和移动授权，不扫描 Claude Desktop/CLI，也不增加桌面 `cor` 宿主；iOS 当前为宿主占位，只检查共享接口与原型一致性，不标记为可用客户端或已完成实机验证。界面专属操作和平台专属能力保留合理差异，说明依据；确认的共用能力缺口应补齐。

## 多尺寸 UI 检查

使用逻辑视口尺寸，不能把手机的物理分辨率直接当作布局宽度。依据改动选择小屏、常规屏、大屏及平板的代表尺寸，先查受影响页面，再查共用控件的调用页面：

| 场景 | 代表逻辑尺寸 |
| --- | --- |
| 小屏与窄屏手机 | `320×568`、`360×800` |
| 常规与大屏手机 | `393×852`、`412×915` |
| 手机横屏 | `800×360` |
| Pad 竖屏与横屏 | `800×1280`、`1280×800` |
| 桌面最小窗口与常规窗口 | `800×450`、`950×700` |

每种布局检查顶部、滚动后的列表中部和末尾；覆盖长文本、空结果及大字号（如 `1.3` 倍），确认来源、详情与关键操作仍可见。检查键盘弹出/收起、列表条数变化及空结果后能否继续输入，不能重建搜索框而丢失焦点；键盘展开时还要有结果显示空间，不能只按整页高度判断是否固定尾栏。规则页顶部筛选/快捷规则应随列表滚走，不能持续遮住规则；桌面拖动、移动长按拖动都检查规则浮起跟随、原位占位、目标反馈、双向边缘自动滚动、中心停滚、松手和取消；源行滚出视口后预览仍应跟随，不能被回收或随内容漂走。矮横屏和大字号允许尾部操作随内容滚动，以保证所有控件可达。

资源受限时串行预览本次相关页面的一种主题，按风险选择尺寸，不生成全量页面/主题/对话框组合；输出放在工作区外并清理。预览只证明静态外观，手势、键盘与运行时行为由现有 CI 的交互回归验证，系统字体、安全区与实际触感仍需设备验收。记录查过的尺寸与未覆盖项，不把截图视为全部机型通过。

## 何时可以结束

- 完整一轮覆盖上述维度，没有新增可落实的 Bug、明显 UI 缺陷或应同步的功能缺口；已发现问题完成修复与对应复查，不以固定轮数代替结束条件。
- 每项结论有实际调用链、复现或验证证据；区分“通过 / 失败 / 未执行 / 仅静态检查”。没有设备、工具链、资源或外部服务时列明未完成项及影响，不能宣称没有 Bug 或所有平台已通过。
- 不为增加轮数做无依据的美化、无关重构或重复测试。超出用户授权的功能扩展及尚不能定位的问题记录原因、影响和下一步；存在未关闭问题时不得称为无问题完成，发布前明确其是否阻塞发布。

## 提交与发布衔接

功能和修复先完成循环审查、同步文档，再按[提交规则](../AGENTS.md#actions提交与发布)整理最终提交。推送后持续跟进同提交 CI；失败修复后重新复查受影响链路，并取得新提交的验证结果。

Release 与 Pre-release 采用同一审查要求。按[Publish Release](workflows.md#publish-release)核对成功 CI、安装包、校验值、安装后行为和来源提交；仅打包及公开发布分别遵守既有授权和参数要求。最终检查发现代码或版本需改动时，重新进入循环并验证新提交，不能借用旧提交产物直接发布。

资源不足时本地只做静态检查和必要单页 UI 预览，其余验证交已授权的 Actions；未执行项如实记录。跟进频率按[历史耗时](workflows.md#actions-跟进节奏)，不因循环审查提高轮询频率或每修一个问题就推送。完成后精简复盘、检查 diff 和工作区，清理本次临时产物；纯文档补充保留本地，随下一次功能更新提交与推送。

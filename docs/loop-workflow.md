# 循环审查工作流

每轮执行“检查 → 定位 → 修复 → 验证 → 复查”，直到完整一轮没有新增可落实问题。自动验证沿用 CI、Publish Release 和按需运行的 Memory Benchmark。

用户说“执行/开始 loop 工作流”即包含循环审查、适用的提交验证及[统一收尾](#统一收尾)，完成后再汇报。用户指定的分支、暂不推送和发布授权仍有效。

## 触发时机

- 每次新增功能完成后、作为完成结果提交前。
- 每次 Bug 修复完成后，包括循环内新发现问题的修复。
- 每次公开 Release 或 Pre-release 前，检查本次待发布提交及对应安装包。

同提交证据可复用，修改后复查受影响链路及跨端一致性。发布前核对覆盖、遗留项和产物身份。纯文档只检查内容、链接及流程，不单独触发编译、CI 或打包。

## 每轮怎么做

1. **建立范围。** 核对提交、工作区、要求和 diff；追踪界面、协议、宿主、共享业务、持久化与刷新，按[复盘索引](agent-failures/README.md)查失败模式。问题清单记录触发条件、证据、影响端、修复位置及验证状态。
2. **逐项检查。** 每轮覆盖下表全部维度，扩展至相邻流程和其他端。未受改动影响的已验证部分引用证据，继续检查未覆盖场景与交互组合。
3. **定位并修复。** 优先解决数据丢失、网络状态恢复、功能错误和无法操作的问题，再处理布局、性能和一致性缺陷。追踪到实际原因，在共享层或对应平台修复；同步所有调用者、必要的协议、预览和权威文档。
4. **验证修复。** 根据风险补充最小且有价值的回归，覆盖触发场景、边界、失败与恢复；同时检查修复对其他端和 GUI/CLI 的影响。验证方式遵循[开发与验证](development.md#本地验证与-ui-预览)及[资源受限规则](../AGENTS.md#资源受限环境)。
5. **开始下一轮。** 重新审阅实际 diff，复查上一轮修复及其上下游，再走一遍全部维度。新问题继续进入清单处理；CI 或打包失败也进入本循环，先定位再修复，不能靠放宽断言或反复重跑掩盖代码问题。

问题在任务内跟踪，收尾汇总到[最近复盘](agent-failures/reviews.md)，不重复堆日志。

## 每轮覆盖范围

| 维度 | 必查内容 |
| --- | --- |
| 功能与数据 | 订阅添加、导入、编辑、更新、切换及删除当前订阅；规则表单、启停、排序、筛选、分页与应用草稿；Fake-IP 来源、排除及还原；节点、测速、连接、日志、诊断、IP 与 A÷检测。覆盖校验、重复操作、空数据、大列表、取消、重试、退出及重启。 |
| 下载与网络 | 追踪订阅、Geo、客户端更新入口，检查代理/直连、实际出站、DNS/IPv6、重定向、超时、慢速、断流、校验及临时文件清理。速度结论须有对应证据；下载或重载失败保留旧数据和可用网络，不破坏活动文件。 |
| UI 与交互 | 按下文尺寸检查桌面、手机横竖屏和 Pad，兼顾字号及主题。检查裁切、遮挡、列表重叠、宽度、滚动、长文本、来源/原文、键盘及安全区；分页、应用/放弃、拖动与边缘滚动须可达且清楚。覆盖加载、禁用、进度、错误及成功反馈。 |
| `cor` 命令行 | 核对[命令文档](cli.md)、参数、帮助、默认值、退出码、标准输出/错误及结构化结果；覆盖无显示环境、后台启动/重新附加、取消、失败、配置和规则操作。Linux 检查普通用户、sudo、直接 root 与指定用户的环境、目录、文件/后台归属、跨用户只读总览和隔离，防止假成功、遗漏入口或额外 GUI/内核。 |
| 桌面与移动同步 | 双向盘点 Windows、Linux、macOS、Android 手机及 Pad 已有功能与便利交互，不只核对本轮改动；逐项判断能否推广到其他端，例如进入代理页时当前策略组置顶并展开。对照入口、业务、校验、持久化、反馈和失败恢复，补齐适用能力；保留差异须写明平台理由和替代入口。 |
| GUI 与 CLI 同步 | 共用功能保持业务语义、默认值、校验和结果一致。核对 GUI 修改后的 `cor` 查询/操作及 CLI 修改后的窗口刷新；保留草稿，共享数据目录、后台所有者与内核，防止重复任务和旧状态覆盖。 |
| 平台与生命周期 | Android VPN、套接字保护、通知、磁贴、Activity 重建及后台；桌面托盘、窗口关闭/重建、服务、授权、自启动、代理/TUN/DNS 切换恢复。覆盖拒绝授权、迟到回调、连续点击、退出及重启；按[平台矩阵](workflows/release.md#publish-release)检查不同系统、发行版和架构，避免重复已有回归。 |
| 性能与资源 | 网络/同步磁盘操作是否阻塞 UI、worker 或引擎锁；下载缓冲、轮询、模型复用、任务取消、内存/日志/缓存上限及关窗后的资源释放。性能结论注明环境、版本、输入和方法。 |
| 可靠性与发布 | 控制器本机认证、脱敏、文件/配置事务、协议兼容、版本迁移、依赖/资源身份、脚本调用；安装、升级、卸载、签名、架构、更新通道、文档及安装后行为。 |

按平台适用性同步：Android 使用系统 VPN/移动授权，不扫描 Claude Desktop/CLI，不增加桌面 `cor` 宿主；iOS 仍为宿主占位，只检查共享接口与原型，不标记为可用或实机通过。说明界面/平台专属差异，补齐共用能力缺口。

## 多尺寸 UI 检查

使用逻辑视口尺寸，不能把手机的物理分辨率直接当作布局宽度。依据改动选择小屏、常规屏、大屏及平板的代表尺寸，先查受影响页面，再查共用控件的调用页面：

| 场景 | 代表逻辑尺寸 |
| --- | --- |
| 小屏与窄屏手机 | `320×568`、`360×800` |
| 常规与大屏手机 | `393×852`、`412×915` |
| 手机横屏 | `800×360` |
| Pad 竖屏与横屏 | `800×1280`、`1280×800` |
| 桌面最小窗口与常规窗口 | `800×450`、`950×700` |

每种布局检查顶部、列表中部及末尾，覆盖长文本、空结果和大字号（如 `1.3` 倍），确保来源、详情、操作可见。键盘弹出/收起、条数变化及空结果后仍能输入，不重建搜索框丢失焦点；键盘展开须留结果空间，不能只按整页高度固定尾栏。规则页筛选/快捷规则随列表滚走。桌面拖动、移动长按拖动均检查浮起跟随、原位占位、目标反馈、双向边缘滚动、中心停滚、松手及取消；源行回收后预览仍跟随，不随内容漂移。矮横屏/大字号允许尾部操作随内容滚动，保证控件可达。

资源受限时按风险选择尺寸，串行预览相关页面的一种主题；输出放在工作区外并清理。预览只证明静态外观；CI 验证手势、键盘与运行时，字体、安全区及触感仍需设备验收。记录尺寸与未覆盖项。

## 何时可以结束

- 完整一轮覆盖上述维度，没有新增可落实的 Bug、明显 UI 缺陷或应同步的功能缺口；已发现问题完成修复与对应复查，不以固定轮数代替结束条件。
- 每项结论有实际调用链、复现或验证证据；区分“通过 / 失败 / 未执行 / 仅静态检查”。没有设备、工具链、资源或外部服务时列明未完成项及影响，不能宣称没有 Bug 或所有平台已通过。
- 不为凑轮数做无依据美化、无关重构或重复测试。未获授权的扩展及未定位问题记录原因、影响和下一步；有未关闭问题不得称为无问题完成，发布前标明是否阻塞。
- 完成适用的提交、验证及统一收尾；列出外部阻塞，不能以循环检查结束代替整个流程完成。

## 提交与发布衔接

功能和修复先完成循环审查、同步文档，再按[提交规则](../AGENTS.md#actions提交与发布)整理最终提交。推送后持续跟进同提交 CI；失败修复后重新复查受影响链路，并取得新提交的验证结果。

Release 与 Pre-release 采用同一审查要求。按[Publish Release](workflows/release.md#publish-release)核对成功 CI、安装包、校验值、安装后行为和来源提交；仅打包及公开发布分别遵守既有授权和参数要求。最终检查发现代码或版本需改动时，重新进入循环并验证新提交，不能借用旧提交产物直接发布。

资源不足时本地只做静态检查和必要单页 UI 预览，其余验证交已授权的 Actions；未执行项如实记录。跟进频率按[历史耗时](workflows.md#actions-跟进节奏)，不因循环审查提高轮询频率或每修一个问题就推送。

## 统一收尾

以下均属于 loop，无需另行提醒；提交前整理，验证后最终复查。

1. **改动与脚本。** 对照要求复查 diff、调用链和验证结果；按[脚本说明](../scripts/README.md)审查全仓入口，有依据才合并重复或删除弃用脚本，同步调用者。
2. **文档精简与更新。** 按实际行为、命令、版本和流程修正过时内容，合并重复，长文按任务拆分并更新入口/链接/锚点。遵循[长度与上下文约束](../AGENTS.md#文档与上下文)，保留一处权威说明及必要命令、证据、许可证。
3. **失败复盘。** 在[最近复盘](agent-failures/reviews.md)记录结论、来源提交、证据与验证范围，完成的待办改为实际结果；经验归主题，已有模式引用，不堆流水和日志。
4. **仓库清洁。** 检查生成目录，清除本次预览、日志、缓存、构建产物和临时文件；保留用户文件、未合并分支、必需资源及许可证。分支仅按[合并规则](../AGENTS.md#actions提交与发布)清理。
5. **最终验证与汇报。** 检查链接、`git diff --check`、`git status --short` 及文件范围；纯文档保留预期未提交改动。推送后跟进同提交 CI/不发布打包至核验完成，核对来源、附件、Release 未变及最终分支/工作区状态。汇报修复、文档、清洁和验证结果，区分通过/失败/未执行/仅静态检查，列明设备验收与阻塞。

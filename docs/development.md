# 开发与验证

按本次改动阅读职责、数据流、平台或验证的相关章节；跨任务约束与收尾流程见 [AGENTS](../AGENTS.md)。功能和修复的循环检查按[循环审查工作流](loop-workflow.md)执行。

## 目录与职责

| 目录 | 职责 |
| --- | --- |
| `crates/client-core` | 共享配置、存储、订阅、规则、控制器、DNS 与检测；不依赖 GUI。 |
| `crates/client-runtime` | 桌面/CLI 内核生命周期、平台网络、更新与共享控制服务。 |
| `crates/client-ui` | 正式 Slint 组件、界面数据与列表模型。 |
| `crates/desktop-protocol`、`crates/desktop-shell` | 宿主/窗口协议；托盘等桌面原生集成。 |
| `apps/desktop`、`apps/desktop-ui` | 常驻宿主与状态投影；可关闭并重建的窗口进程。 |
| `apps/cli` | `cor` 与后台入口，见 [CLI 文档](cli.md)。 |
| `crates/mobile-ffi` | 共享移动会话，以 `NativeHost` 接入原生能力；不依赖 JNI、Slint 或 Android SDK。 |
| `apps/android` | `native` Rust/Slint/JNI 宿主、`app` 生命周期/VPN/通知、`core` Go/mihomo 桥接。 |
| `apps/ios` | 仅 `.gitkeep` 宿主占位；可预览原型位于 `crates/client-ui/ui/mobile/ios`，尚非可用 VPN 客户端。 |
| `resources`、`scripts`、`docs` | 必需资源、[维护脚本](../scripts/README.md)与文档。 |

界面细节见 [Slint 说明](../crates/client-ui/README.md)，Android 生命周期与构建见 [Android 说明](../apps/android/README.md)。尽量在现有层次解决问题，不把平台权限、文件访问或网络请求写进 `.slint`。

## 分支版本

每次创建开发或修复分支，先核对 GitHub 当前最新的非草稿、非预发布正式版，将其 patch 加一，附分支类型、递增序号和简短内容。正式版为 `0.6.4` 时：

| 分支用途 | 版本示例 |
| --- | --- |
| 功能开发 | `0.6.5-dev.1.fake-ip-sources` |
| 问题修复 | `0.6.5-fix.1.android-protection` |

序号在相同基础版本和类型中递增，首次为 `1`；再次提供该类型的预发布安装包时递增序号，内容描述不承担排序。描述只用 ASCII 字母、数字和连字符，多个标识用点分隔；`0.6.5-dev:描述` 不符合 Cargo/打包器的 SemVer 格式。`0.6.4 < 0.6.5-dev.1.fake-ip-sources < 0.6.5`；`dev` 与 `fix` 仍按 SemVer 字典序比较，不代表跨分支的开发先后顺序。

版本的权威来源为根 `Cargo.toml` 的 `[workspace.package].version`。同步 `Cargo.lock` 中所有 workspace 包、Android Gradle 的版本默认值和离线预览 fixture；不改第三方包版本或历史 Release 文档。正式发布去除后缀、跳版本及其他例外仍需维护者明确授权。版本变化后必须重新取得同提交 CI，不能复用旧版本的构建产物。

安装包版本核验及高版本本地包的更新行为见[版本与更新通道](workflows/versions.md#版本与更新通道)。

## 修改前后都要检查

- 读实际调用链、相关测试与 diff，保留用户未提交的内容，不修改无关文件或撤销他人改动。
- GUI/CLI 共享数据目录、后台所有者和内核；检查两端刷新、退出与重新附加，避免重复内核、轮询或测速。
- 界面选项贯通 Slint 状态/回调、协议、宿主、业务、持久化和刷新，并检查桌面/移动端。协议变更同步收发端、序列化、预览和测试，明确兼容性与版本变化。
- 外部更新不得覆盖规则、订阅或设置草稿；保留并发校验、删除确认、原订阅与配置原子保存/回滚，覆盖拒绝、超时、退出和重启恢复。
- 规则表单统一拒绝重复的启用规则及越界位置，数量上限等校验通过后才替换草稿；拒绝不得污染原草稿。拖动按起始规则 ID 提交，筛选或分页变化后立即失效，不能只等待异步状态回调清理。
- 手动与定时订阅更新都先完整下载并校验有效 YAML，再进入保存/重载事务；代理与直连均不可用、超时、HTTP 错误、空白/错误页面或响应截断时结束本次更新，保留原始订阅、用量、更新时间、设置、草稿和运行状态，不切回默认直连。测速与检测结果只在更新成功后失效；失败必须提示，不能伪报成功。定时任务由唯一后台所有者运行，提交前复核订阅、来源、文件、开关和保护状态，过期结果丢弃；间隔与失败计时见[订阅自动更新](subscriptions.md)。桌面与 CLI 共用运行时，Android 共用移动会话，iOS 目前仅为宿主占位。
- Geo、订阅与 Release 安装包沿用[共享下载约束](../crates/client-core/src/download.rs)，检测断流及可回退路线的持续慢速；Geo 与安装包采用缓冲异步写盘。每条路线重新下载并校验，最后路线允许慢网继续，不能跳过 SHA256/大小校验或自动改用户节点。Geo 先下载到独立暂存目录，四文件全量校验后才安装；旧数据不匹配或缺失不能阻止已验证的新数据修复，备份记录旧文件实际内容及缺失状态，重载失败按原样恢复。清单中的本机更新时间只在安装和必要的内核重载成功后记录，事务失败恢复旧时间；旧清单无记录时不能冒充已更新。Android 重载沿用现有 VPN，不重新申请或连接。
- 控制器只监听本机，使用随机密钥并处理内部端口冲突；密钥不得进入日志、示例或界面。
- 系统代理、TUN、DNS、提权、自启动、通知与更新沿用平台入口，检查授权、拒绝、重复操作和失败清理。
- Linux 发行构建与最老系统验证边界见[CI](workflows/ci.md#ci)和[打包验证](workflows/release.md#publish-release)；共享宿主内核的容器不等于旧系统内核验证，不以新版系统成功替代旧系统证据。
- macOS 保护的动态 DNS、Tailscale 分域、原生就绪与失败隔离按[保护说明](claude-protection.md#dns-与-tailscale)执行；实现前查[DNS 共存复盘](agent-failures/macos-dns.md)。在可丢弃原生环境验证接管、重连、故障及恢复，不以配置写入成功代替实际解析，不要求用户调整 DNS。
- 系统代理使用后台实际托管状态，窗口重建只投影快照；辅助字段变化不判为关闭。恢复只合并仍托管的字段，保留外部修改与网络服务增删，详见[代理状态与安全恢复](agent-failures/desktop.md#系统代理状态与安全恢复)。
- 桌面网络恢复由 GUI/CLI 唯一所有者监控，不依赖窗口轮询或公网探测；离线转联网与默认路由变化稳定后刷新当前运行配置、出站/DNS 及旧连接，保留实际模式、节点、TUN、保护与磁盘数据。读取失败不能冒充断网，恢复失败退避重试，见[断网启动恢复](agent-failures/network-recovery.md)。
- Android VPN/通知独立于 Activity，关闭窗口不停止 VPN；保留套接字绕过自身 TUN。macOS 原生 UI/Dock/主线程、Windows 消息循环与窗口重建遵循各自宿主生命周期。
- 维护脚本优先扩展现有共享模块；独立权限、进程、离线测试或用户入口的保留依据见[脚本说明](../scripts/README.md)。

## 内存与响应速度

- 日志、连接、列表和缓存有界，按页面构建数据、复用模型，释放隐藏页面与关闭窗口的闲置资源。
- UI 线程或全局引擎锁内不做长时间网络/进程等待；后台任务可取消，迟到结果不覆盖新状态。轮询复用已有后台所有者。
- 性能结论必须实测并注明版本、环境、输入和方法；区分 RSS/PSS、窗口开/关与相同负载。基准按任务需要安排，常规使用低强度场景，压力场景另标；预览不作基准。

## 本地验证与 UI 预览

- 资源充足时优先做相关本地验证，再按风险扩大范围；沿用同一 Release profile 与 `--locked`。文档改动只做内容、链接等静态检查；新增测试覆盖行为、边界或恢复，不镜像实现。构建与 CI 范围见 [README](../README.md#编译与打包)及[工作流说明](workflows/ci.md#ci)。
- UI 使用持久安装、版本匹配的官方 Slint Viewer 直接预览正式组件，可用 `--viewer PATH` 指定；参数见 [UI 预览](workflows/local-development.md#ui-预览与静态资源)及[Slint 说明](../crates/client-ui/README.md)。
- 桌面默认 950×700、最小 800×450，移动端按[代表性尺寸与可用性检查](loop-workflow.md#多尺寸-ui-检查)覆盖手机横竖屏、平板与系统字号；检查主题、强调色、滚动、弹窗。复用主题控件与间距，语义颜色不被强调色覆盖；安全区/键盘只扣一次，内容合理顶部对齐。
- 固定演示数据只能验证外观，外观改动附实际截图；交互、后端与系统功能另验。真实代理/TUN 测试只在可丢弃环境执行，不擅自改用户路由、防火墙、代理或重启网络。
- 汇报区分“通过 / 失败 / 未执行 / 仅静态检查”，说明资源、设备、授权或工具链缺口；其他提交的 CI 不算本次验证。

## 依赖维护

- [依赖核对表](dependency-audit.csv)记录 2026-10-24 的升级前后版本、官方元数据与兼容性限制；后续升级同步声明、锁文件和对应行，不把核对日期当成持续安全保证。
- YAML 使用维护中的 `yaml_serde` / `libyaml-rs`，替换已停止维护的 `serde_yaml` / `unsafe-libyaml`；保留原订阅、别名、标签和引号标量语义。桌面私有管道使用 `postcard`，协议号为 9，收发端须一起更新，保留帧长度、截断和尾随数据检查。
- HTTP 客户端统一使用 `clash_client_core::network::client_builder`，保留内置公共根证书；`reqwest` 0.13 的平台证书校验默认值不能直接用于未接入 Java verifier 的 Android 宿主。JNI 0.22 原生入口先经 `EnvUnowned::with_env`，工作线程经 VM 回调获取 `Env`，全局引用和异常处理遵循其生命周期。
- macOS `tray-icon` 仍固定在与 Slint 共用原生菜单类的版本。Slint/ksni 的 zbus 5、字体栈的 `ttf-parser` 及 `typed-index-collections` 的可选 bincode 尚受上游约束；不以强制替换不兼容主版本掩盖这些链路。

# 网站循环审查工作流

`loop-website` 是客户端正式版公开后的独立网站维护流程，也可由维护者单独启动。网站内容、版本记录和下载入口仅提供正式版，预发布不单独更新网站。每轮执行“核对发行 → 审阅内容 → 修复 → 验证 → 复查”，直到没有新增可落实问题。自动验证复用现有 CI 的 `Website validation`；本流程不是新增 GitHub Actions 工作流，也不自动授予推送、部署或再次发布客户端的权限。

客户端发布前仍按[主 loop](loop-workflow.md)准备与待发布版本一致的说明；公开后按本页核对实际标签、日期、附件及网站内容。未发布能力不得提前标成可下载，网站维护不重复客户端编译、安装、兼容性或内存验收。

## 阅读层级与操作入口

| 入口 | 职责 |
| --- | --- |
| 首页 | 简要介绍产品，分别引导开始使用、查功能和下载，不承载完整教程。 |
| 快速上手 | GUI、TUI、CLI 三条独立路径，各自完成安装、添加订阅、选节点、连接和确认状态。GUI 区分桌面与 Android；只解释完成首次使用所需的选项。 |
| 功能手册 | GUI、TUI、CLI 各有可直达的手册和目录；CLI 不再作为其他教程末尾的附录。功能多时按主题拆文章，避免一页堆下全部说明。 |
| 网络工具 | 保留现有专题和共用工具数据，讲清检查内容、参数、结果与限制；其他手册链接对应工具，不复制完整文章。 |
| 下载与版本 | 共用正式版包数据和版本记录，下载完成后引导对应快速上手。 |

三类手册共用业务事实，但分别说明真实入口：GUI 用界面操作和软件截图，TUI 用页面、按键及真实终端帧，CLI 用命令、参数、输出、退出码和脚本示例。某端没有的能力说明平台限制和替代入口，不伪造三端功能对等，也不要求读者先学另一种操作方式。

详细手册按连接与策略链、订阅与更新、节点与测速、规则与应用分流、连接与日志、各类检测、Claude 保护、设置与计划任务、授权与后台服务、诊断与恢复逐项盘点。每项说明用途、操作、默认值、保存与生效时机、失败恢复、保护限制及平台差异；初次使用之外的细节放在手册，入门只链接。事实以对应 `docs/` 主题、实际入口和发行版本为准，不另外维护一份容易失效的功能清单。

改造复用现有 `guide.html`、`tools.html`、首页及下载页，保留已有 `#gui`、`#tui`、`#cli` 和各功能深链；移动章节须提供兼容入口，并同步站内导航、语言切换、站点地图及重定向。无脚本时正文和导航仍可用。

## 每轮检查与修复

1. **固定范围。** 核对网站提交、工作区、最近公开发行及上次网站验证；列明本轮内容、代码、配图和待验证项。读取涉及的权威主题与实际 GUI/TUI/CLI 入口，保留既有未提交改动，不反复加载未变化内容。
2. **核对发行与双语。** 按[网站维护](../website/README.md#每次发布都同步)更新正式版、日期、九种包和校验入口。对照实际正式版，纠正旧页数、旧命令和未发布标记。中英文同轮更新结构、步骤、参数、默认值、限制和图片说明；默认中文，英文显式切换。版本记录保留各正式版，当前系列提供亮点，更早版本依据原始发行说明提供双语摘要、日期和 GitHub 入口，不收录预发布。下载页只查询最新正式版，正常时不显示查询状态，接口异常时保留正式版快照并提供最新正式版入口。
3. **审阅完整性。** 分别以新手和查阅者走通三种操作入口，检查首次连接与完整手册能否互达。涉及数据清空、网络接管、授权、后台自启、应用出口失效和 Claude 保护的说明保留必要边界；删去重复口号、无意义脚注和实现细节，不能为精简而省掉风险或恢复方法。
4. **统一字标与配图。** 字标以 README 使用的 `resources/icons/wordmark-light.svg` 和 `wordmark-dark.svg` 为来源，检查生成结果、比例、线宽、线端、颜色及浅深背景对比；优先复用资产，不能用近似字体或另绘路径替代。软件截图和终端帧沿用[配图来源](../website/README.md#内容与设计)，核对版本、提交、主题、平台及正文操作，不混用版本冒充当前画面。所有新旧内容页均有与首页一致的铁路、道岔和蓝猫风格插画，可按页面复用或裁切；插画与真实软件画面各司其职，不为每个小节堆大图。新增素材保留来源及许可证。
5. **优先修手机布局。** 从 360×640 起检查，再覆盖常见手机、平板和桌面。菜单可收起、章节目录可展开；按钮与标签换行，长命令和表格只在局部滚动，截图可放大，正文不横向溢出。检查首页及各页插画缩放、字标和导航宽度、标题折行、固定栏遮挡、长目录和页脚，不以缩小整页字体补救拥挤。保持统一圆角和短时动效，尊重减少动态效果，不引入常驻逐帧任务。
6. **验证并回到循环。** 修复后复查相邻页面、旧深链、两种语言和同一组件的其他调用者。测试随页面和入口调整，不以旧页面数量或旧教程结构限制新设计。发现内容错误、布局缺陷或下载入口问题继续定位修复，不能仅凭页面能构建就结束。

## 验证与预览

本地仅运行轻量检查：

```sh
python3 -B website/test_build.py
node --check website/src/site.js
git diff --check
git status --short
```

另外核对本轮 Markdown 链接与锚点。页面数、语言目录、旧深链、字标资源、图片及本地下载回退应有静态检查；不为纯流程文档新增实现镜像测试。

真实浏览器和长图检查交给现有 CI 的 `Website validation`，串行覆盖全部页面及三类教程入口、手机/平板/桌面、目录与菜单、键盘操作、图片放大、无脚本、减少动态效果，以及下载接口离线和异常数据回退。核对连续调整尺寸和 80%～200% CSS 缩放；CSS 缩放不能冒充手机浏览器、触屏或系统缩放实机验收。

每页交付至少一张手机与桌面预览，长页面保留完整长图；必要时补平板、展开菜单和手册详情。实际查看图中文字、插画和布局，不能只检查截图文件存在。预览及报告留工作区外或 Actions 短期附件，不提交历史截图、浏览器缓存或排障日志；资源受限主机不运行浏览器矩阵。

## 结束条件与交付

- 完整一轮没有新增可落实问题；已发现问题有修复及对应证据，未定位和未验证项列明影响，不宣称“没有 Bug”。
- 更新网站维护说明、站内入口及相关测试，按[结构复查](structure-review.md)消除文档冲突、重复内容和过长文章；局部拆分保持旧链接，跨仓库目录重构仍先获批准。
- 最终检查 diff、文档链接、工作区及来源提交。纯文档沿用[提交约定](../AGENTS.md#actions提交与发布)，不单独触发客户端 CI；网站代码推送与部署遵守本轮授权，复用已有验证入口，不额外运行客户端发布或打包。
- 汇报内容与布局改动、字标和配图来源、页面预览、验证编号及部署状态，明确区分“通过 / 失败 / 未执行 / 仅静态检查”。发布后的首次循环不能用旧截图或旧提交通过结果代替本次验证；一般经验归本页或网站说明，近期证据记入[最近复盘](agent-failures/reviews.md)。

页面、素材来源和当前截图版本集中维护在[网站说明](../website/README.md#内容与设计)；本轮结果与尚未执行的浏览器检查记入最近复盘，不在此重复维护实施状态。

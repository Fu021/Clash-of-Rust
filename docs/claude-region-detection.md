# Claude 地区线索检测

**A÷检测**检查可观察的地区线索与 Claude 配置风险。请求耗时和远端连通性只用于排障，不代表官方服务状态、账号资格或封号概率。

## 使用

1. 点击“开始检测”，自动扫描已记录的 Claude 项目配置，采集本机与内核网络线索，并打开默认浏览器。内核检测显式通过本应用内核查询 IPv4/IPv6、Claude 同域出口及系统递归 DNS；内核不可用时不回退到直连。
2. 浏览器页面加载后自动采样并回传，无需再次点击开始。请使用平时访问 Claude 的浏览器与同一用户配置；页面检测其出口、Intl 时区、语言、Canvas 字体与 Emoji、WebRTC 和递归 DNS。需要重试时可点击浏览器页面的“重新检测”。
3. 报告汇总正常、风险和线索，摘要优先显示风险与出口 IP 线索。点击分类卡片查看该类全部项目，再点单项的“查看详情”展开来源、证据和建议。
4. 开启“Claude 保护”后，后台持续监测 Claude 及所覆盖关联服务的连接。偏离指定节点的存续连接会被关闭并触发系统提示；保留最近 32 条记录，切页或隐藏窗口继续运行。开启前请阅读共享规则、TUN 和 DNS 变化的确认提示。
5. 在详情的“补充采样”中可复制网页脚本，在实际 Claude 页面的开发者工具 Console 运行并导入结果。脚本只读取公开接口与同域 trace，不读取 Cookie、账号或密钥；受 CSP、权限或扩展限制的项目保持未确认，不执行站点内的 DNS 实测。

GUI 导出 JSON 到应用数据目录的 `diagnostics`，包括已采集线索、配置扫描范围和脱敏风险项。`cor claude check` 默认显示分类计数、风险摘要和出口 IP 线索，`--details` 显示完整项目与来源，`--output` 写出完整 JSON。`cor claude browser` 同样支持 `--details`。

本地浏览器采样页沿用应用的中性圆角卡片、几何字标与陶土强调色，按浏览器系统主题切换浅色或深色；原始 JSON 收在“原始采样”中。仍使用用户实际浏览器采集和自动回传，不自动安装或启动无头浏览器：新建的无头环境无法代表用户已有浏览器的代理、扩展、权限、字体与 WebRTC 行为。应用内已完成的网络检测也不能替代这份浏览器证据。

## 配置扫描

本节的 Desktop、CLI 和项目扫描仅适用于桌面端。Android 使用 VPN 下的网络、DNS、WebRTC 与系统浏览器自动采样，支持取消检测及导出报告，不扫描桌面项目或终端配置。离开检测页会取消当前任务并忽略迟到结果，VPN 与实时保护继续由原生服务运行。

自动读取 `~/.claude.json` 的项目目录记录及 `.claude/projects/*/sessions-index.json` 的项目路径元数据，同时支持本应用启动环境中的 `CLAUDE_CONFIG_DIR`。检查全局 `settings.json`、已记录项目的 `.claude/settings.json` 与 `.claude/settings.local.json`、本机的 `managed-settings.json` 和 `managed-settings.d/*.json`；当前工作目录中可识别的项目也会加入；已记录的子目录项目会同时检查仓库根目录的本地配置。路径去重，已删除项目另行计数。

检查可能绕过 Claude 代理的 `NO_PROXY`、空代理覆盖、不支持的代理协议、与本应用端口不同的代理、API 地址和云平台提供方/区域覆盖、关闭 TLS 验证等。风险项给出文件路径、字段、脱敏值、原因与建议。配置文件正常不代表请求已经走代理，候选覆盖是否生效还受项目信任、启动参数及其他托管来源影响。

只读配置，不执行 hooks 或启动终端，不修改文件，不遍历整个磁盘，不读取会话对话和凭据文件。项目注册表仅保留路径，设置仅保留白名单字段；URL 用户名、密码、路径、查询和片段不会进入报告。中文、字体和时区偏好本身不判为风险。

文件不可读、索引无效或超过读取上限时明确显示未完成检查。单个设置文件上限 256 KiB、项目注册表 16 MiB，最多扫描 4096 个已记录项目；最多保留各 512 条风险/未确认及正常文件明细，数量超出时保留实际计数并注明省略。列表每页最多创建 20 项界面。停止或离开页面会取消尚未开始的文件检查，旧任务的结果不会覆盖新检测。

未记录的项目、自定义启动脚本中的环境、运行中 Code 的 `--settings` 参数、远端/MDM 托管和账号信息不在自动扫描范围内，可结合 Code `/status` 核对。原终端仍支持独立诊断：

```text
clash-of-rust --claude-diagnose --output /路径/claude-code-report.json
clash-of-rust --claude-diagnose --offline --output /路径/claude-code-report.json
```

Windows 使用 `clash-of-rust.exe`；此入口先于 GUI、托盘、内核和数据目录初始化执行。未指定输出文件时保存在当前目录，`--offline` 不发出网络请求。详情中仍可导入其报告。

## 结果的含义

每个检测项目保留简短标题及结果，说明、建议、来源分别标注；连接记录另标规则、线路和时间。旧报告缺少标题时，按项目类型显示“DNS 地区”“IP 归属与信誉”等名称；无目标的连接记录显示“连接检查”，空结果显示“未确认”，不展示无标题的数值或裸露说明。桌面和 Android 使用相同投影规则，JSON 仍保留原始结构化字段。

桌面与 Android 的实际递归 DNS 结果在国家文字前显示 emoji 国旗，与 IP 检测、保护报告和详情共用国家映射及[随包 emoji 字体](../resources/fonts/SOURCE.md#noto-color-emoji)，不使用独立国旗图片。香港、澳门、台湾显示中国国旗并保留地区文字，未知国家不猜测旗帜。国旗跟随报告最终采用的国家，不改变国家差异的风险判定。

- **正常**：实测项目未发现上述网络差异，或已读取配置未发现上述风险字段；不代表 Claude 已授予服务资格。
- **风险**：需要复核的配置覆盖、实测的出口、DNS 或 WebRTC 差异，以及实时选路异常。详情保留证据和适用范围。
- **线索**：IP 属性和注册资料、第三方数据源分歧、浏览器验证、语言和时区等偏好，以及证据不足的检测。

不同测试域名、内核请求、浏览器请求和 Claude 同域 trace 的结果保留各自来源，不能相互代替。地区来自目标 trace 或 IP 数据库，可能与 Claude 自己的判断不同。账号历史、注册及付款资料、服务端判定算法不在本地检测范围内。

正常、风险与线索互斥计数。语言、时区、字体、Emoji、Canvas 和 WebGL 供用户复核实际环境。浏览器人机验证提示用户交互检查。CLI JSON 的 `clues` 字段保留线索数量。

手机和 Pad 点分类计数后显示完整宽度的分类报告，返回后保留总报告。总报告与分类详情在桌面、Android 和 iOS 原型上均使用一整块圆角卡片，项目之间仅以细线分隔；标题、结果、地区、说明、来源与耗时排列一致，不为隐藏项目留空位。各页使用同一批报告数据。

## 网络与生命周期

检测使用 [ipify](https://www.ipify.org/) 的 IPv4/IPv6 出口、[IP.SB](https://ip.sb/api/) 的地区及 ASN、[bash.ws](https://bash.ws/dnsleak) 的权威 DNS 记录和 Cloudflare STUN。失败项目不会借其他域名结果判为成功。定位默认不请求，只有在浏览器页面主动点击后才采集；坐标不发送到第三方反向地理编码。

回传服务只监听 `127.0.0.1`，使用临时随机路径，校验 Host、Origin、请求大小和回传头，不开放跨域读取。离开页面、关闭入口、隐藏窗口或 20 分钟到期会关闭服务，不持久保存入口令牌。主动开启的实时请求检测独立于回传服务，不按进程区分，也不解密 HTTPS 内容。

## 扩展检测

地区线索检测无需开启 Claude 保护或填写密钥。扩展检测包含多 STUN 的 IPv4/IPv6 候选与来源、Canvas 摘要、WebGL、Cookie 功能布尔值、Cloudflare trace、轻量 HTTPS 连通性、官方支持地区及 IP 归属与信誉。Cookie 内容和 Claude 凭据不读取。

主动开始检测后，应用通过内核将本轮内核实测的公网出口 IP 并行提交给下列 IP 数据源。最多检查五个不同的出口，优先检查 Claude 同域出口；普通探测域名的出口保留自身来源。各家会接收到查询 IP 和请求连接的来源地址。没有有效公网 IP 时跳过查询。开启保护时，这些数据源的请求和 DNS 也经保护节点。

| 数据源 | 地址类型 | 读取的属性 |
| --- | --- | --- |
| [IPQuery](https://ipquery.io/developers/api) | IPv4、IPv6 | 机房或托管、VPN、代理、Tor、移动网络 |
| [IPLogs](https://iplogs.com/docs) | IPv4、IPv6 | 机房或托管、VPN、代理、Tor、爬虫、近期滥用名单。只用 `fast` 模式，要求响应确认未主动探测 |
| [Layer3 Intel Open API](https://docs.layer3intel.com/docs/intel-api/open-api) | IPv4 | 机房或托管、VPN、代理、Tor |

每个 IP 的属性合为一条线索。摘要突出命中、来源不一致和待确认的属性，详情列出各家判断、字段缺失、限流或超时。各家的定义、覆盖和更新时间可能不同。应用保留单项判断，综合评分不进入报告。请求发送给各供应商，数据保留适用各自的规则，例如 [IPLogs 隐私说明](https://iplogs.com/privacy)。

点击“开始检测”后，桌面、Android 与 `cor claude check` 自动补充“IP 注册信息”和“全球连通性”，不另设检测选项。仅向 RDAP 和 Globalping 提交本轮已实测的有效公网出口 IP；无有效 IP 时不发出查询，报告写明未确认原因。注册查询总限时 15 秒；全球探测最多 20 个位置、总限时 30 秒，两者并行。全球结果聚合为响应探针数与中位延迟，不列出逐个探针行；全部无响应、超时或服务拒绝不当作节点故障，也不中断其他检测结果。注册地区不等于出口物理地区，远端 ICMP 不等于本机访问 Claude 的延迟。不再提供或自动执行下载/上传带宽测速。

与 [Net.Coffee Claude 检测](https://ip.net.coffee/claude/) 对照，本应用覆盖出口与地区、ASN 与运营商、上述多源属性、DNS 解析器、WebRTC 公网候选、HTTPS 可达性，以及浏览器语言、时区、平台、Canvas 与 WebGL。城市级位置、住宅或“原生”标签、触屏、连接类型和 Do Not Track 未纳入当前报告。应用支持手动导出本轮报告，未维护跨轮出口历史，也不生成 Claude 信任分。WebRTC 仅代表可取得的 ICE 候选，不能覆盖所有 UDP 应用。

## Claude 保护与扩展检测

保护范围、开启/关闭与恢复、Tailscale 共存、递归 DNS 国家修正及 STUN 边界见[Claude 保护](claude-protection.md)。检测报告与保护状态独立；明确保护错误归风险，暂时的控制接口错误仅在实际连接恢复后清除，历史异常拦截记录保留。

# Claude 地区线索检测

`0.5.7` 在 IP检测下方增加 **A÷检测**，检查可观察的地区线索与 Claude 配置风险，不包含稳定性、延迟、官方服务状态或封号概率。

## 使用

1. 点击“开始检测”，自动扫描已记录的 Claude 项目配置，采集本机与内核网络线索，并打开默认浏览器。内核检测显式通过本应用内核查询 IPv4/IPv6、Claude 同域出口及系统递归 DNS；内核不可用时不回退到直连。
2. 浏览器页面加载后自动采样并回传，无需再次点击开始。请使用平时访问 Claude 的浏览器与同一用户配置；页面检测其出口、Intl 时区、语言、Canvas 字体与 Emoji、WebRTC 和递归 DNS。需要重试时可点击浏览器页面的“重新检测”。
3. 报告统一显示“正常”和“风险”的数量，不分网页版、Desktop 和 Code。点击数量卡片查看具体项目、来源、证据与建议，再返回报告。辅助线索和未确认结果通过“其他线索”长条按钮进入，不计入正常或风险。
4. 开启“Claude 保护”后，后台持续监测 Claude 及所覆盖关联服务的连接。偏离指定节点的存续连接会被关闭并触发系统提示；保留最近 32 条记录，切页或隐藏窗口继续运行。开启前请阅读共享规则、TUN 和 DNS 变化的确认提示。
5. 在详情的“补充采样”中可复制网页脚本，在实际 Claude 页面的开发者工具 Console 运行并导入结果。脚本只读取公开接口与同域 trace，不读取 Cookie、账号或密钥；受 CSP、权限或扩展限制的项目保持未确认，不执行站点内的 DNS 实测。

GUI 导出 JSON 到应用数据目录的 `diagnostics`，包括已采集线索、配置扫描范围和脱敏风险项。

## 配置扫描

自动读取 `~/.claude.json` 的项目目录记录及 `.claude/projects/*/sessions-index.json` 的项目路径元数据，同时支持本应用启动环境中的 `CLAUDE_CONFIG_DIR`。检查全局 `settings.json`、已记录项目的 `.claude/settings.json` 与 `.claude/settings.local.json`、本机的 `managed-settings.json` 和 `managed-settings.d/*.json`；当前工作目录中可识别的项目也会加入；已记录的子目录项目会同时检查仓库根目录的本地配置。路径去重，已删除项目另行计数。

检查可能绕过 Claude 代理的 `NO_PROXY`、空代理覆盖、不支持的代理协议、与本应用端口不同的代理、API 地址和云平台提供方/区域覆盖、关闭 TLS 验证等。风险项给出文件路径、字段、脱敏值、原因与建议。配置文件正常不代表请求已经走代理，候选覆盖是否生效还受项目信任、启动参数及其他托管来源影响。

只读配置，不执行 hooks 或启动终端，不修改文件，不遍历整个磁盘，不读取会话对话和凭据文件。项目注册表仅保留路径，设置仅保留白名单字段；URL 用户名、密码、路径、查询和片段不会进入报告。中文、字体和时区偏好本身不判为风险。

文件不可读、索引无效或超过读取上限时明确显示未完成检查。单个设置文件上限 256 KiB、项目注册表 16 MiB，最多扫描 4096 个已记录项目；最多保留各 512 条风险/未确认及正常文件明细，数量超出时保留实际计数并注明省略。列表每页最多创建 20 项界面。停止或离开页面会取消尚未开始的文件检查，旧任务的结果不会覆盖新检测。

未记录的项目、自定义启动脚本中的环境、运行中 Code 的 `--settings` 参数、远端/MDM 托管和账号信息不在自动扫描范围内，可结合 Code `/status` 核对。原终端仍支持独立诊断：

```text
clash-of-rust --claude-diagnose --output /路径/claude-code-report.json
clash-of-rust --claude-diagnose --offline --output /路径/claude-code-report.json
```

Windows 使用 `clash-of-rust.exe`；此入口先于 GUI、托盘、内核和数据目录初始化执行。未指定输出文件时保存在当前目录，`--offline` 不发出网络请求。详情中仍可导入其报告。

## 结果的含义

- **正常**：实测项目未发现上述网络差异，或已读取配置未发现上述风险字段；不代表 Claude 已授予服务资格。
- **风险**：配置存在需核对的覆盖或问题、实测网络出口不一致、WebRTC 公网候选与出口不同，或实时记录出现 DIRECT/REJECT 线路、拨号失败。用于排查，不等同于地区限制或泄漏已经确认。
- **辅助线索与未确认**：语言、时区和字体偏好属于辅助线索；未返回有效记录、无 IPv6、空 WebRTC 候选、DNS 失败或不可读文件保持未确认，不当作“无泄漏”。普通“内核已选路”事件也不证明连接成功。

不同测试域名、内核请求、浏览器请求和 Claude 同域 trace 的结果保留各自来源，不能相互代替。地区来自目标 trace 或 IP 数据库，可能与 Claude 自己的判断不同。账号历史、注册及付款资料、服务端判定算法不在本地检测范围内。

## 网络与生命周期

检测使用 [ipify](https://www.ipify.org/) 的 IPv4/IPv6 出口、[IP.SB](https://ip.sb/api/) 的地区及 ASN、[bash.ws](https://bash.ws/dnsleak) 的权威 DNS 记录和 Cloudflare STUN。失败项目不会借其他域名结果判为成功。定位默认不请求，只有在浏览器页面主动点击后才采集；坐标不发送到第三方反向地理编码。

回传服务只监听 `127.0.0.1`，使用临时随机路径，校验 Host、Origin、请求大小和回传头，不开放跨域读取。离开页面、关闭入口、隐藏窗口或 20 分钟到期会关闭服务，不持久保存入口令牌。主动开启的实时请求检测独立于回传服务，不按进程区分，也不解密 HTTPS 内容。

## Claude 保护与扩展检测

A÷检测中的“Claude 保护”默认关闭。开启时使用当前具体代理节点，将核心、关联服务、关键词及官方入站 IP 网段规则作为优先运行时覆盖，启用 TUN、严格路由、IPv6、UDP 转发、TCP/UDP DNS 接管、经该节点的公网 DoH 与后台实时拦截。保留开启时的规则或全局模式并锁定；直连模式开启时使用规则模式。全局出口沿嵌套策略组检查，最终为 DIRECT 时拒绝开启；保护期间 GLOBAL 临时固定到具体节点，重启后仍有效，关闭后恢复原选择。它不会改写原始订阅、用户规则或原 DNS/IPv6/UDP 偏好。设置中的“启用 UDP”默认开启，保护期间临时强制开启，关闭保护后恢复原偏好。

开启确认按钮等待 3 秒后才可点击。开启前保存原运行模式、代理模式和节点选择；恢复记录随设置持久化。重启后继续保护并保留首次开启时的记录；关闭后移除覆盖并恢复原状态，保留检测报告且不自动重测。开启/关闭均使用配置事务，未完成的事务在下一次启动时恢复。取消授权不会保存开启状态。开启后会通过内核实际查询上游 DNS，无法解析时恢复原网络与配置，不将仅创建 TUN 视为开启成功。保护期间须先关闭保护再切换当前订阅、更新其内容或修改网络模式与规则。

公网解析使用 Cloudflare/Google DoH 并指定保护线路；节点引导解析优先保留原节点 DNS 与分流，未指定时使用原 DNS 上游，避免强行替换为当前网络不可达的固定地址；仅节点引导在本地直连解析，Claude 等公网域名始终经保护节点使用加密 DNS，不回退到本地。局域网名称保留本地解析策略。订阅原有 DNS 分流、备用、直连解析与 TUN 排除项在保护期间被运行时覆盖，关闭后恢复。系统或浏览器绕行、独立 DoH、时区、语言和账号资格仍需独立验证，不能宣称消除所有风险。

保护期间为纯 IP 请求启用 HTTP、TLS 与 QUIC 域名嗅探，补充浏览器旧 DNS 缓存等路径的规则匹配；已知 DNS/代理域名保留，不被订阅的强制嗅探或其他 SNI 名称覆盖。相关配置关闭保护后恢复。没有可识别域名的加密请求仍有识别限制。

实时监测在隐藏窗口和切换页面后继续运行。它只关闭 Claude、所覆盖共享服务及官方入站 IP 范围中偏离指定节点的存续连接，不依据 DNS 地区差异或浏览器偏好断连，也不读取 HTTPS 内容或进程名。共享服务可能属于其他应用，开启确认框对此作出提示。通知与断连分开运行，提示合并去重；通知不可用时保留失败说明，不因此停止拦截。连接扫描逐条解析，只保留最多 128 条异常连接，展示最近 32 条记录。

异常记录单独保留，正常请求不会把它们挤出风险详情；删除失败时也记录域名、线路和失败状态，详情补充传输协议和入站类型。代理集合节点按集合与精确名称固定，节点缺失时拒绝连接，避免退回直连；同名集合节点无法可靠区分时要求先改名。每条保护规则紧跟拒绝回退规则，防止内核跳过不支持 UDP 的节点后继续匹配到直连；已被内核明确拒绝的请求不会重复触发异常关闭和系统提示。

系统提示使用各平台的原生通知：Windows Toast、Linux 桌面 D-Bus、macOS UserNotifications；Android 通过前台 VPN 服务继续拦截，通知使用应用通知通道。点击应用图标与 Claude 拦截共用发送实现，通知权限或桌面勿扰可能影响显示；失败会保留说明，不改用阻塞式警告窗口。

扩展检测包含多 STUN 的 IPv4/IPv6 候选与来源、Canvas 摘要、WebGL、Cookie 功能布尔值、Cloudflare trace、轻量 HTTPS 连通性、官方支持地区及 IP 归属/信誉。Cookie 内容和 Claude 凭据不读取。信誉字段由供应商提供，缺失或额度不足时显示未确认；可在“检测选项”填写自己的 ipapi.is 密钥，密钥以请求正文提交、不写入报告。浏览器指纹和第三方标签不等于 Claude 的账号判定。

检测选项还提供手动 RDAP 注册信息、最多 20 个 Globalping 远端探针和小流量测速。查询会向对应服务提交所查的公网出口 IP；测速下载 10 MiB、上传 2 MiB，使用分块传输。注册地区不等于出口物理地区，远端 ICMP 不等于本机访问 Claude 的延迟；这些补充测试不会在开启保护时自动运行。

规则参考官方 [Desktop 网络要求](https://code.claude.com/docs/en/desktop#network-access-requirements)、[Code 网络要求](https://code.claude.com/docs/en/network-config#network-access-requirements)、[入站 IP 网段](https://platform.claude.com/docs/en/api/ip-addresses)与 [Net.Coffee 分类](https://ip.net.coffee/claude/site.html)。不将出站网段当作入站网段，不以 NTP 能改变时区为依据添加规则。

# Claude 地区线索检测

`0.5.7-dev.1` 在 IP检测下方增加 **A÷检测**。仅检查地区线索，不包含稳定性、延迟、官方服务状态或封号概率。

## 使用

1. 点击“开始检测”，同时采集本机系统线索、内核网络线索，并自动打开默认浏览器。内核检测显式通过本应用内核查询 IPv4/IPv6、Claude 同域出口及系统递归 DNS；内核不可用时不回退到直连。提示框会介绍 Code 自动终端检测与 Claude 请求实时检测。
2. 浏览器页面打开后自动采样并回传，无需再次点击开始。请使用平时访问 Claude 的浏览器与同一用户配置；浏览器直接访问测试域名，采集它自己的出口、Intl 时区、语言、Canvas 字体与 Emoji、WebRTC 和递归 DNS。需要重试时，可在浏览器页面点击“重新检测”。
3. 要核对 Claude 网站本身的环境，在“网页版”复制页面采样脚本，在 Claude 页面的开发者工具 Console 中运行，再导入脚本复制的 JSON。脚本只读取公开浏览器接口与同域 trace，不读取 Cookie、账号或密钥。受 CSP、浏览器权限或扩展限制而失败的项目仍显示未确认。此入口不执行站点内的 DNS 实测。
4. 开启“实时检测 Claude 请求”，持续订阅内核的连接事件流，记录它识别到的 `claude.ai`、`claude.com`、`anthropic.com` 及子域名连接，包含快速结束的连接与拨号失败。普通事件显示“内核已选路”，不据此确认服务可用，REJECT 线路也会作为选路事件记录。适用于网页、Desktop 和 Code，不按进程区分，也不解密 HTTPS 请求内容。Desktop 分类保留最近 32 条时间、域名、规则、线路和结果，以及累计数量；关闭后保留已获得记录，离开页面或隐藏窗口继续检测，退出程序停止。事件流断开后自动重连，不更改内核日志级别。系统线索与客户端内部环境分别标注。
5. 点击“Code 检测”，可填写项目目录并点击“自动检测”，程序自动打开终端执行检测并回传；留空使用用户目录。Windows 使用加载用户配置的 PowerShell，macOS 使用 Terminal 的 `.command` 入口，无需 Apple Events 授权，Linux 使用桌面终端与登录交互 Shell。自动结果标明来自**新建终端会话**，不代替已运行的 Code 会话；仍可复制命令，在启动 Code 的同一终端、同一项目目录补充检测。只采集代理、地区、语言和基础地址的白名单字段，检查可读取的用户、项目、本地及设备托管配置，按候选配置复现网络探测。正在运行的 Code、`--settings` 参数、项目信任、MDM 和服务端托管配置需要结合 Code `/status` 核对。

可点击各分类查看原始值、来源、证据和建议，再导出 JSON 报告。GUI 的报告保存在应用数据目录的 `diagnostics` 下；Code 命令回传成功时不另外生成文件。

终端独立检测也支持：

```text
clash-of-rust --claude-diagnose --output /路径/claude-code-report.json
clash-of-rust --claude-diagnose --offline --output /路径/claude-code-report.json
```

Windows 使用 `clash-of-rust.exe`；此入口先于 GUI、托盘、内核和数据目录初始化执行。独立命令未指定输出文件时保存在当前目录。`--offline` 不发出网络请求。

## 结果的含义

- **实测**：从注明的环境取得了有效数据。普通测试域名出口、GUI 内核探测、Claude 同域 trace 分别记录；不能相互代替。
- **辅助线索**：地区偏好或字体识别等推断。中文、中文字体、某个时区均不证明物理所在地，也未确认 Claude 使用该项进行限制。
- **未确认**：未检测、请求被阻止、没有返回有效记录或本地无法观察。无 IPv6、空 WebRTC 候选、DNS 测试失败均不当作“无泄漏”。
- **存在差异**：与同份报告的出口或内核出口参考存在地区差异，或 WebRTC 公网候选与 HTTP 出口不同；用于排查，不等于地区限制或泄漏已确认。

地区来自目标 trace 或 IP 数据库，可能与 Claude 自己的判断不同。账号历史、注册及付款资料、服务端判定算法不在本地检测范围内。

## 数据与生命周期

检测使用 [ipify](https://www.ipify.org/) 的 IPv4/IPv6 出口、[IP.SB](https://ip.sb/api/) 的地区及 ASN、[bash.ws](https://bash.ws/dnsleak) 的权威 DNS 记录和 Cloudflare STUN。失败项目不会借其他域名的结果判为成功。定位默认不请求，只有浏览器页面中主动点击后才采集；坐标不发送到第三方反向地理编码。

浏览器与终端回传入口只监听 `127.0.0.1`，使用临时随机路径，校验 Host、Origin、请求大小和回传头；不开放跨域读取，不持久保存入口令牌。离开检测页、关闭入口、隐藏窗口后或 20 分钟到期关闭回传服务。自动终端脚本仅保存在私有临时目录，关闭检测入口时清理。主动开启的 Claude 请求实时检测独立于回传入口。报告不包含代理用户名、密码、URL 路径参数、API 密钥或会话凭据。

## CI 覆盖

六个平台执行报告解析、私网/IPv6 分类、同域 trace、DNS 记录、令牌与跨域拒绝、取消及过期结果、自动浏览器调度与客户端引导、无 GUI 的 Code 入口和凭据脱敏测试。Linux x64 使用真实 Chromium，拦截第三方网络为固定测试数据，检查页面加载自动检测、回传失败后重试、浏览器语言、时区、定位仅由点击触发、WebRTC 不支持/超时以及 DNS/IPv6 失败；不依赖公共检测服务实时可用。

实时事件测试覆盖分片、断线重连、停止后释放连接、重复事件计数及 32 条上限，并以真实 mihomo 验证 silent 日志级别下仍可捕获选路、REJECT 与真正拨号失败的 Claude 连接。六个平台还实际启动本地终端，用含空格、引号和中文的项目路径执行离线检测并检查回传；自动标记与项目配置必须一致。

Linux x64 保留正常/最小窗口、浅色/深色与三个环境的实际 Iced 截图；macOS Intel 和 ARM 的原生截图也包括新页及分类详情。`claude-report-{system}-{arch}` 保存诊断与 Linux 截图，macOS 截图仍在原生诊断产物中。测试安装包继续通过 Publish Release 的 `check_only` 构建，未发布。

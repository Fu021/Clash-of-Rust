# 客户端内更新测试

## 0.4.9 的取消下载

在支持自动更新的安装版 0.4.9 客户端中，发现之后的新版本时验证以下情况：

| 操作 | 预期 |
| --- | --- |
| 下载中点击“取消下载” | 停止网络请求、清理临时文件、撤掉进度条，上方显示“已取消更新下载” |
| 取消后再次点击“更新” | 从头下载，旧任务的进度或结果不会影响新任务 |
| 下载即将完成时点击取消 | 若取消先被处理，不安装；若已进入安装阶段，取消下载按钮已撤掉 |
| 代理回退或校验文件下载期间取消 | 停止本次更新，不继续尝试其他连接 |

Windows ARM64 客户端应选择 `windows-arm64-setup.exe`；Linux ARM64 客户端应选择 `linux-arm64.deb`。CI 在四种系统/架构组合上验证对应安装包和内核，正式发布前需全部通过。

## 升级到 0.4.8

保留已安装的 0.4.7。待 0.4.8 发布后，在客户端检查更新，验证下载进度、系统安装授权、自动重启以及设置页版本变为 0.4.8。升级前的 0.4.7 仍有两个更新按钮；安装 0.4.8 后，客户端更新和每条订阅都只保留一个“更新”按钮，自动选择代理和直连。

Windows 自动安装需要完成 UAC 授权。Linux 普通用户需要 `pkexec` 与可用的桌面授权服务。

每次重复升级测试前重新安装旧版本，订阅与个人设置应保留。

## 0.4.8 的自动连接回退

在 0.4.8 中测试订阅导入与更新；客户端安装包下载可在之后发布新版本时验证。设置页手动检查更新使用同一套连接顺序。

| 操作 | 预期 |
| --- | --- |
| 内核未启动，但系统代理可用 | 自动使用系统代理，无需启动内核或选择代理按钮 |
| 当前内核代理无法连接，但系统代理可用 | 自动尝试系统代理 |
| 所有代理不可用，直连可用 | 自动回退到直连 |
| 内核代理与系统代理为同一地址 | 该代理只尝试一次 |
| `github.com` 可达，但 GitHub API 不可用 | 自动使用官方 Release 订阅源检查版本 |
| 安装包下载中断或校验失败，但下一连接可用 | 重新下载并校验，进度从零开始，校验成功后安装 |
| 所有连接均失败 | 简要显示原因；客户端更新撤掉进度条，允许重试；订阅保留原有配置 |
| 订阅返回错误状态、过大、不完整或不是 UTF-8 | 不保存失败响应；下一连接可用时重新下载 |
| 取消系统安装授权 | 上方显示授权取消，进度条撤掉，保留可操作的客户端 |
| 安装包缺失、损坏或校验不一致 | 显示原因，停止安装并撤掉进度条 |

## 历史低版本测试包

0.4.6 开发时曾提供显示版本号为 0.3.0 的测试包，用于验证 0.3.0 → 0.4.6 的安装协议；该测试包不作为正式 Release 附件。Windows 的旧版 0.4.5 安装器不支持自动安装协议，需要先手动升级至 0.4.6 或之后版本。

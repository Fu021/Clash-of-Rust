# 循环审查检查清单

[总流程](loop-workflow.md#每轮怎么做) · [多尺寸 UI](loop-ui.md) · [文档与结构复查](structure-review.md)

每轮覆盖以下全部维度，再按证据深入相关链路。未受改动影响的已验证部分引用对应证据；未覆盖和不适用部分说明原因，不能把清单勾选当作运行验证。

| 维度 | 必查内容 |
| --- | --- |
| 功能与数据 | 订阅添加、导入、编辑、更新、切换及删除当前订阅；规则表单、启停、排序、筛选、分页与应用草稿；Fake-IP 来源、排除及还原；节点、测速、连接、日志、诊断、IP 与 A÷检测。覆盖校验、重复操作、空数据、大列表、取消、重试、退出及重启。 |
| 下载与网络 | 追踪订阅、Geo、客户端更新入口，检查代理/直连、实际出站、DNS/IPv6、重定向、超时、慢速、断流、校验及临时文件清理。默认开启 IPv6 时覆盖无 IPv6、从无到有、从有到无和读取失败，普通 TUN 与保护均不得把无 IPv6 误报为绕行，见[矩阵](ipv6-tun.md)。速度结论须有对应证据；下载或重载失败保留旧数据和可用网络，不破坏活动文件。 |
| UI 与交互 | 按代表尺寸检查桌面、手机横竖屏和 Pad，兼顾字号及主题。检查裁切、遮挡、列表重叠、宽度、滚动、长文本、来源/原文、键盘及安全区；分页、应用/放弃、拖动与边缘滚动须可达且清楚。覆盖加载、禁用、进度、错误及成功反馈。 |
| `cor` 命令行 | 核对[命令文档](cli.md)、参数、帮助、默认值、退出码、标准输出/错误及结构化结果；覆盖无显示环境、后台启动/重新附加、取消、失败、配置和规则操作。Linux 检查普通用户、sudo、直接 root 与指定用户的环境、目录、文件/后台归属、跨用户只读总览和隔离，防止假成功、遗漏入口或额外 GUI/内核。 |
| 桌面与移动同步 | 双向盘点 Windows、Linux、macOS、Android 手机及 Pad 已有功能与便利交互，不只核对本轮改动；逐项判断能否推广到其他端，例如进入代理页时当前策略组置顶并展开。对照入口、业务、校验、持久化、反馈和失败恢复，补齐适用能力；保留差异须写明平台理由和替代入口。 |
| GUI 与 CLI 同步 | 共用功能保持业务语义、默认值、校验和结果一致。核对 GUI 修改后的 `cor` 查询/操作及 CLI 修改后的窗口刷新；保留草稿，共享数据目录、后台所有者与内核，防止重复任务和旧状态覆盖。 |
| 平台与生命周期 | Android VPN、套接字保护、通知、磁贴、Activity 重建及后台；桌面托盘、窗口关闭/重建、服务、授权、自启动、代理/TUN/DNS 切换恢复。覆盖拒绝授权、迟到回调、连续点击、退出及重启；按[平台矩阵](workflows/release.md#publish-release)检查不同系统、发行版和架构，避免重复已有回归。 |
| Claude 保护边界 | 新旧功能均对照[操作权限](claude-protection.md#操作权限)：保护关闭、开启中、已开启、关闭中及失败恢复分别检查界面、宿主、共享业务和 CLI。网络、订阅、规则、应用出站、更新/Geo、自启动及定时任务修改必须拒绝，主题、强调色、字号、窗口、通知显示、排序、导航、日志清空及只读查询应可用；外观保存不得重载内核或改变保护状态。新字段/新入口先在共享业务默认拒绝再分类，每轮复核旧入口，误锁纯外观或只读能力应放宽并补回归；功能触及保护判定、共享设置、内核/VPN 或应用分流时重跑完整允许与拒绝矩阵。混合提交、旧表单、迟到保存和并发启用保护不得绕过校验，关闭后恢复原网络偏好与应用规则。 |
| 性能与资源 | 网络/同步磁盘操作是否阻塞 UI、worker 或引擎锁；下载缓冲、轮询、模型复用、任务取消、内存/日志/缓存上限及关窗后的资源释放。性能结论注明环境、版本、输入和方法。 |
| 可靠性与发布 | 控制器本机认证、脱敏、文件/配置事务、协议兼容、版本迁移、依赖/资源身份、脚本调用；安装、升级、卸载、签名、架构、更新通道、文档及安装后行为。 |

按平台适用性同步：Android 使用系统 VPN/移动授权，不扫描 Claude Desktop/CLI，不增加桌面 `cor` 宿主；iOS 仍为宿主占位，只检查共享接口与原型，不标记为可用或实机通过。说明界面/平台专属差异，补齐共用能力缺口。

Claude 保护还须每轮完成[名单维护](claude-protection.md#名单维护)：在线核对指定来源、补齐新增网站与回归，来源减项或不可访问不删现有规则；未完成在线核对单独说明。

收尾另执行[文档冲突纠错、代码模块及全仓目录职责复查](structure-review.md)，将发现的问题带回 loop；整体重构先提交方案供维护者批准。

## 推送前检查

统一检查新增测试的调用者、可见性、类型、条件编译与严格 lint，复查产品代码及测试双方的状态、坐标和生命周期。静态检查通过不代表编译或设备回归通过；同提交证据及同轮集中修复要求见[提交与发布衔接](loop-workflow.md#提交与发布衔接)。

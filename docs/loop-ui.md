# 循环审查的多尺寸 UI 检查

[返回循环审查](loop-workflow.md#多尺寸-ui-检查)。使用逻辑视口尺寸，不能把手机的物理分辨率直接当作布局宽度。依据改动选择小屏、常规屏、大屏及平板的代表尺寸，先查受影响页面，再查共用控件的调用页面：

| 场景 | 代表逻辑尺寸 |
| --- | --- |
| 小屏与窄屏手机 | `320×568`、`360×800` |
| 常规与大屏手机 | `393×852`、`412×915` |
| 手机横屏 | `800×360` |
| Pad 竖屏与横屏 | `800×1280`、`1280×800` |
| 桌面最小窗口与常规窗口 | `800×450`、`950×700` |

每种布局检查顶部、列表中部及末尾，覆盖长文本、空结果和大字号（如 `1.3` 倍），确保来源、详情、操作可见。键盘弹出/收起、条数变化及空结果后仍能输入，不重建搜索框丢失焦点；键盘展开须留结果空间，不能只按整页高度固定尾栏。规则页筛选随列表滚走，快捷规则入口固定在标题栏右侧。桌面拖动、移动长按拖动均检查浮起跟随、原位占位、目标反馈、双向边缘滚动、中心停滚、松手及取消；源行回收后预览仍跟随，不随内容漂移。矮横屏/大字号允许尾部操作随内容滚动，保证控件可达。

资源受限时按风险选尺寸，串行预览相关页面的一种主题；输出放在工作区外。预览只证明静态外观；CI 验证手势、键盘与运行时，字体、安全区及触感仍需设备验收。记录尺寸与未覆盖项。

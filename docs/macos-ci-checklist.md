# macOS 开发与验收

版本：0.5.7。最低系统目标为 macOS 14；CI 原生覆盖 Intel (`macos-15-intel`) 和 Apple Silicon (`macos-latest`)，分别输出 x64 和 arm64 安装包。

## 自动检查

CI 运行格式检查、Clippy、所有单元测试和真实 mihomo 集成测试，随后验证原生网络服务读取、开机启动开关、系统代理恢复及其他客户端后续修改的保护、管理员内核会话启动与 GUI 父进程异常退出后的桥接、网卡及内核清理。TUN 测试通过实际 HTTP 订阅缓存验证退出后的普通用户写入能力，并检查清理不会修改目录外的符号链接、硬链接目标。代理和 TUN 检查仅允许在一次性的 GitHub Actions runner 上运行。

手动 Publish Release 复用 CI 二进制，生成 `.app` 和 `.dmg`，检查版本、架构、离线资源与签名，并测试安装后的真实 GUI 窗口及内核。开发分支使用 `check_only=true`；不会合并分支或发布 Release。内存基准工作流保持手动触发。

CI 与安装后的 DMG 均执行 19 个原生 GUI 场景：TUN 授权取消、授权超时、长会话后的内核重启；用户目录与系统目录自动更新、更新取消、版本/签名/架构校验拒绝、两种目录的替换失败恢复，以及只读 DMG 运行；另覆盖 TUN 与系统代理反复切换、真实用户 LaunchAgent 下开关自启动，以及开过 TUN 后切系统代理再更新的两种安装目录。文件导入场景打开实际 NSOpenPanel sheet 并取消，确认主事件循环与内核保持运行、导入状态正常释放。退出场景调用原生 NSApplication 退出入口，确认经客户端保存窗口、关闭内核后正常退出。窗口场景通过 AppKit 的真实关闭按钮动作隐藏窗口，用 LaunchServices (`open -a`) 重新打开同一个正在运行的签名应用，检查原生窗口可见状态、最小化恢复、图标缺失后的窗口唤回及内核不中断。再通过原生应用委托回调补充 `hasVisibleWindows=true` 分支，不依赖模拟 `ShowWindow` 消息；物理 Dock 鼠标点击仍需人工确认。测试检查正常退出、应用内容、以普通用户重启、实际窗口与健康内核、TUN 和进程清理。CI 使用免密 sudo 替代人工授权确认，但仍经过 osascript 和实际授权入口；系统代理测试临时允许一次性 runner 的固定网络授权项，结束后恢复，仍调用真实 Authorization Services 与 SystemConfiguration；故障注入仅存在于测试夹具，不进入发行程序。

每种 Mac 架构都上传 `macos-*-report-*`：逐项状态与耗时、完整编译/测试日志、系统与硬件信息、网络设置、进程列表、系统日志、应用崩溃报告，以及窗口截图和线程采样。CI 还用独立测试入口保存十个页面及 Claude 数量卡片、配置扫描与正常/风险/未确认详情的双主题视图，共 56 张实际渲染截图（含订阅编辑、连接详情、删除与草稿确认框、大字号、实时请求说明与报告视图），并在真正的 GUI 主线程检查托盘创建、取消初始化、重复创建保护、三种状态、节点菜单勾选、可选速度标题及销毁；同时检查 NSStatusItem 可见性、按钮图像及实际菜单栏窗口尺寸；测试入口不进入发行程序。runner 未授予屏幕录制权限时，截图明确标记不可用，不计为截图验收通过。

CI 还用真正的 root TCP 连接重现跨用户 TIME_WAIT：确认旧进程已退出而普通用户仍无法绑定，等待连接状态释放后复用原端口；正常启动时真实监听占用立即拒绝；更新重启允许最多三秒退出交接。沿用代理后如内核启动失败，恢复原系统代理，避免继续指向未启动的内核。

## 实现与安装

- 托盘创建、更新及销毁在 AppKit 主线程完成，确认桌面事件循环已启动后初始化，失败按时限重试；菜单栏仅显示系统模板图标。图标的原生状态窗口丢失时自动重新注册，重试有间隔限制。关闭窗口后可用 Dock 或菜单栏重新显示，菜单栏图标缺失时仍保留 Dock 恢复入口。Windows/Linux 保持现有线程实现。
- 系统代理复用进程内的 Authorization Services 会话，先无交互验证有效权限，未发生变化时不写入；开机启动仅在已保存的系统代理模式、端口和当前设置均属于本客户端时沿用恢复记录。系统代理使用 SystemConfiguration 原生接口，保留各网络服务原先的 PAC、例外列表及代理设置；恢复前检查当前设置仍由客户端持有。
- 开机启动开关只调整用户的 plist，避免卸载正在运行的客户端 LaunchAgent。开机启动采用当前用户的 `~/Library/LaunchAgents/org.clashofrust.desktop.plist`，以普通用户后台启动。启用后下次登录生效。
- TUN 助手单独编译，不链接 AppKit/Cocoa 或 Iced 桌面库；CI 用 `otool` 核对依赖。TUN 首次使用请求管理员授权，只启动短期的内核服务；GUI 不提权。会话使用私有 Unix socket、用户身份与随机令牌验证，固定执行已验证并冻结的 mihomo。桥接断开后停止内核，未使用的授权服务在五分钟后退出，不安装永久 root 服务或 setuid 文件。后台登录启动不会弹出 TUN 授权。
- DMG 中的 `.app` 拖入 Applications 即可安装。数据目录使用 macOS 用户 Application Support，不写入应用包。
- 当前安装包使用 ad-hoc 签名，可验证包完整性；它不提供 Apple Developer ID 信任或公证。尚未配置 Developer ID 签名和公证凭据，首次下载后的 Gatekeeper 提示见 [Apple 说明](https://support.apple.com/zh-cn/102445)。

## 仍需交互式 Mac 验收

1. 首次安装的 Gatekeeper 提示、系统代理授权、TUN 授权，以及取消授权后保持原模式。
2. 托盘菜单、关闭窗口后后台运行、重新显示窗口；切换模式后菜单和图标一致。
3. 开机启动在真正注销/登录后生效；自动后台启动不会连续弹出权限提示。
4. TUN 开启时实际访问网站、DNS 解析及断网/恢复；关闭或退出后恢复正常网络。
5. 自动更新成功、取消授权、空间不足、旧版恢复；更新后重新启动和版本正确。
6. 浅色/深色、Retina 缩放、多显示器、窗口尺寸恢复及休眠唤醒。

Actions 可以验证真实系统 API 和基本桌面运行；授权弹窗操作、真实重启、物理显示器和睡眠行为需要远程桌面或实体 Mac 补充确认。

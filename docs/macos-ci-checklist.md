# macOS 开发与验收

开发版本：0.5.3-dev.1。最低系统目标为 macOS 14；CI 原生覆盖 Intel (`macos-15-intel`) 和 Apple Silicon (`macos-latest`)，分别输出 x64 和 arm64 安装包。

## 自动检查

CI 运行格式检查、Clippy、所有单元测试和真实 mihomo 集成测试，随后验证原生网络服务读取、开机启动开关、系统代理恢复及其他客户端后续修改的保护、管理员内核会话启动与桥接进程退出后的清理。代理和 TUN 检查仅允许在一次性的 GitHub Actions runner 上运行。

手动 Publish Release 复用 CI 二进制，生成 `.app` 和 `.dmg`，检查版本、架构、离线资源与签名，并测试安装后的真实 GUI 窗口及内核。开发分支使用 `check_only=true`；不会合并分支或发布 Release。内存基准工作流保持手动触发。

每种 Mac 架构都上传 `macos-*-report-*`：逐项状态与耗时、完整编译/测试日志、系统与硬件信息、网络设置、进程列表、系统日志、应用崩溃报告，以及可用的窗口截图和线程采样。runner 未授予屏幕录制权限时，截图明确标记不可用，不计为截图验收通过。

## 实现与安装

- 托盘创建、更新及销毁在 AppKit 主线程完成，Windows/Linux 保持现有线程实现。
- 系统代理使用 SystemConfiguration 原生接口，保留各网络服务原先的 PAC、例外列表及代理设置；恢复前检查当前设置仍由客户端持有。
- 开机启动采用当前用户的 `~/Library/LaunchAgents/org.clashofrust.desktop.plist`，以普通用户后台启动。启用后下次登录生效。
- TUN 首次使用请求管理员授权，只启动短期的内核服务；GUI 不提权。会话使用私有 Unix socket、用户身份与随机令牌验证，固定执行已验证并冻结的 mihomo。桥接断开后停止内核，未使用的授权服务在五分钟后退出，不安装永久 root 服务或 setuid 文件。后台登录启动不会弹出 TUN 授权。
- DMG 中的 `.app` 拖入 Applications 即可安装。数据目录使用 macOS 用户 Application Support，不写入应用包。
- 开发构建使用 ad-hoc 签名，可验证包完整性；它不提供 Apple Developer ID 信任或公证。正式分发前需要配置 Developer ID 签名和公证凭据。

## 仍需交互式 Mac 验收

1. 首次安装的 Gatekeeper 提示、系统代理授权、TUN 授权，以及取消授权后保持原模式。
2. 托盘菜单、关闭窗口后后台运行、重新显示窗口；切换模式后菜单和图标一致。
3. 开机启动在真正注销/登录后生效；自动后台启动不会连续弹出权限提示。
4. TUN 开启时实际访问网站、DNS 解析及断网/恢复；关闭或退出后恢复正常网络。
5. 自动更新成功、取消授权、空间不足、旧版恢复；更新后重新启动和版本正确。
6. 浅色/深色、Retina 缩放、多显示器、窗口尺寸恢复及休眠唤醒。

Actions 可以验证真实系统 API 和基本桌面运行；授权弹窗操作、真实重启、物理显示器和睡眠行为需要远程桌面或实体 Mac 补充确认。

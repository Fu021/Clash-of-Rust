# 文档与代码结构复查

[文档索引](README.md) · [loop 收尾](loop-workflow.md#统一收尾) · [开发约束](development.md)

每轮结束、最终提交前及验证后复查文档和源码结构。先用文件清单、大小、标题和调用关系定位，再按需读相关章节；不用每轮全文加载全仓。结构整理围绕受版本控制的源码、文档及引用，工作区清理由专用维护 agent 负责。

## 文档冲突纠错

1. 对照本轮改动，核对用户说明、开发约束、功能文档、工作流、命令帮助和预览描述中的同一事实。遵守系统、开发者、用户及适用目录指令的优先级；仓库内约定不得覆盖用户当前明确要求。
2. 发现文档与实现不一致时，先确认是实现缺陷、说明过期，还是仅适用于旧版本或特定平台。用源码、配置、协议及对应提交的验证证据判断；不能把错误实现直接写成新规范，也不以文档日期较新作为唯一依据。
3. 每项现行规则保留一个权威位置，其他入口引用；同步修正命令、参数、门禁、平台范围、链接和锚点。历史验证保留版本与范围，避免与现行要求混写；必要的来源、许可证和风险边界不能为缩短文本而删除。
4. 无法确定的冲突记录证据、影响和待确认事项，暂停依赖该结论的操作，继续独立工作；在最终汇报中说明，不能静默任选一种约定。

## 文档精炼与拆分

- `AGENTS.md` 建议不超过 6 KiB，仅保留跨任务约束和入口；普通操作文档超过约 10 KiB 时评估拆分。大小是检查信号，是否拆分取决于主题、读者和所需上下文。
- 先删重复与过时说明，再按使用、实现、协议、验证或历史证据拆分；短文保留入口和必要摘要。避免把单个操作拆成大量碎片，导致每次必须连续打开多篇才能完成。
- 总览只说明职责和导航；实现细节放主题页。检查子文档是否也变得过长、同一规则是否多处维护，以及尚有无旧入口。
- 移动章节时同步目录、相对链接和锚点；已有常用锚点保留简短跳转。检查按新入口能否找到完整约束，而非只比较字节数。

## 大代码文件与模块边界

按大小定位候选，再检查一个文件是否混合业务、平台、持久化、协议、UI 投影或测试夹具，是否有过长函数、重复逻辑、循环依赖及频繁跨模块修改。没有统一硬行数；同一职责内的长表、生成代码或第三方快照单独判断。

在当前授权范围内，按可独立描述和验证的职责拆分模块，保持对外入口稳定、状态所有权清楚，让同一业务变化尽量集中。核对 GUI/CLI、桌面/移动共享层及平台宿主，避免通过复制代码、扩大可见性、增加包装层或全局状态掩盖耦合。

拆分同时更新导入与导出、条件编译、资源引用、序列化/协议、测试路径、脚本和工作流的路径筛选；保持授权、取消、并发、持久化及恢复语义。沿用相关回归，不为纯移动代码增加镜像测试。静态检查不能替代编译或运行证据，不以文件变短宣称性能改善。

## 全仓目录职责复查

结合下面的职责树核对全仓受版本控制的顶层目录，再深入本轮触及及依赖相邻模块：文件是否放错层、公共能力是否重复、依赖方向是否倒置、入口是否同义或过期。工具、平台宿主和第三方补丁保留各自边界；不为整齐而移动无关文件。

局部且属于当前任务的模块拆分可随修复完成。涉及整套目录树、多个 crate/宿主归属、公共接口或大量路径迁移时，先给维护者可审阅方案，批准后再执行。方案至少包含：

- 当前问题、调用/依赖证据、预期收益及保持现状的成本。
- 当前树与目标树、目录职责、依赖方向，以及旧路径到新路径的映射。
- 受影响的 workspace、平台、资源、脚本、工作流、文档及兼容入口。
- 分步迁移、验证范围、资源/CI 成本和回退方法；结构迁移与行为改动尽量分开审阅。

发现候选后在任务内记录问题、影响和优先级；最终汇报区分已完成的局部整理与等待批准的整体重构。结构审查不自动授权整仓迁移。

## 目录与职责

职责树只列主要维护入口。`target/`、`bundle/` 和 `dist/` 是构建输出，不提交到仓库。

```text
Clash-of-Rust/
├── apps/                          各端入口与原生宿主
│   ├── desktop/                   常驻桌面宿主、后台协调与状态投影
│   ├── desktop-ui/                可关闭并重建的独立窗口进程
│   ├── cli/                       cor 命令行与后台入口
│   ├── android/
│   │   ├── native/                Rust / Slint / JNI 宿主
│   │   ├── app/                   Java 生命周期、VPN、通知与系统交互
│   │   └── core/                  Go / mihomo 移动桥接
│   └── ios/                       宿主占位，尚无可用 VPN 客户端
├── crates/                        共享模块
│   ├── client-core/               配置、存储、订阅、规则、控制器、DNS、检测与诊断
│   ├── client-runtime/            桌面 / CLI 内核生命周期、平台网络、更新与控制服务
│   ├── client-ui/                 正式 Slint 组件、界面数据与列表模型
│   │   └── ui/mobile/             Android 共享界面与 iOS 原型
│   ├── desktop-protocol/          桌面宿主与窗口间的消息协议
│   ├── desktop-shell/             托盘等桌面原生集成
│   └── mobile-ffi/                共享移动会话与 NativeHost 原生能力接口
├── resources/                     图标、字体、默认配置、检测数据与第三方声明
├── scripts/                       构建、验证、打包、缓存和 UI 预览入口
├── docs/                          使用、开发、工作流、发布说明与失败复盘
├── vendor/                        带来源、许可证及移除条件的 Slint/winit 局部修复
├── .github/
│   ├── workflows/                 CI、发布、内存及 Android/Ubuntu 兼容验证
│   ├── actions/                   工作流共用的下载与缓存操作
│   ├── cache-server/              缓存服务运行配置；服务实现由另一仓库维护
│   └── build-versions.json         工作流工具与资源版本基线
├── Cargo.toml / Cargo.lock        Rust workspace、包版本与已解析依赖
├── README.md                      项目概览、安装与使用入口
└── AGENTS.md                      agent 跨任务开发约束
```

`client-core` 不依赖 GUI；`mobile-ffi` 不依赖 JNI、Slint 或 Android SDK。桌面 GUI 和 CLI 共用运行时，移动端通过 `NativeHost` 接入原生能力。脚本职责和调用关系见[脚本说明](../scripts/README.md)，界面见 [Slint 说明](../crates/client-ui/README.md)，Android 宿主见[平台说明](../apps/android/README.md)。

## 收尾验证

核对权威来源、旧入口和路径调用者，执行文档链接及锚点、`git diff --check`、`git status --short` 检查。代码或目录移动还须完成受影响的格式、编译和行为验证；资源受限时沿用[本地验证边界](development.md#本地验证与-ui-预览)，如实列出未执行项。纯文档随下次功能提交，不单独触发 CI；结构变更完成后更新本页职责树及相关入口。

# loop 的依赖与缓存审查

[总流程](loop-workflow.md#每轮怎么做) · [构建输入](workflows/versions.md) · [缓存分工](workflows/cache-coverage.md)

每轮执行以下审查；同一依赖清单近期的完整结果可复用，查询失败必须保留，不能算已检查。

## 审计与升级

执行 `python3 scripts/build_inputs.py audit --directory /tmp/cor-dependency-audit`，或读取对应 CI 审计附件，覆盖源码依赖、Actions、工具链、构建工具和资源的升级候选、撤回版本及上游归档/弃用信号。

按维护者授权直接更新依赖与工具，无需逐项询问；核对官方版本、目标平台下载、兼容约束和缓存身份，更新声明与锁文件并完成同提交验证。会引入已知冲突的候选保留兼容版本并说明证据，不能只为版本数字更大破坏现有功能。正常构建使用已提交的版本，审计本身只读；用户明确指定冻结或暂缓时遵从该约束。

存在框架相关缺陷时，同时检查 Slint 等相关依赖的官方 issue、已合入修复及发布记录，不能只比较版本号。正式版含修复时优先升级并同步构建依赖、宿主及预览版本；尚未发布时评估范围最小的回移，记录上游来源、许可证、回归和移除条件，不用未验证的主分支替代正式版。

## 缓存与耗时

按[缓存分工](workflows/cache-coverage.md)核对构建、发布、内存及两套兼容工作流与公共 action：Rust 对象只用 GitHub，原始下载官方优先、私网回退，末尾只交 URL 清单；大型预装 VM 仅存私网。不得恢复私网分片/目录快照上传或主动清理私网。

比较同平台的“恢复＋编译/测试＋缓存收尾”和关键路径，区分精确命中、兼容命中、部分恢复及冷编译；没有冷对照时不能断言缓存比重编更快。预算保留慢平台，取消时跳过清理。缓存覆盖与应用功能是否通过分别报告，服务端问题只向维护者反馈必要证据和验收条件。

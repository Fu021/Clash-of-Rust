# 服务端可保留白名单

本页供维护者转交缓存服务端 agent，依据 2026-11-04 的新分工执行。不是删除命令，不授权本侧操作服务器。工作流实现及覆盖边界见[缓存分工](cache-coverage.md)，接口见[服务边界](cache-server.md)。

## 长期保留条件

只接纳同时满足以下条件的缓存：

1. 是官方可独立下载的原始普通文件，有明确公开 HTTPS URL、原文件大小和 SHA256；来源属于已确认构建基线或实际经过校验的下载清单。
2. 使用 `upstream/files`、`sha256-<原文件SHA256>`，载荷为 gzip tar 中唯一普通文件 `0`；外层与原文件摘要均能通过。相同摘要跨平台/运行共用，不保留安装后的目录快照。
3. 明确记录来源 URL、内容身份、导入状态和使用关系。域名或组名前缀只是初筛，不能单凭名称认定可保留；实际需要的版本由已确认基线和有效清单决定。

| 可保留的原文件 | 依据与限制 |
| --- | --- |
| mihomo 官方 ZIP/GZ、Geo DAT/MMDB | `.github/build-versions.json` 的逐资产 URL、大小和 SHA256；不是解压后核心或拼装后的资源目录 |
| NSIS 官方安装程序 | 同一工具基线的 URL 与 SHA256；不是安装目录 |
| Linux 独立 Python 压缩包、Ubuntu 原始云镜像 | 工具基线的架构、URL 与 SHA256；云镜像可以作为原文件保留，运行后系统盘不可以 |
| Go 模块 ZIP/MOD | `go mod verify` 后登记的公开 proxy 下载，逐文件大小与 SHA256；不含 gomobile/gobind 二进制、解压目录或编译对象 |
| APT 的原始 DEB | 当前签名索引核对 URL、大小与 SHA256；不含本项目安装包、系统盘或包配置后的文件 |
| 其他工具官方分发包 | Rust 工具链、Python、Go、Tailscale、JDK、Gradle、Android SDK/NDK/模拟器、Maven 等只在具备逐文件来源和强校验，并实际接入原包清单后保留；不能把安装目录当作分发包 |

最后一行是接纳条件，不代表客户端已全量接入或服务端已存在，实际边界以[覆盖表](cache-coverage.md)为准。冻结清单未包含的新文件不能仅因来自白名单域名就自动导入。工作流不保存 Rust 的 `target` 对象到私网；Rust 官方工具链分发包与项目编译对象是两种数据。

## 旧数据仅保留这些迁移候选

旧组名不能整体套用长期白名单。服务端可暂留以下候选，逐文件核验后迁入新命名空间：

| 旧数据候选 | 必须核对 |
| --- | --- |
| `tools/linux-python-{x64,arm64}` | 原始压缩包与构建基线逐字节一致 |
| `tools/linux-cloud-{x64,arm64}` | 原始云镜像与构建基线逐字节一致，未被启动或写入 |
| `tools/runtime-linux-x64` 内 Java key 的 `jdk.tar.gz` | 仅这个原始文件，匹配 Temurin 官方 URL/摘要；同组其他 runtime key 不因此获准 |
| 旧资源/APT/Go 等混合归档内确有原始文件的条目 | 提取原文件后重建来源、大小及 SHA256；无来源证据则重新从官方代拉，不整体保留混合归档 |

最近可用的旧盘点采于 **2026-11-04 14:04:06 UTC**：Linux Python/云镜像四类共 6 条、约 1.390 GiB，可作迁移候选；这不是服务端当前实时空间。`tools/runtime-*` 包含目录快照，不能整体列入白名单。

切换前等待所有旧工作流及其 post 保存结束，核对没有其他仓库或活动事务引用。白名单以外的数据由服务端决定回收节奏；本页不要求保留旧 Rust 索引和分片，也不要求修复将不再读取的历史缺片。服务状态、SQLite、认证配置、队列、人可读运维日志和备份属于运维数据，应独立管理。

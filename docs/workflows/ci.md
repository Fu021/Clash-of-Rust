# CI 与依赖缓存

[工作流索引](../workflows.md)。按需读取本页，不必加载全部工作流文档。

## CI

先生成一次 `dependency-snapshot`，只复制仓库的 Rust/Go 锁文件与 Android 声明，结合 `.github/build-versions.json` 中已确认的工具、内核和资源身份；不执行 `cargo update`、`go get` 或 Maven 自动升级，也不应用旧缓存中曾自动解析出的新版源码依赖。所有平台和 Publish Release 复用同一份快照，打包不再刷新安装工具版本。

依赖维护可手动运行现有 CI，设置 `refresh_dependencies=true`：只在 Actions 解析 Cargo/Go 更新并导出带来源提交和 SHA256 的 `dependency-updates`，不运行平台矩阵，也不作为打包依据。将已审阅的锁文件提交后，仍须取得新提交的普通 push CI 与不发布打包验证；受限本机不执行依赖下载或构建。

CI、Publish Release 和 Memory Benchmark 统一 GitHub 优先、私网回退，均不可用时正常安装或编译。GitHub 命中只省略私网下载，仍检查并补齐镜像。完整类别、工具快照、容器和 GitHub 启动边界见[缓存覆盖清单](cache-coverage.md)，服务能力及可选的服务端代拉下载见[协议](cache-server.md)。工作流不删除私网条目，服务端自行维护；GitHub 的 9 GiB 热缓存预算独立执行。

每轮 loop 执行只读依赖审计，CI 在最后的缓存 job 中输出 `dependency-audit` 附件及 summary，避免候选查询阻塞平台矩阵启动。报告覆盖 Cargo 锁定包、Go 模块、Android Maven 声明、Actions、已确认工具及 Linux/资源元数据，标出撤回、弃用和上游归档信号；查询失败与未检查项单列。升级或替换先由用户决定，再修改声明、锁文件、工具基线或 Actions SHA 并验证。第三方 Actions 固定为基线成功 CI 已实际使用的提交；版本标签保存在工具基线中供审计，不随上游标签移动自动更新。

私有 Rust 镜像分为 32 个校验分片，逐片串行下载并解压；恢复默认使用 5 分钟预算，超时保留已校验分片并使构建脚本重新验证，缺失内容由 Cargo 补齐。日志按分片显示进度与速度。阻塞超过硬上限时先清除部分编译缓存再正常构建，不允许混用未完成的恢复结果。只回传变更部分，索引最后提交；中断后复用已完成的分片，缺片由正常下载或重编补齐，旧运行不能覆盖较新的内容。GitHub 缓存预算 9 GiB，优先保留公共下载、必要工具及较慢的 macOS/Windows 编译结果；命中后不重复下载私有副本。工作区源码逐文件核对内容，相同内容才恢复旧时间戳，变化的 crate 及使用共享输入的构建脚本会失效重编。测试报告和安装包不进入编译缓存。

私网写入受[服务能力约定](cache-server.md#客户端与服务端的写入约定)保护；旧服务继续可读，但升级并完成事务、分片引用保护及完整保留之前暂停相应保存。GitHub 或私网索引精确命中仍须核对引用分片，缺片可在具备能力后重新上传。源码 key 包含编译使用的 SVG，图标修改会生成新精确 key。开发模式的 `debug` 与发布模式的 `release` 编译依赖均可镜像；报告、当前依赖快照和已导出的应用/测试程序不进入编译缓存。

Go 审计只查询声明的模块路径，不执行更新。Android 公共任务一次准备已校验的模块下载包和绑定工具，经本轮附件分发给三个 ABI；解压内容由 Go 重建，编译结果按 ABI 缓存。Gradle 保留依赖、转换缓存及分发包，由 x64 单点回写，避免三个 ABI 争抢保存相同 key。

私网服务使用独立访问令牌，只可写自己的数据、索引和日志目录。各任务总结记录缓存来源、版本、大小与分阶段耗时，最终 `private-cache-inventory` 列出本地快照的校验值和占用。

需要服务端配合的事项由用户转达，职责见[缓存服务边界](cache-server.md)。工作流不修改或上传 README.txt，不自动交换 agent 反馈；服务器文档由服务端 agent 维护。

单次可选缓存保存最多等待 5 分钟，未完成上传不会替换有效分片。恢复受上述总预算与连接超时共同约束；解包使用原子写入，失败时清除不完整编译对象和解压源码，再正常下载与编译，保留依赖快照和测试报告。

### Ubuntu 20.04 环境下载缓存

CI 和打包通过 `.github/actions/linux-download-cache` 复用独立 Python、包含构建依赖的容器和原始云镜像。按架构、冻结的上游校验值、Dockerfile 和构建用户区分环境，恢复后再验证；验证完成即保存，不必等 GUI 测试结束。详细类别及边界见[覆盖清单](cache-coverage.md)。

Python、云镜像和虚拟机 DEB 下载均使用 GitHub 优先、私网回退；CI 与打包共享私网 `tools/linux-python-{arch}`、`tools/linux-cloud-{arch}` 和 `dependencies/linux-apt-{arch}` 类别。验证后的上游归档在测试前补齐私网；DEB 在虚拟机退出后保存，即使后续 GUI 验证失败也只回传已校验的下载。GitHub 命中不再次下载私网归档，已成功回传的内容不在 post 阶段重复上传。

宿主、容器补充包和虚拟机 DEB 均以本轮签名 APT 索引核对包名、大小和 SHA256，缺失、损坏或弱校验时正常下载，不缓存应用 DEB、系统盘或测试结果。不再在镜像保存前按 512 MiB 裁剪下载文件；GitHub 可独立淘汰热缓存，私网清理由服务端负责。环境与 GUI/代理/TUN 检查照常进行，KVM 不可用时仍记录 TCG；缓存不能消除包配置、启动和软件模拟耗时。

### 测试覆盖

- 六种桌面平台使用相同的 Release profile 完成整个 workspace 的格式检查、Clippy、编译和源码单元测试，包括共享移动会话；Android 另用三种 ABI 构建实际 Slint/Java/Go 宿主，iOS 不参与构建。
- Linux x64/ARM64 在同一轮冻结的 Ubuntu 20.04 镜像中构建；独立 Python 与镜像按上游校验值固定。逐个检查发行 ELF 与集成测试程序的依赖和 `GLIBC` 符号上限 2.31，将镜像、系统依赖及文件摘要写入产物。镜像共享宿主内核，旧内核及完整安装/GUI 验证另见[发布流程](release.md#publish-release)。
- 单元测试保留配置与规则、网络响应解析、认证信息脱敏、状态恢复、任务取消、列表复用与边界、实际指针交互等验证。`cor` 的命令解析、帮助和无显示环境入口也在源码测试内验证；历史截图和长期忽略的联网/平台手工回归入口已移除。
- 真实系统集成测试只运行系统代理与 TUN：验证代理设置写入、HTTP 转发、TUN 接管无显式代理的流量、模式恢复及关闭清理。Linux 使用隔离网络命名空间和 GSettings 内存后端；macOS 使用真实 launchd 网络助手；Windows 先注册服务，再以普通用户令牌运行代理/TUN、恢复和服务清理检查。
- Linux 隔离夹具还验证普通用户、sudo、指定用户与直接 root 的 CLI：临时账户/认证策略只在私有挂载命名空间存在，检查同名订阅隔离、root 只读总览、后台与文件 UID、常用配置/规则/导出操作、真实 TUN 及信号清理。帮助覆盖命令表；公网下载/安装、交互式认证代理、真实登录自启和公网检测不在此矩阵中。
- Linux TUN 测试在独立双栈上游中使用正式保护覆盖，验证域名节点的引导解析、经节点的 DoH A/AAAA、TCP/UDP DNS 接管、HTTP 转发、冷启动及原设置恢复；额外阻断固定公网引导 DNS 并延迟 IPv6 节点 AAAA，验证订阅解析器与慢解析仍可用。上游记录公网明文 DNS 与绕过节点的公网 DNS，发生泄漏即失败。保护 DNS 全部不可达时必须拒绝开启并恢复原网络。隔离环境使用专用测试 CA，保留 TLS 证书校验，不访问外网。
- macOS 代理/TUN 集成还在可丢弃 runner 中建立合成 VPN 补充解析器，检查本机系统域名请求、私有分域、搜索设置与 DNS 租约的启用和恢复，以及保护 DNS 上游超时时不向冲突的 VPN 解析器回退；夹具不登录 Tailscale，不替代真实 tailnet、出口节点、网络变化或端到端保护线路验证。
- Python 构建辅助与产物校验单元测试在前置依赖解析任务中执行一次，失败时不启动各平台下载与编译。内存基准 example 不作为 CI 测试程序额外构建或运行。
- main push、PR 更新触发 CI；过时运行自动取消。本地生成的编译、打包产物和缓存已在 `.gitignore` 中排除，不应提交。
- 桌面 CI 不生成安装包；桌面后台、界面程序、`cor` 和网络助手一起导出，现有代理/TUN 集成场景同时验证真实控制台命令及后台生命周期。Android CI 生成供安装测试与发布复用的 APK。产物记录提交、版本、架构、Cargo.lock、工具链及逐文件校验值；仅附带发布后复用的 `core_integration` 代理/TUN 测试程序，不上传源码单元测试程序。产物采用 schema 3，只与同一提交的打包流程配套使用。

Android x86_64 使用 API 35 模拟器运行真实代理/TUN 流量测试，验证正式界面的内核状态、默认策略组、订阅导航和设置触摸滚动，以及系统 VPN 授权、DNS、套接字保护、快捷磁贴连接/断开、Activity 重建和路由恢复。取消后到达的普通授权、过期服务启动与排队连接不得重新开启 VPN，连接中必须提供取消入口；ARM64/ARMv7 完成实际编译、Gradle lint 与架构校验，仍需真机验收。Android 测试结果、体积报告和 logcat 保存在 `android-report-{arch}`，固定开发签名与构建说明见 [Android 宿主](../../apps/android/README.md)。

macOS 失败日志、系统与网络状态、崩溃报告保存在 `macos-ci-report-{arch}`，Windows 集成检查结果保存在 `windows-ci-report-{arch}`。人工授权窗口、真实重启登录和物理显示器行为仍需人工验收。

## 审核与缓存边界

外部 fork 每次运行须维护者批准，不绕过隔离、网络或 Secrets 限制；贡献者使用自己的工具链和缓存，不索取维护者私网凭据。附件保留 3 天，缓存沿用现有版本身份、校验与容量预算；新增工作流先经维护者同意，不擅自取消他人运行或删除 Actions 历史、附件与缓存。

## 0.7.3 正式版

提交 `24a1c967` 的 [Memory Benchmark 45788967631](https://github.com/Fu021/Clash-of-Rust/actions/runs/45788967631) 完成 80 个场景。环境为 Ubuntu 22.04 x64、Xvfb/X11、Rust 1.100.0、Mihomo 1.19.34，使用 release/light 和虚构订阅。公开读数见 [README](../../README.md#内存占用)。普通规则负载下，GUI 关闭及 TUI 退出后前端进程均已结束。约 60 秒时，客户端 PSS 分别为 17.76 MiB 和 13.44 MiB，纯 CLI 后台为 12.79 MiB。反复开关 20 次后，原后台与内核继续运行，客户端 PSS 分别为 18.95 MiB 和 13.46 MiB。本轮覆盖 Linux 短时合成负载，长期运行、真实业务流量和其他平台需独立测量。

## 0.7.3-dev.3 内存优化

在同一 Linux ARM64 主机上，以相同 Rust 工具链和 release 配置重建 `c88d79ab` 和优化版。共用测量程序、Mihomo、四份 Geo 文件、Xvfb 与 PTY，使用虚构订阅，关闭系统代理、TUN 和定时测速。Light 含 100 节点、5 组和 1,001 条规则，stress 含 2,000 节点、40 组和 20,001 条规则，规则数含末尾的 `MATCH`。

内存降幅主要来自去除控制响应的中间 JSON 值树，以及为快捷规则使用五项订阅包含状态。初轮 stress 对照中，TUI 前端的节点页 PSS 观测峰值从 19.56 降至 13.01 MiB，快捷规则页从 38.41 降至 15.51 MiB。再次退出后，后台匿名页比基线多约 6 MiB。随后加入最近一项快捷规则判定缓存，以订阅文件内容变化为失效条件，减少对同一大订阅的重复 YAML 解析。

### 内核控制查询

独立对照中，stress 下十次 `/proxies` 后约 61 秒，Mihomo PSS 增量为 30.65～34.73 MiB，主要来自匿名私有页。十次 `/configs` 基本持平，`/proxies/group-0` 增量约 0.17 MiB。完整代理查询保留独立节点、分组选择及测速历史。优化应用侧分配后的 Mihomo 驻留仍单独记录。

## 串行与分片的同源对照

固定应用源码 `7011a707`，对照串行 `44250192384` 和分片 `44264484788`。两次均为 release/light：Rust 工具链、内核可执行文件及四份 Geo 的 SHA256、API 输入和 250 ms 采样间隔一致。分片使用 `022dff39` 的测量脚本，覆盖全部 46 个原场景并增加 14 个；原场景保留同样或更长的采样，合计样本由 1,840 增至 3,472。该源码只有代理组具备分页切换能力。

| 实际耗时 | 串行 | 分片 |
| --- | ---: | ---: |
| 首个 job 等待 runner | 6 秒 | 3 秒 |
| 准备及测量 | 单步骤 15 分 39 秒 | 准备脚本 2 分 24 秒；最长测量脚本 5 分 33 秒 |
| 准备完成至各测量 runner 启动 | 同 runner | 1 分 38 秒～3 分 04 秒 |
| 汇总 | 包含在串行步骤 | 脚本 0.22 秒，含附件处理的 job 15 秒 |

### 退出驻留的进程拆分

重新读取同一来源 `4b75f89`、Memory `44175190252` 的原始进程及映射采样，末次 PSS 如下，单位 MiB；不将此历史测量作为后续 TUI 改动的同提交证明。

| 阶段 | 普通规则后台 | 普通规则内核 | 快捷规则后台 | 快捷规则内核 |
| --- | ---: | ---: | ---: | ---: |
| 从未打开 TUI | 12.44 | 43.64 | 12.23 | 60.61 |
| 首次退出 TUI | 14.82 | 47.20 | 13.69 | 67.89 |
| 再次退出 TUI | 15.07 | 46.82 | 14.78 | 67.91 |

首次退出相对初始基线，后台增加约 2.38／1.46 MiB，内核增加约 3.56／7.28 MiB。内核的主要增量在节点页首次明显出现；匿名加堆私有页同样增加，值得优先用相同只读 API 请求序列和等时纯 CLI 对照定位。两次退出尚不足以确认泄漏、分配器缓存或 Go 回收时机，也不能从合计变化认定只有 Rust 后台持有。活跃 TUI 与后台共享可执行映射；前端退出会改变这些页的 PSS 分摊，必须比较没有前端时的初始与退出状态。

静态调用链中，TUI 按页请求快照，后台临时克隆元数据并将快照转换为 JSON 值及响应字节；CLI 后台尚未调用现有空闲堆回收接口。所测内核为 Mihomo `v1.19.33`，[代理路由](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/hub/route/proxies.go)序列化代理对象，[选择组序列化](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/adapter/outboundgroup/selector.go)会组装成员名列表。这些是待隔离测量的临时分配路径，尚非根因结论。Rust 回收只作用于本进程，不能回收独立内核；生产环境也不为下降指标启用内核调试路由或强制 GC。后续先验证有效持有和退出后的稳定曲线，再决定减少重复转换或合并一次空闲回收。

普通关闭已释放约 28 MiB 客户端 PSS，但相对纯 CLI 仍多约 5.61／6.06 MiB；其中宿主匿名加堆私有页约多 2.20／2.08 MiB，剩余映射还须区分代码、库、栈及托盘所需状态，不能全部算作未释放对象。内核独立变化：普通关闭后的 PSS 为 46.12／66.76 MiB，节点搜索后关闭为 52.32／77.70 MiB；对应纯 CLI 为 43.64／60.61 MiB。后续同时压缩客户端残留与定位内核查询后的驻留。

当前关闭路径已清理页面快照、投影和无草稿规则文档，销毁渲染器并回收空闲堆；需要继续查仍有效的持有和回收时序，而非仅增加同样的回收调用。桌面 Tokio 运行时默认按 CPU 数设置 worker，纯 CLI 固定两个，也是待验证的后台差异。现有 `tray-after-cycles` 是完成 20 次关闭重开后的**可见窗口**，尚无最后再次关闭后的独立场景，不能把该值作为 20 次关闭后的驻留；后续须补齐并同时记录重开耗时。

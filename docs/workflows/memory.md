## Memory Benchmark

手动选择 `ref`（分支、标签或提交），默认测当前所选分支：

- `profile`：release 或 dev，默认 release。
- `workload`：默认 light；stress 保留较大的压力输入。
- `rows`：可选 API 行数，1–50,000；默认 light 为 1,000，stress 为 50,000。
- `repetitions`：每项 API 测试的独立进程次数，1–10，默认 3。
- `sample_seconds`：每个 GUI 场景采样 1–120 秒，默认 10 秒。

一次只测一个版本。比较时分别运行，保持工具链、profile、输入和环境一致；常规 CI 和打包不自动运行内存基准。

桌面构建与 CI 共用包范围选择：从所选版本实际的 workspace 成员中排除移动会话与 Android 宿主，保留桌面依赖及基准 example；旧版本不存在对应成员时不添加不存在的排除项。移动端源码测试归 Android job，不在此流程重复编译或执行。

编译对象、原包下载及持久清单提交沿用[三条工作流的缓存分工](cache-coverage.md)：Rust 对象仅用 GitHub，预算紧张时 Memory 优先让出空间；原包官方优先、私网回退，宿主依赖准备完成后提交检查点，末尾追加和查询回执。缓存准备、编译、排队和收尾耗时不计入应用内存指标，比较工作流总耗时时另行列出。

API 基准覆盖规则、连接、代理三类数据的流式/缓冲解析和 1/5 次刷新。GUI 在隔离数据目录、Xvfb 中采样首页、代理组折叠、节点搜索、返回首页；关闭系统代理与定时测速，不生成业务流量。light 为 100 节点、5 个代理组、1,000 条规则；stress 为 2,000 节点、40 个代理组、20,000 条规则。支持的版本另测五项快捷规则全开的同样场景。

Slint 版本另在独立进程中测量可用托盘下的首页、关闭窗口后驻留托盘；通过真实关闭事件隐藏窗口，核对内核未重启，并验证窗口可再次打开。另测搜索后关闭、重新打开及连续开关 20 次；支持销毁窗口的版本须确认原生窗口确实被销毁；采用独立界面进程的版本还需确认该进程已退出，客户端内存合计宿主与界面进程。证明文件记录每次重新启动应用至窗口可见的耗时（不代表首帧耗时），映射报告区分匿名、堆与文件页，不记录地址和文件路径。包含 `cor` 的版本再测纯 CLI 后台：使用 `cor start`，移除显示与桌面会话变量，单独统计 cor、内核及合计内存。附加场景不改变原有四个可见窗口场景的环境；托盘宿主和观察器不计入客户端进程树。

工作流只替换所选版本的 example 基准程序，兼容旧版目录布局，不改应用源码。产物包含版本与环境、提交身份、资源清单、输入订阅、API 数据、GUI/内核内存采样和报告，不生成截图。API 为 Rust 堆分配量；GUI/内核分别统计 RSS、PSS、USS，需区分口径；采样峰值为观测峰值。

## 最近一次与正式版对照

`85699d4` 的 [Memory Benchmark 42810646529](https://github.com/Fu021/Clash-of-Rust/actions/runs/42810646529) 为 release／light，2/2 成功。正式版 `0.6.6` 的基线直接采用 [README 的已有实测](../../README.md#内存占用)，未为该对照重复运行工作流。两次均为 Ubuntu 22.04 x64、4 vCPU、Rust 1.99.1、Slint 1.18.1 软件渲染、100 节点／5 个策略组／1,000 条规则，代理关闭且无业务流量；应用代码及上游资源有变化，runner 也不是同一实例，因此只是历史观测对比。

| 场景 | 0.6.6 客户端 RSS | fix.9 客户端 RSS | 差值 |
| --- | ---: | ---: | ---: |
| 首页 | 48.38 MiB | 52.00 MiB | +3.62 MiB |
| 代理组折叠 | 49.16 MiB | 52.39 MiB | +3.23 MiB |
| 节点搜索 | 58.90 MiB | 63.72 MiB | +4.82 MiB |
| 返回首页 | 58.90 MiB | 63.74 MiB | +4.84 MiB |
| 首页打开、托盘可用 | 50.12 MiB | 54.02 MiB | +3.90 MiB |
| 关闭窗口、驻留托盘 | 21.10 MiB | 22.53 MiB | +1.43 MiB |
| 纯 CLI 后台运行 | 14.56 MiB | 14.76 MiB | +0.20 MiB |

新版可见窗口客户端 RSS 约增加 7%～8%，不能宣称比正式版更省内存。普通首页的客户端与内核合计 PSS 为 84.07 → 90.85 MiB，纯 CLI 为 54.26 → 55.21 MiB，口径不同，不与客户端 RSS 相加。

本轮普通规则与五项快捷规则全开两种场景，各完成 20 次原生窗口销毁／重建，核对界面进程退出、内核 PID 不变及纯 CLI 无 GUI；这不替代真实设备、长期运行或业务流量下的内存验收。Android 和其他桌面系统未在此工作流测量。

## fix.10 优化范围

当前增量优先减少已确认的重复分配：窗口收到状态后先比较源行，仅转换变化行；策略组与节点保持模型身份，折叠时释放后台引用而保留短暂收起动效；宿主比较列表时借用原行，不克隆整份列表。共享探测器让同轮八项服务检测复用一个 HTTP 客户端，并在后台初始化；控制接口解析直接传递接收缓冲切片，读完立即释放，保持背压、32 MiB 上限及错误／取消语义。

页面切换或一轮首页探测结束后，宿主在下一次空闲 tick 回收已释放的堆页；窗口在页面切换或节点列表缩小时延迟 350 ms 合并一次回收，避开 200 ms 收起动效。复用已有平台回收接口，只释放分配器中的空闲页，不销毁活跃窗口、字体缓存或网络客户端，也不对每次轮询执行回收。实际下降仍由基准核对。

源码回归覆盖未变化行不转换、选择变化、分组重排、折叠重开、清空，以及共享探测器的并发代理路径。上述是优化机制，不能替代 RSS／PSS 实测；提交后与 fix.9 的相同场景基准比较，不能把短时分配减少等同于常驻内存必然下降。正式版重跑失败不再追查，历史基线仍使用上表。

相关界面变更由 CI 的 Linux x64 专项执行共享模型、窗口数据转换及控制 API／概览探测源码回归；只在现有界面专项或扩展模式选中时运行，未加入常驻模拟器或临时工作流。

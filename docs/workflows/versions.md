# 版本与更新通道

[工作流索引](../workflows.md)。按需读取本页，不必加载全部工作流文档。

## Rust 工具链

固定版本集中于 [build-versions.json](../../.github/build-versions.json)，当前为 Rust 1.100.0；CI、Android 和内存基准沿用此版本，发布不另编译 Rust。升级核对[官方发行说明](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/)和 Cargo 产物布局、严格 Clippy 与最低系统验收，不只修改版本号。缓存身份及新旧目录兼容见[缓存分工](cache-coverage.md#编译对象只用-github)。

新 API 不自动意味着驻留内存更低。重构须有相同负载下的持有、复制或分配证据，并保留共享业务和平台边界；本次先更新工具链、关闭 ThinLTO，再由同提交内存基准核对 RSS/PSS，不为使用新语法引入未经测量的改写。

## 版本与更新通道

版本格式和同步规则见[版本管理](../development.md#版本管理)。打包器从所选 CI 提交的根 `Cargo.toml` 读取版本，核对构建 manifest、包名、收据和平台版本信息：Windows 的 PE 字符串 `FileVersion`、Android 的 `versionName` 必须一致。Windows 数字版本使用基础版本加 `.0`；macOS 的系统版本字段使用基础版本，自定义 `ClashOfRustVersion` 保留完整后缀。仅改文件名或系统元数据不会改变程序内部用于检查更新的编译版本；不一致的产物不能通过正常打包校验。

桌面、CLI 与 Android 共用[更新通道选择](../../crates/client-core/src/update/channel.rs)。关闭“包含预发布版本”时，只选择线上最新正式版；桌面与 CLI 允许确认后返回较低正式版，Android 仅提示比本地更高的版本，不提供降级入口。开启后纳入预发布版，并只提供比本地更高的版本。先按 SemVer 选出通道内最高版本，再与本地比较；版本相同（仅构建元数据不同也视为相同）时不重复提示，更旧的其他 Release 不会因此被选中。假设线上正式版为 `0.6.4`、预发布版为 `0.6.5-dev.1.example`：

| 当前程序版本 | 包含预发布版本 | 检查结果 |
| --- | --- | --- |
| `0.999.0` 或 `0.999.0-fix.1.example` | 关闭 | 桌面与 CLI 可确认返回正式版 `0.6.4`；Android 没有可用更新。 |
| `0.999.0` 或 `0.999.0-fix.1.example` | 开启 | 两种线上版本都更低，没有可用更新。 |
| `0.6.4` | 关闭 | 已是最新正式版，不提示其他旧正式版。 |
| `0.6.4` | 开启 | 提供 `0.6.5-dev.1.example`，需确认预发布风险后安装。 |

通道只由用户设置决定，不依赖本地版本是否带后缀，也不要求线上保留对应本地版本的 prerelease 标记。草稿与非法标签始终忽略；未开启预发布时，同时排除 GitHub 标记的 prerelease 和含 SemVer 预发布后缀的版本。桌面 API 不可用时的正式版回退入口采用同一策略；网络错误或附件缺失明确报错，不当作已是最新。版本不按发布日期、文件名或分支名比较，也没有 `0.6.x` 的硬编码上限；格式校验本身允许合法的 `0.999.0`，版本管理规则要求避免无意跳号。

安装风险提示依据实际目标的预发布标记（GitHub prerelease 或 SemVer 预发布后缀），不依据是否开启预发布通道。CLI 先显示目标再确认，下载前复核版本及标记；目标变化时须重新确认，见[CLI 安装](../cli/maintenance.md#安装结果与更新设置)。

Geo、订阅与安装包下载沿用[共享下载策略](../development.md#修改前后都要检查)：无数据等待最多 30 秒，前一路线的 20 秒窗口持续低于 32 KiB/s 时转向下一条可用路线；订阅保留原有更短的读超时。最后一条路线允许慢网继续，不自动改节点或跳过校验。Geo 和更新包使用 256 KiB 异步缓冲写入。该策略不能绕过源站或线路限速，实际速度按设备与下载任务验证。

Android 安装还独立校验签名、包名、架构和 `versionCode`；较低 `versionName` 不等于较低 `versionCode`，CI 的 code 来自运行序号。检查更新不提供较低语义版本，安装阶段仍拒绝目标 code 更低的 APK；应用不自动卸载。仅打包的开发签名也不能覆盖签名不同的正式包。

## 自动检查更新

设置页“计划任务”提供“自动检查更新”的分钟输入及保存，默认 360，允许 0–10080。设为 0 时关闭启动及定时自动检查；非零时，桌面初始化完成后、Android 内核运行时可执行首次检查，之后按所设间隔检查。Claude 保护及其切换期间暂停，到期任务在允许检查后执行，不积压多次请求。

该设置保存在当前数据目录的 `settings.json`，旧配置缺字段时仍取 360。桌面与 Android 共用调度规则；保存新间隔后重新计时，手动检查也从本次尝试起重新计时，失败不会每秒重试。界面刷新保留尚未保存的输入；保存失败不改变原设置。0 只禁止后续自动发起，不取消已经进行的检查或下载，手动检查仍可用，也不会自动下载或安装。

GUI 与 [CLI 设置命令](../cli/maintenance.md#安装结果与更新设置)共用 `update_check_interval_minutes`。纯 CLI 后台不新增定时网络任务；iOS 仅共享设置界面原型，尚无原生检查更新宿主。订阅更新有独立的间隔及调度，见[订阅自动更新](../subscriptions.md#自动更新)。

桌面与 Android 检出候选版本后，在各页面顶部持续显示更新栏及“下载安装”，切换页面或普通通知到期不会消失；Android 设置页同时保留版本、检查和安装入口，只展示可升级的候选，不出现“返回正式版”。下载后仍须校验安装包的签名和系统版本号，不能仅凭候选信息保证可覆盖安装。下载期间显示进度与取消按钮。只提示、不自动安装，预发布仍须风险确认，Claude 保护及其切换期间隐藏更新入口并暂停新检查；关闭保护后显示保留的结果。iOS 原型没有原生更新能力，不展示虚构更新。

## 写入目录与权限边界

| 写入内容 | 身份与位置 | 失败处理 |
| --- | --- | --- |
| 设置、订阅、运行配置、Geo、窗口状态、日志与诊断 | GUI/CLI 当前用户的实际数据目录；共享后台保存，原子替换使用目标同目录临时文件。Windows 网络服务回写运行缓存时使用原调用用户的身份，不回写宿主配置或 Geo。 | 保存失败报告具体文件，保留原文件；Windows 短时文件锁有限重试，不删除原件绕过锁。诊断导出失败保留原错误。 |
| 桌面更新下载、安装助手及结果 | 当前用户临时目录；Windows 安装完成页以普通桌面用户启动，更新后重启显式保留原数据目录。 | 目录不可写、空间不足、摘要不符或助手启动失败均停止本次安装；不向安装目录写下载缓存。 |
| Windows、Linux、macOS 系统安装目录 | Windows 通过 UAC 安装器；Linux 通过 `dpkg`/`pkexec`；macOS 普通用户可写时事务替换，否则使用授权事务。 | 保留原有安装回滚，不给整个安装目录或用户目录放宽 ACL。Windows 区分主程序、界面、卸载器、网络助手和登记失败。 |
| Android 安装包及文件导出 | 应用私有缓存及数据目录，APK 只读 URI 交给系统安装器；用户选择的导出位置由系统文件保存器授权。 | 写入或保存器失败回到原错误并允许重新导出，不请求共享存储写权限。 |

普通用户身份的回归与安装后测试覆盖设置保存、订阅导入、日志和诊断导出，运行与 Geo 的事务回归沿用共享层。设置与订阅索引只有读取明确返回不存在时才使用初始值；其他读取错误及格式错误报告具体路径，不覆盖原内容或伪装为空订阅。历史版本或手工提权留下的不可写文件不会被静默重置，也不会自动修改无关文件的归属；无法恢复时先保留诊断与具体路径。人工 UAC、跨账户授权、第三方安全软件和设备文件系统仍须按现场验收。

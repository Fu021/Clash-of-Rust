# 私网缓存客户端与服务端交接

[返回 CI 与缓存](ci.md)。工作流侧维护客户端、缓存身份和交接请求；服务端 agent 维护服务实现、部署、数据和自己的 AGENTS.md 等文档。服务器通用说明不再由工作流同步，贡献者不需要服务器账号或缓存凭据。

## 请求通道

仅将需要服务端配合的具体事项写入 [.github/cache-server/README.txt](../../.github/cache-server/README.txt)，包含稳定的 `Request-ID`、请求和验收条件，不放目录说明、安装教程、日志、令牌或私网地址。完成事项从待交接内容中移除；没有请求时保留空文件。

可信 `main` 推送的 CI 在 **Actions cache budget → Deliver pending cache server requests** 执行 `python3 scripts/action_cache.py sync-handoff`：确认提交仍为远端 `main`，通过现有认证 `/v1/readme` 接口发送，并回读校验。服务仍写固定的 `state/README.txt`，服务器根目录 `README.txt` 的既有链接是交接入口；这份文件仅供请求使用，服务端 agent 将自己的长期文档放在其他文件中。

空请求不访问 GitHub 或服务；请求正文与服务端内容相同则不写入，不因提交或运行号变化重发。服务端保留最后已送达请求，服务端 agent 在自己的文档记录已处理的 `Request-ID`，不重复执行。新请求携带来源提交和 Actions 序号，沿用现有串行预算 job、防旧运行覆盖、64 KiB UTF-8 限制及 SHA256 校验。PR、发布和内存工作流不传递请求。

沿用现有 `LOCAL_CACHE_URL`、`LOCAL_CACHE_TOKEN` 和 Tailscale 连接，不增加私网或远程命令权限。不可达或接口尚未部署时记录未交接，缓存仍为可选加速；连接失败不能视为已送达。纯文档不单独触发 CI，本地请求也不能当作服务端已经收到。

## 客户端与服务端的写入约定

工作流侧负责客户端、缓存 key、回退与协议文档；服务实现、部署及数据修复交由服务端 agent。当前仓库中的 `Store`/`Handler` 尚未实现下面的能力，修改客户端或通过仓库 CI 均不代表服务已经修复。

客户端在发送归档前通过现有 `GET /health` 检查 `schema: 1`、`status: "ready"` 及字符串数组 `capabilities`。服务端完成实现和失败路径验证后才可声明相应能力：

| 能力 | 服务端必须保证 |
| --- | --- |
| `validated-cache-commit-v1` | 暂存预留容量，先校验内容、长度、SHA256 和运行序号，再决定淘汰；拒绝或失败上传不能删除现有有效条目。归档使用不可变物理文件名，发布文件后在同一 SQLite 事务提交逻辑映射及淘汰记录，提交成功后才回收旧文件；数据库失败或提交前中断时旧映射仍指向原内容，提交后中断时新映射及文件一致可用。 |
| `rust-index-references-v1` | 每个已发布 `rust/<目标>/index` 引用的分片保持可取；上传单片、超时或中断不能先淘汰旧索引的引用。提交新索引时，在同一临界区核验全部非空分片的组、key、id、大小、校验值及文件存在性，原子发布索引及引用关系，再回收不再引用的版本。容量不足时拒绝新上传，或原子淘汰其他完整快照，不能留下悬空引用。 |

修复后的响应示例：

```json
{
  "schema": 1,
  "status": "ready",
  "capabilities": ["validated-cache-commit-v1", "rust-index-references-v1"]
}
```

两项能力都具备后才允许 Rust 分片上传；普通归档仅要求第一项。旧服务缺少字段、返回 404 或声明不全时，客户端跳过相应保存并记录 `server upgrade required`，继续使用已有缓存、GitHub 缓存或正常编译。服务仍须校验每次写入，不能只添加声明字段。保持现有 `/v1/lookup`、`/v1/blob` 及 `rust-shards-v1` 格式兼容；当前客户端按 `SHA256(key)` 得到逻辑 `id`，不可变物理文件名与此逻辑标识分离。

GitHub 命中时客户端仍逐片核对私网 metadata；保存前再次检查精确命中索引，不能只凭源码 key 跳过。生成分片时每个 key 都重新 lookup，缺失则重新归档上传，不直接复用旧记录；实际下载仍核验完整 SHA256。Rust 源码 key 包含 `crates/` 等目录的 SVG，图标变化仅使精确命中失效，保留兼容的依赖前缀。

服务端交接验收须覆盖：上传新片后中断，旧索引全部可恢复；相同分片 key 的缺片可修复；校验失败和过期序号不淘汰其他组；同 key 文件发布后 SQLite 写入或提交失败，旧快照仍能通过原校验。2026-11-03 用户报告的 Windows ARM64 缺片属于既有损坏，声明能力不会恢复已删除的文件，须由服务端 agent 处理并核验。

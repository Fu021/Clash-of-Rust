# Android 应用分流

[文档导航](README.md) · [Android 客户端](../apps/android/README.md) · [Claude 保护](claude-protection.md)

设置 → 应用分流决定哪些应用进入 VPN。进入后的具体出站仍遵循当前模式和订阅规则，不等于强制选中应用使用代理节点。

| 模式 | 选中应用 | 其余应用 |
| --- | --- | --- |
| 全部应用 | 进入 VPN | 进入 VPN |
| 仅代理选中应用 | 进入 VPN | 使用系统原有网络 |
| 排除选中应用 | 使用系统原有网络 | 进入 VPN |

Android 系统 VPN 的“阻止不使用 VPN 的连接”若开启，仍可能阻止这些直连应用；该开关由用户在系统设置决定，客户端不会擅自修改。

## 选择与保存

独立应用选择页提供名称/包名搜索、系统应用开关、图标、全选当前结果、反选当前结果、清空全部和已选计数。隐藏或过滤应用不丢掉选择；清空会同时清除不可见项。已安装应用可见性权限只用于本地选择，应用清单不上传。

宿主声明 `QUERY_ALL_PACKAGES`，因为仅查询带启动图标的 Activity 会漏掉无启动入口的系统应用和后台应用，无法提供完整的分流清单。Manifest 仅对此声明标记 `QueryAllPackagesPermission` 检查例外，理由即本节的全应用选择用途；没有关闭 Gradle lint 或其他权限检查。这不代表已经取得 Google Play 的权限政策审核，当前安装包由 GitHub 分发。

连接中可以保存，当前 VPN 保持原选择，重新连接后才生效；放弃返回不修改设置，旋转保留未保存的选择。设置保存在 Android 私有 `vpn` preferences 中：`application_mode` 为 `all`、`only` 或 `exclude`，`selected_apps` 为去重包名集合。旧版 `excluded` 非空时按排除模式读取，并在保存或清理有效列表时持久迁移；空旧列表等价于全部应用。

连接时删除已卸载包名。仅选中模式不接受空列表；选中应用全部卸载时拒绝本次连接，避免 Android 将空允许列表视为接管所有应用。VPN 就绪检查监听 VPN 网络及其路由更新，不要求本应用的默认网络一定经过 VPN，因此可以将 Clash of Rust 自身排除。

Claude 保护期间锁定编辑并临时覆盖为全部应用，不修改用户保存的模式和清单；关闭保护后恢复原分流。保存按钮会再次检查保护状态，避免打开选择页后启用保护仍能保存。

## 范围与验证

系统按 UID 分流，共享 UID 的应用不能保证独立选择；仅列出当前 Android 用户可见的应用，不代管工作资料或其他用户。[issue #37](https://github.com/Fu021/Clash-of-Rust/issues/37) 进阶的“按应用指定节点/策略组”尚未实现，需要单独接入连接归属和 UID 规则，不能用进入 VPN 的选择替代。

`ProxyTunTest.applicationRoutingPersistsAndKeepsOtherAppsOnline` 沿用现有 Android x64 网络集成入口，覆盖旧设置迁移、三种模式、本应用被允许/未选中/被排除的实际路由、直连请求、保存后重连和卸载清理；保护覆盖另核对有效模式与原列表保留。不新增工作流，也不重复键盘专项。

新增源码须取得同提交 Actions 结果才算模拟器验证通过。真机、厂商 ROM、多用户、IPv6/UDP/DNS 专项仍需独立验收，不能据 IPv4 模拟器结果认定完整兼容性。

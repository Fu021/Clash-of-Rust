# Android 应用分流

[文档导航](README.md) · [Android 客户端](../apps/android/README.md) · [Claude 保护](claude-protection.md)

设置 → 应用分流决定哪些应用进入 VPN。进入后的具体出站仍遵循当前模式和订阅规则，不等于强制选中应用使用代理节点。

| 模式 | 选中应用 | 其余应用 |
| --- | --- | --- |
| 全部应用 | 进入 VPN | 进入 VPN |
| 仅选中 | 进入 VPN | 使用系统原有网络 |
| 排除选中应用 | 使用系统原有网络 | 进入 VPN |

Android 系统 VPN 的“阻止不使用 VPN 的连接”若开启，仍可能阻止这些直连应用；该开关由用户在系统设置决定，客户端不会擅自修改。

## 选择与保存

应用选择页使用 Slint，与规则和 Fake-IP 编辑沿用“已保存状态 → 修改 → 保存”的操作顺序；Java 仅通过 `ApplicationCatalog` 枚举应用和持久化选择，不绘制业务页面。

1. 在“哪些应用进入 VPN”选择全部应用、仅选中或排除选中，说明行直接显示选中与其余应用的去向。
2. 全部应用模式收起应用列表、搜索、筛选和批量操作；仅选中与排除选中才显示。仅选中与排除选中互切时，对完整已安装应用清单自动反选，包括当前隐藏的系统组件，保持每个应用的去向；不受搜索或筛选影响。从全部应用切到仅选中时全选，切到排除选中时清空，仍保持所有应用进入 VPN。列表不完整时拒绝需要完整清单的转换，保留草稿并提供应用信息与刷新入口。
3. 搜索名称或包名，用“全部／已选／未选”核对清单；需要时打开系统组件。点击应用行改变选择；全选和反选只作用于当前搜索、筛选结果，清空则清除包括不可见项在内的全部选择。切换模式会重置筛选和滚动位置，避免沿用已选筛选造成列表看似丢失。
4. 顶部保留“已保存”摘要和未保存提示，可撤销到最近保存状态。保存按钮仅在实际有改动时可用，选中后再取消或切回原模式不会制造假草稿。刷新只更新应用和已保存基线，保留当前编辑。
5. 未连接时点击“保存”，下次连接生效；已连接时点击“保存并重连”，自动请求重建 VPN。提交重连请求不等于已经连接成功，后续失败沿用 VPN 错误提示；已保存但无法发起重连时明确区分结果，提供诊断出口。

列表合并已安装应用和 Launcher 查询，默认显示有启动入口的预装应用及用户应用，已选系统组件也保持可见，避免只剩本应用。读取、保存及图标转换在独立工作线程执行；失败保留草稿，可重试或导出诊断。图标来自本机 `PackageManager`，缓存为应用私有 `cache/application-icons/*.png`，按 APK 修改时间更新并清理已卸载应用的缓存；读取失败使用通用图标并明确提示，不从网络下载。应用清单和图标不上传，诊断只记录数量及加载状态。

保存区固定在视口上方，滚动长清单后仍可保存或撤销；范围、筛选和应用行放在同一个滚动视口，横屏或小窗口可以滚动查看全部控件和应用。搜索框保留在应用行循环之外，筛选不会重建搜索框。返回键只在实际显示软键盘时先隐藏键盘，否则交给页面处理未保存确认。

宿主声明 `QUERY_ALL_PACKAGES`，因为仅查询带启动图标的 Activity 会漏掉无启动入口的系统应用和后台应用，无法提供完整的分流清单。它是普通权限，Android 不提供通用的运行时授权弹窗，见 [Android 权限定义](https://developer.android.com/reference/android/Manifest.permission#QUERY_ALL_PACKAGES)和[包可见性说明](https://developer.android.com/training/package-visibility/declaring)。若权限未生效或系统只返回本应用，页面显示原因和“应用信息”入口；在厂商权限／设备策略中核对后返回刷新，不假称点击即可获得授权。Manifest 仅对此声明标记 `QueryAllPackagesPermission` 检查例外；没有关闭 Gradle lint 或其他权限检查。当前安装包由 GitHub 分发，未取得 Google Play 权限政策审核。

未保存时返回或导航会确认是否放弃，旋转沿用 Slint 草稿；保存期间阻止重复保存，VPN 正在连接时拒绝本次写入。设置保存在 Android 私有 `vpn` preferences 中：`application_mode` 为 `all`、`only` 或 `exclude`，`selected_apps` 为去重包名集合。旧版 `excluded` 非空时按排除模式读取，并在保存或清理有效列表时持久迁移；空旧列表等价于全部应用。

连接时通过 `PackageManager` 显式检查已安装状态，再向 VPN Builder 登记，并删除已卸载包名；不只依赖 Builder 抛出异常。仅选中模式不接受空列表；选中应用全部卸载时拒绝本次连接，避免 Android 将空允许列表视为接管所有应用。VPN 就绪检查监听 VPN 网络及其路由更新，不要求本应用的默认网络一定经过 VPN，因此可以将 Clash of Rust 自身排除。

Claude 保护期间锁定编辑并临时覆盖为全部应用，不修改用户保存的模式和清单；关闭保护后恢复原分流。保存按钮会再次检查保护状态，避免打开选择页后启用保护仍能保存。

## 范围与验证

系统按 UID 分流，共享 UID 的应用不能保证独立选择；仅列出当前 Android 用户可见的应用，不代管工作资料或其他用户。应用范围由 `VpnService.Builder` 决定，进入后的指定出站见下节，不能把范围勾选当作节点绑定。

`ProxyTunTest.applicationRoutingPersistsAndKeepsOtherAppsOnline` 沿用现有 Android x64 网络集成入口，覆盖旧设置迁移、三种模式、本应用被允许/未选中/被排除的实际路由、直连请求、保存后自动重连及卸载清理。新增实际分段按钮连续三轮往返、完整补集保存及重新打开、切回后自动重连、全部模式隐藏和撤销；自动重连同时核对服务代次递增和真实 TUN 请求，避免把旧连接仍可用误认作已应用。纯函数回归遍历全部选择组合及多次反选，软件窗口检查列表显示／收起、滚动重置、范围／筛选／保存独立动作、无改动禁止保存及保护锁定。该网络专项由普通 CI 按改动范围选择，多版本截图不执行网络测试，也不重复键盘专项。

提交 `3ff9550` 的 CI `42871572328` 为 14/14 成功；经维护者专项授权，运行 `42876368177` 在 Android 8.0～16 共 11 个版本完成基础代理/TUN 与上述真实应用分流回归，两项 instrumentation 均通过，逐版回执与原始日志一致，应用崩溃和 Rust panic 为零。截图证据见[预览验收](workflows/android-previews.md#截图与边界)。该次临时多版本流量入口在验收后移除，常规 CI 的相关源码回归保留。真机、厂商 ROM、多用户、IPv6/UDP/DNS 专项仍需独立验收，不能据 IPv4 模拟器结果认定完整兼容性。

维护者可在 [Android Compatibility](workflows/android-compatibility.md) 选择 `capture_screenshots`，复用成功 CI 的 x64 APK 检查 Slint 页面、非本应用可见、真实图标、保存摘要及模式切换；清单保留图标失败数、权限与可见性状态。截图使用真实分段按钮并放弃编辑，不保存分流或重跑键盘；基础代理/TUN 另行执行，截图仍不代表实际按应用分流已验收。

## 按应用指定出口

应用分流 → 管理应用规则，以命名规则组维护应用出口：每组填写名称、选择直连／拦截／策略组／节点，再进入应用列表。列表复用外层分流的图标、名称/包名搜索、全部／已选／未选筛选、系统组件及批量选择；全选、反选、清空只作用于当前结果。完成选择返回表单，不立即写入或重连。规则卡显示名称、出口、应用摘要和生效状态；名称为 1～40 个字符，同一订阅内不得重复。

一个应用只能属于一组。未进入 VPN 或已属于其他组的应用标出原因并禁止新增选择；已保存但卸载或被排除的应用仍可取消勾选。保存前重新核对已安装应用、共享 UID、VPN 范围、订阅和文件身份，整组校验通过后一次持久化；失败保留草稿。Claude 保护期间允许查看和筛选，禁止选择、改出口、保存及移除。Android 8/9 只显示不支持指定出口的说明。

底层仍按订阅 ID 和包名保存，组标识和名称仅为管理信息，不参与目标身份或选路；最多 256 个应用，不修改原订阅。旧规则按相同出口及失效策略聚合展示，编辑保存时再补组名，不覆盖原失效选择。新建组默认勾选“目标失效时阻止连接”，不会为用户预选一个出口。移除规则组需确认，所含应用恢复跟随订阅规则。

静态节点身份始终对照原订阅计算，不拿运行配置补充或覆盖的 UDP 等客户端偏好字段判定节点变化。节点名保留完整 Unicode（含国旗、组合 emoji、空格和正则特殊字符），不移除 emoji 或按显示标签重命名；动态节点的筛选按完整名称转义后精确匹配。旧版未存摘要的规则仍按精确名称匹配，界面状态与运行配置沿用同一判定；已有摘要的规则仍拒绝同名但服务端配置改变的目标。

连接时保存会请求重新连接 VPN，新连接应用新规则；请求重连不等于已经生效，失败保留已保存记录并报告可恢复错误。未连接时下次连接生效。表单保存／撤销、选择页返回及系统返回均保留清楚的草稿边界，不刷新覆盖未保存的名称或选择。

Android 10 起使用官方 [getConnectionOwnerUid](https://developer.android.com/reference/android/net/ConnectivityManager#getConnectionOwnerUid(int,%20java.net.InetSocketAddress,%20java.net.InetSocketAddress))，按原始 TCP/UDP 源与目标地址/端口查询 UID，再交给 mihomo 的包名回调。Fake-IP 解析后仍使用原始目标元组。Android 8/9 显示不支持按应用指定出口，继续提供全部／仅选中／排除范围分流，不使用 root 或不可靠的 `/proc` 绕过。

| 情况 | 行为 |
| --- | --- |
| 规则模式、应用进入 VPN、归属可识别 | 应用规则优先于普通订阅规则；未指定的应用跟随配置 |
| 全局/直连模式、Claude 保护 | 暂停应用规则；保护期间锁定修改并保留记录 |
| 应用未进入 VPN、已卸载 | 清单标注不生效，不擅自扩大 VPN 范围；命中绑定前复核包名当前 UID，避免卸载后的 UID 复用套用旧出口 |
| 切换订阅 | 使用新订阅的规则；旧表单拒绝保存，旧订阅规则继续保留 |
| 编辑期间订阅更新 | 文件摘要变化后拒绝旧表单保存，要求重新打开 |
| 静态节点名称相同但配置身份变化 | 视为原目标失效，不自动绑定新节点；摘要不包含节点名称，不持久化凭据 |
| 节点或策略组消失 | 按“目标失效时阻止连接”拦截或跟随配置；不按列表位置替代 |
| provider 节点 | 绑定集合及精确名称，使用隐藏选择器；集合/名称消失遵从失效策略。动态集合接口不提供配置身份，同名节点内容变化不能保证识别 |
| 目标存在但超时 | 沿用指定目标，不擅自换节点；目标不支持 UDP 时拦截 UDP，不回退其他规则 |
| 普通模式的 UDP 开关 | 指定节点、策略组及动态节点的内部选择器同样遵守 UDP 代理偏好；关闭时仅拦截对应 UDP，不影响 TCP，也不报“目标失效” |
| 反复开启／关闭 Claude 保护 | 保护期间暂停应用规则并临时启用 UDP 接管，保持原 UDP 偏好和绑定不变；关闭后按原设置重新生成规则，重新打开客户端也不能把运行配置误当成节点身份 |
| 共享 UID、隔离进程或归属查询失败 | 不允许共享 UID 配置不同出口；查询失败保留诊断计数并跟随配置，不声称已识别 |

UDP 与保护的优先级和恢复规则见[UDP 与应用分流](claude-protection.md#udp-与应用分流)。源码回归对两种 UDP 偏好分别连续切换保护三轮，在每次重新打开客户端后核对原订阅、设置和应用规则完整恢复，并覆盖运行中关闭保护被内核拒绝后的回滚。

支持度由宿主自动判断，不把保存成功当作所有连接都已命中。界面覆盖手机、横屏、Pad、旧系统提示、失效状态和保护锁定；持久化及真实选路分别由 Rust 和 Android 网络回归验证。回归包含原订阅到运行配置的完整生成、UDP 开关、保存后重开、同名目标实际改变及恢复；网络夹具另核对 emoji 节点经隐藏选择器的真实 TCP/Fake-IP 请求和失效计数不增长。TCP、不同 UID、拦截和缺失目标具有专项断言；这些新增回归须取得同提交 Actions 结果，IPv6、厂商 ROM、隔离进程及长期运行仍需独立现场验收。诊断字段见[Android 现场](diagnostics.md#android-现场)，当前改动的验证结果以最近复盘为准。

### 失效提醒

仅实际连接因失效目标命中 REJECT 时累计 `missing_rejected`；保存规则、打开页面、显式拦截、节点测速超时或单纯不支持 UDP 不触发这种告警。静态目标消失／身份改变及内部动态选择器退为空回退分别保留失效原因，不把合法的 REJECT 出口误判为缺失。

前台 VPN 服务读取轻量计数，不依赖 Activity 存活，按类限频发送 Android 可恢复错误通知；应用内保留同类可恢复提示。缺少通知授权仍保留应用内记录，通知失败不改变 REJECT 或扩大 VPN 范围。后台错误、通知权限及诊断边界见[通知与警告](ui-design.md#通知与警告)和[Android 现场](diagnostics.md#android-现场)。

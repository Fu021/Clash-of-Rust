# Android 应用分流

[文档导航](README.md) · [Android 客户端](../apps/android/README.md) · [Claude 保护](claude-protection.md)

设置 → 应用分流决定哪些应用进入 VPN。进入后的具体出站仍遵循当前模式和订阅规则，不等于强制选中应用使用代理节点。

| 模式 | 选中应用 | 其余应用 |
| --- | --- | --- |
| 全部应用 | 进入 VPN | 进入 VPN |
| 仅选中 | 进入 VPN | 使用系统原有网络 |
| 排除选中应用 | 使用系统原有网络 | 进入 VPN |

Android 系统 VPN 的“阻止不使用 VPN 的连接”若开启，仍可能阻止这些直连应用；该开关由用户在系统设置决定，客户端不会擅自修改。

## 选择与保存

应用选择页使用 Slint，与规则和 Fake-IP 编辑沿用“已保存状态 → 修改 → 保存”的操作顺序；Java 仅通过 `ApplicationCatalog` 枚举应用和持久化选择，不绘制业务页面。

1. 在“哪些应用进入 VPN”选择全部应用、仅选中或排除选中，说明行直接显示选中与其余应用的去向。
2. 全部应用模式收起应用列表、搜索、筛选和批量操作；仅选中与排除选中才显示。仅选中与排除选中互切时，对完整已安装应用清单自动反选，包括当前隐藏的系统组件，保持每个应用的去向；不受搜索或筛选影响。从全部应用切到仅选中时全选，切到排除选中时清空，仍保持所有应用进入 VPN。列表不完整时拒绝需要完整清单的转换，保留草稿并提供应用信息与刷新入口。
3. 搜索名称或包名，用“全部／已选／未选”核对清单；需要时打开系统组件。点击应用行改变选择；全选和反选只作用于当前搜索、筛选结果，清空则清除包括不可见项在内的全部选择。切换模式会重置筛选和滚动位置，避免沿用已选筛选造成列表看似丢失。
4. 顶部保留“已保存”摘要和未保存提示，可撤销到最近保存状态。保存按钮仅在实际有改动时可用，选中后再取消或切回原模式不会制造假草稿。刷新只更新应用和已保存基线，保留当前编辑。
5. 未连接时点击“保存”，下次连接生效；已连接时点击“保存并重连”，自动请求重建 VPN。提交重连请求不等于已经连接成功，后续失败沿用 VPN 错误提示；已保存但无法发起重连时明确区分结果，提供诊断出口。

列表合并已安装应用和 Launcher 查询，默认显示有启动入口的预装应用及用户应用，已选系统组件也保持可见，避免只剩本应用。读取、保存及图标转换在独立工作线程执行；失败保留草稿，可重试或导出诊断。图标来自本机 `PackageManager`，缓存为应用私有 `cache/application-icons/*.png`，按 APK 修改时间更新并清理已卸载应用的缓存；读取失败使用通用图标并明确提示，不从网络下载。应用清单和图标不上传，诊断只记录数量及加载状态。

保存区固定在视口上方，滚动长清单后仍可保存或撤销；范围、筛选和应用行放在同一个滚动视口，横屏或小窗口可以滚动查看全部控件和应用。搜索框保留在应用行循环之外，筛选不会重建搜索框。返回键只在实际显示软键盘时先隐藏键盘，否则交给页面处理未保存确认。

宿主声明 `QUERY_ALL_PACKAGES`，因为仅查询带启动图标的 Activity 会漏掉无启动入口的系统应用和后台应用，无法提供完整的分流清单。它是普通权限，Android 不提供通用的运行时授权弹窗，见 [Android 权限定义](https://developer.android.com/reference/android/Manifest.permission#QUERY_ALL_PACKAGES)和[包可见性说明](https://developer.android.com/training/package-visibility/declaring)。若权限未生效或系统只返回本应用，页面显示原因和“应用信息”入口；在厂商权限／设备策略中核对后返回刷新，不假称点击即可获得授权。Manifest 仅对此声明标记 `QueryAllPackagesPermission` 检查例外；没有关闭 Gradle lint 或其他权限检查。当前安装包由 GitHub 分发，未取得 Google Play 权限政策审核。

未保存时返回或导航会确认是否放弃，旋转沿用 Slint 草稿；保存期间阻止重复保存，VPN 正在连接时拒绝本次写入。设置保存在 Android 私有 `vpn` preferences 中：`application_mode` 为 `all`、`only` 或 `exclude`，`selected_apps` 为去重包名集合。旧版 `excluded` 非空时按排除模式读取，并在保存或清理有效列表时持久迁移；空旧列表等价于全部应用。

连接时通过 `PackageManager` 显式检查已安装状态，再向 VPN Builder 登记，并删除已卸载包名；不只依赖 Builder 抛出异常。仅选中模式不接受空列表；选中应用全部卸载时拒绝本次连接，避免 Android 将空允许列表视为接管所有应用。VPN 就绪检查监听 VPN 网络及其路由更新，不要求本应用的默认网络一定经过 VPN，因此可以将 Clash of Rust 自身排除。

Claude 保护期间锁定编辑并临时覆盖为全部应用，不修改用户保存的模式和清单；关闭保护后恢复原分流。保存按钮会再次检查保护状态，避免打开选择页后启用保护仍能保存。

## 范围与验证

系统按 UID 分流，共享 UID 的应用不能保证独立选择；仅列出当前 Android 用户可见的应用，不代管工作资料或其他用户。按应用指定节点尚未实现，方案见下节。当前 `VpnService.Builder` 只配置允许／排除应用，Go 桥接只传 TUN 描述符和套接字保护，不能把勾选当作节点绑定。

`ProxyTunTest.applicationRoutingPersistsAndKeepsOtherAppsOnline` 沿用现有 Android x64 网络集成入口，覆盖旧设置迁移、三种模式、本应用被允许/未选中/被排除的实际路由、直连请求、保存后自动重连及卸载清理。新增实际分段按钮连续三轮往返、完整补集保存及重新打开、切回后自动重连、全部模式隐藏和撤销；自动重连同时核对服务代次递增和真实 TUN 请求，避免把旧连接仍可用误认作已应用。纯函数回归遍历全部选择组合及多次反选，软件窗口检查列表显示／收起、滚动重置、范围／筛选／保存独立动作、无改动禁止保存及保护锁定。该网络专项由普通 CI 按改动范围选择，多版本截图不执行网络测试，也不重复键盘专项。

提交 `3ff9550` 的 CI `42871572328` 为 14/14 成功；经维护者专项授权，运行 `42876368177` 在 Android 8.0～16 共 11 个版本完成基础代理/TUN 与上述真实应用分流回归，两项 instrumentation 均通过，逐版回执与原始日志一致，应用崩溃和 Rust panic 为零。截图证据见[预览验收](workflows/android-previews.md#截图与边界)。该次临时多版本流量入口在验收后移除，常规 CI 的相关源码回归保留。真机、厂商 ROM、多用户、IPv6/UDP/DNS 专项仍需独立验收，不能据 IPv4 模拟器结果认定完整兼容性。

维护者可按需运行独立 [Android 界面预览](workflows/android-previews.md)，复用成功 CI 的 x64 APK，在已固定身份的模拟器版本上打开实际 Slint 页面，核对非本应用可见、真实图标加载、已保存摘要及模式切换；清单保留图标失败数量、权限与可见性状态。模式截图点击实际分段按钮，不再按旧下拉菜单坐标定位。该流程只在模拟器里预览并放弃分流编辑，不启动 VPN、不保存设置、不做流量测试，也不重跑键盘专项；截图不代表实际分流已验收。

## 按应用指定节点（待实施）

应用范围继续只决定是否进入 VPN，另设“应用策略”管理每个应用的出站，沿用规则页的新增、编辑、保存和已保存清单；不把额外选项塞进范围分段按钮。

- 每项选择应用和“跟随规则／直连／策略组或节点”。默认跟随规则；VPN 外的应用不能设置节点，保留原策略但标明当前不生效。
- 按包名独立持久化，目标关联来源订阅和策略名，不改写原订阅。保存检查目标存在；切换订阅或目标删除后显示失效项，不能悄悄绑定同序号的其他节点。Claude 保护期间只读，保留原记录。
- 首版在规则模式将应用策略置于普通域名规则前；全局／直连模式明确显示该层未启用。保存后自动重连，重新建立的连接按新策略处理。
- 先接通连接原始五元组 → UID → 包名 → mihomo 元数据，确保 Fake-IP 改写前仍能准确识别 TCP／UDP、IPv4／IPv6。现有 [mihomo 包名回调](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/component/process/process.go) 是接入点，仍须核对触发时序，不能仅注入回调就宣称所有连接可识别。
- Android 10 起可评估官方 [getConnectionOwnerUid](https://developer.android.com/reference/android/net/ConnectivityManager#getConnectionOwnerUid(int,%20java.net.InetSocketAddress,%20java.net.InetSocketAddress))；Android 8／9、共享 UID、隔离进程及识别失败的策略须另行验证。不能把不可靠的归属显示为已指定节点；旧版本未通过能力验收前仍保留当前范围分流。

验收需对两个应用配置不同可观测出站，核对真实请求、内核规则命中、重连与持久化，再覆盖模式切换、目标失效及保护锁定。界面截图只能验证入口和状态，不能证明选路生效。本轮不提供尚未接通的节点选择入口。

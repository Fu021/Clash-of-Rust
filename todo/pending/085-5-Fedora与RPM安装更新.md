# Fedora 与 RPM 安装更新

## 需求与顺序

Linux 系列第五项，首次引入 RPM，首批候选 Fedora 44/45 x64。复用同提交、Ubuntu 20.04 基线的冻结 Linux payload，避免为每个发行版重新编译。

完整合同、调用关系、发布附件规模、版本比较及授权边界见 [Linux 扩展索引](../pending/085-Linux发行版与安装格式扩展.md)。先完成前面的 DEB 批次，再单独推进本项。

## 验收

- [ ] 接手时重新核对官方版本、EOL、镜像、签名/摘要；访问限制不能用猜测补成精确日期。
- [ ] 设计并审核 RPM 元数据、依赖、安装脚本、polkit、权限、capabilities、用户服务和卸载恢复；保留受信 `/opt` 布局、普通用户 GUI 与固定内核。
- [ ] 打通安装格式识别、附件选择、GUI/TUI/CLI 更新、授权拒绝、包管理器占用、失败恢复及持久化；未知安装来源不能默认下载 DEB。
- [ ] 用原生 RPM 版本比较验证连续预发布与正式版排序；保持 DEB 行为兼容，不机械改写 SemVer。
- [ ] 给出具体 CI、RPM Compatibility 与发布合同改动供审核；新增附件、`.github/`、签名及公开发布分别满足授权，不在 `check_only` 写发行。
- [ ] Fedora 两版本真实 VM 完成索引规定的完整验收；同步包身份、digest、安装/兼容收据、发布附件校验及网站下载识别，取得同提交验证后才开放支持。

## 进度与交接

2026-11-17 拆分排队，尚未新增 RPM spec、包或工作流。首个实施子步骤是核对索引中列出的打包、安装、更新、回执调用链，准备完整但最小的 RPM 接入方案供审核。

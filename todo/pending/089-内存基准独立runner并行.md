## 建议实施

1. 同一提交、工具链和依赖快照只构建/准备一次，输出带摘要及来源清单的测量输入，避免每个 shard 重编译或独立选择 Geo/内核。
2. 独立 runner 并行测量“普通规则 GUI”“快捷规则 GUI”“普通规则 CLI/TUI”“快捷规则 CLI/TUI”；API 独立执行或根据实际耗时归入准备阶段。不在同一台 runner 同时启动多个被测应用。
3. 每个 GUI shard 内保留原始可见场景、托盘、20 次销毁重建及身份断言；每个 CLI/TUI shard 内保留同一后台和内核的未打开、各页面、关闭、重开、再次关闭顺序。关闭 GUI/TUI 后的驻留和累积按最新 loop 规范为第一重点。
4. 汇总 job 校验提交、构建产物/资源 SHA256、参数、runner 规格、场景唯一性及完整性；拒绝缺失或重复 shard、不可读映射、进程身份变化和半成品报告。保留当前下游使用的附件契约，新增各 shard 来源元数据，不把不同 runner 的结果伪装成一个进程的连续测量。
5. 历史版本根据真实能力选取场景，缺少 TUI 的版本不补零；新旧版本可同时派发，各自内部使用上述隔离方式。缓存写入只由明确所有者负责，测量输入不进入公开 Release。

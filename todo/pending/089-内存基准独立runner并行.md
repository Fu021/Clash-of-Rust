## 建议实施

1. 同一提交、工具链和依赖快照只构建/准备一次，输出带摘要及来源清单的测量输入，避免每个 shard 重编译或独立选择 Geo/内核。
2. 独立 runner 并行测量“普通规则 GUI”“快捷规则 GUI”“普通规则 CLI/TUI”“快捷规则 CLI/TUI”；API 独立执行或根据实际耗时归入准备阶段。不在同一台 runner 同时启动多个被测应用。
3. 每个 GUI shard 内保留原始可见场景、托盘、20 次销毁重建及身份断言；每个 CLI/TUI shard 内保留同一后台和内核的未打开、各页面、关闭、重开、再次关闭顺序。关闭 GUI/TUI 后的驻留和累积按最新 loop 规范为第一重点。
4. 汇总 job 校验提交、构建产物/资源 SHA256、参数、runner 规格、场景唯一性及完整性；拒绝缺失或重复 shard、不可读映射、进程身份变化和半成品报告。保留当前下游使用的附件契约，新增各 shard 来源元数据，不把不同 runner 的结果伪装成一个进程的连续测量。
5. 历史版本根据真实能力选取场景，缺少 TUI 的版本不补零；新旧版本可同时派发，各自内部使用上述隔离方式。缓存写入只由明确所有者负责，测量输入不进入公开 Release。

## 分页与完整列表对照

- 使用同一提交、构建产物、内核/Geo、runner 规格及相同列表数据，固定主题、窗口尺寸、节点排序和展开状态，只改变分页方式；分别记录 RSS/PSS/USS 的绝对 MiB、增量和比例，不能以不同版本或不同负载替代对照。
- 代理页对照四组分页与完整代理组列表，覆盖日常规模及大量组/节点、滚动到末组、展开与收起；同时记录可见峰值、稳定驻留和重复进入/退出后的变化。当前组内节点分页独立存在，应明确该变量，不能把全部组可见等同于所有节点已挂载。
- 订阅页使用同样方法补齐分页与完整列表的对照，覆盖日常和大量订阅、宫格/列表及滚动末项；代理页结果不能直接充当订阅页的内存证据。没有现成完整列表入口时，先在同一候选提交提供可比较的显示路径，保持共享模型、虚拟列表及持久化合同。
- 两页均保留关闭窗口后的后台与内核驻留、20 次关闭重建后的累积检查；同时确认选中项、滚动、搜索、操作可达及响应无明显退化，不以一次初始帧或前端进程退出判定影响小。
- 完成对照后先记录数据规模、测量误差与重复性，再判断绝对增量、比例及退出后累积是否足以影响日常使用。影响较小时按维护者授权统一代理与订阅为不分页，并补功能回归与同提交验证；未达到该条件时保留现状和证据，不提前宣称决定。不得为了减少测量结果缩小输入或取消既有关闭回归。

## TUI 退出回落调查

现有实测见[当前内存结果](../../docs/workflows/memory-current.md#退出驻留的进程拆分)：已重新读回 Slint 升级来源的原始进程和映射样本，前端两次退出均消失，增量大部分在独立内核；需要分别定位两个进程，不能把合计差值全部算到 Rust 后台。活跃 TUI 与后台共享映射，退出后的 PSS 分摊变化也必须与真实私有页增加分别判断。

2026-11-18 静态追踪得到以下候选，尚未实测归因或实施优化：

- `apps/cli/src/tui/mod.rs` 中退出返回会释放页面状态，`Request::drop` 中止前端异步任务；`main.rs` 随后结束运行时。检查取消中请求、普通退出、Ctrl+C 和反复重开，确认没有独立工作继续持有数据。
- `control/dispatch.rs::meta` 克隆设置与订阅；快照再转换为 `serde_json::Value`，`control/transport.rs::serve` 生成整份响应字节。请求任务结束后这些临时对象应释放，但后台分配器可能保留已释放页。先核对实际持有与匿名/堆私有页，再考虑减少重复转换，或在最后一批观察请求结束并空闲后合并一次现有 `platform::memory::release_unused_heap`。当前 CLI 后台没有该回收调用；这只是候选，不能据此断言是根因。
- `tui::read` 每轮先经 `backend::connect(false)` 请求完整 `Meta` 确认可达，随后 `Snapshot` 又返回一份完整 `Meta`。这是已确认的重复取值路径，可研究以认证后的快照本身确认可达，保留后台更换、陈旧端点、锁占用与错误提示语义；避免通过常驻元数据缓存掩盖重复分配。先用请求计数与大设置/订阅回归证明行为，再对照退出驻留，不提前承诺内存收益。
- TUI 快照携带 `header=true`；`Engine::poll_with_header/current_route` 除页面数据外读取当前线路，CLI 后台每秒继续 `Scope::Other` 的存活检查。退出后额外页面请求应停止；用等时纯 CLI 对照及相同只读请求序列，区分前端生命周期、控制 API 临时分配、内核请求后的正常保留和实际累积。
- 内核是独立进程，Rust 空闲堆回收不会回收它的内存。保留正常 GC/空闲后的观测，优先分析映射与连续重开曲线，不先换分配器、重启内核或修改 GC 环境参数。
- 原始测量所用内核的代理 API 会序列化代理对象，选择组会临时组装成员名列表；上游固定版本来源已放入上述权威结果页。节点页是优先请求对照入口；不据此断言序列化泄漏，也不为强制回收而开启生产调试路由。

实施时补齐即时退出、退出后 10/30/60 秒与 20 次进入/退出的观测；保留原来每个场景的采样时长，以同一后台和内核身份验证重附加。若采用空闲回收，应合并触发、避开轮询热路径，并覆盖仍有其他 CLI/GUI 查询、迟到响应及取消事务，不新增常驻 TUI 专属后台任务。比较每个进程与去重合计的绝对 MiB、相对基线增量和重复误差；优化后也需明确尚未回落的部分。

## GUI 关闭后向纯 CLI 压缩

已重新读回已有报告并在[GUI 关闭后的差距](../../docs/workflows/memory-current.md#gui-关闭后的差距)记录客户端、内核及私有页拆分。当前关闭链路已清理页面快照/投影、销毁渲染器，并在清理和 reap 后回收空闲堆；剩余差值仍需定位。桌面运行时 worker 默认随 CPU 数增加，纯 CLI 固定两个，作为可测候选，不直接认定为全部差值来源。现有 20 次重建场景以可见窗口结束，必须另补最后关闭后的场景。

- 同一构建、输入和资源下比较纯 CLI、GUI 可见、关闭窗口驻留托盘、搜索后关闭及 20 次销毁重建后再次关闭；关闭前后沿用同一 GUI 宿主和内核，纯 CLI 是独立的等价基线，不伪装成同一进程连续测量。
- 核对渲染器与原生窗口销毁、Slint 模型/图片/字体、页面快照、排序和搜索投影、规则文档、未完成请求、事件队列及捕获闭包；分别定位宿主和内核，优先释放 GUI 已关闭后不再需要的持有。已存在的空闲堆回收只在释放完成后评估，避免反复轮询调用。
- 区分托盘和继续服务 CLI 所需状态、可重新加载的界面状态与无效残留；重开恢复窗口/列表偏好和必要业务草稿，仍运行的下载、保护、订阅定时任务及网络不因释放而损坏。不通过把大对象转存到另一常驻进程隐藏开销。
- 记录关闭前后的客户端与内核 RSS/PSS/USS、匿名/堆私有页、关闭后的稳定曲线，以及相对纯 CLI 的绝对差和比例；重复测量并记录重开到可见耗时。以减小真实驻留和重建累积为目标，不承诺托盘宿主与无 GUI 后台逐字节相等，也不以更慢重开换取未说明的收益。

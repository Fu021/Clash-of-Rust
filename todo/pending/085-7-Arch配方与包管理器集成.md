# Arch 配方与包管理器集成

## 需求与顺序

Linux 系列第七项，先提供官方 Arch x86_64 的配方模板和真实验收；AUR 自动写入不进入首批。维护者授权自行拆分、逐项推进，不包含联系他人、接管现有包、AUR 凭据或公开发布授权。

完整第三方配方调查、源码路径证据、版本政策和共享验收见 [Linux 扩展索引](../pending/085-Linux发行版与安装格式扩展.md)。已存在第三方 `clash-of-rust-bin`，不能覆盖或擅自申请移交；Arch Linux ARM 不算本项官方 Arch 范围。

## 验收

- [ ] 接手时重新核对官方镜像、签名身份、快照日期、包名及现有维护状态；不执行未经审查的第三方 PKGBUILD。
- [ ] 先复现现配方移动 `/opt` 到 `/usr/lib`、改用系统 mihomo 与受信路径/polkit 的差异；静态推断不是已复现故障，不放宽受信边界或以 root GUI 迁就。
- [ ] 首批配方保留 `/opt` 与本轮固定内核，提供一致的 PKGBUILD/`.SRCINFO`、固定公开来源及 SHA256；兼容验证的候选源与正式公开配方来源分开，不能引用未发布 URL。
- [ ] 用原生 pacman 版本比较器验证升级顺序，明确来源/安装所有权；应用内更新应交由包管理器或明确引导，不调用 DEB/dpkg 覆盖 pacman 文件。
- [ ] Arch Compatibility 的具体变更取得审核；真实 VM 完成索引的原生安装、升级、卸载、普通用户三端、代理/TUN、DNS/授权拒绝与恢复、持久化及同提交回执。
- [ ] 完成三端差异与生命周期循环复核后，交维护者决定与现 AUR 维护者的协作方式。是否启用稳定 `-bin` 发布、包名/权限及自动更新 job 另行决定，未授权不发送消息或写 AUR。
